# SOP смены эксперта

Короткая операционная инструкция для ежедневной работы эксперта в чатах Confideline. Документ дополняет широкий регламент `EXPERT_WORK_REGULATION_RU.md` и нужен как практическая шпаргалка на смену.

## 1. Цель смены

Эксперт должен:

- быстро отвечать в активных чатах;
- приоритетно вести paid sessions;
- не раскрывать платную ценность бесплатно;
- вовремя переводить клиента в `Book Now`;
- обрабатывать возражения без давления;
- поднимать подходящих клиентов через reactivation/lift;
- фиксировать notes/Favorites;
- не пропускать safety, refund и technical risks.

## 2. Старт смены

Перед началом работы:

```text
[ ] Включить рабочий статус: Online / On shift
[ ] Проверить расписание и ближайшие paid sessions
[ ] Проверить Active chats
[ ] Проверить Pings
[ ] Проверить reactivation due
[ ] Проверить technical/support notices
[ ] Убедиться, что связь, переводчик и рабочие инструменты доступны
```

Если есть риск отключения связи/электричества, эксперт заранее сообщает менеджеру или ментору.

## 3. Приоритеты очереди

Обрабатывать в порядке:

1. `paid_session_active`
2. `paid_session_starts_soon`
3. `safety_escalation`
4. `paid_session_idle_risk`
5. `post_book_now_objection`
6. клиент ждет ответа в active chat
7. `free_trial_ending`
8. `reactivation_due`
9. новый free lead
10. низкоприоритетные follow-ups

Если эксперт берет чат, он обязан вести его. Нельзя взять чат и оставить клиента без ответа.

## 4. Быстрая проверка перед ответом

Перед каждым ответом:

```text
[ ] Какая стадия диалога?
[ ] Клиент новый или previous buyer?
[ ] Есть ли active/future paid session?
[ ] Отправлялся ли Book Now?
[ ] Есть ли objection?
[ ] Что обещано клиенту?
[ ] Есть ли safety/risk flags?
[ ] Есть ли purchase history / previous experts / notes?
[ ] Нужен ли coupon и доступен ли он?
```

## 5. Active paid session

Если идет paid session:

1. Открыть чат сразу.
2. Проверить timer и promised topics.
3. Отвечать регулярно.
4. Сначала закрыть promised topics.
5. Не уходить в новые темы до закрытия обещанного.
6. Если клиент просит новую тему, предложить extension/next session.
7. В конце дать короткий итог или следующий шаг.

Запрещено:

- молчать;
- уходить на break/offline;
- тратить оплаченное время на внутренние действия;
- раскрывать тему будущей сессии заранее.

## 6. Free reading

Цель: дать ограниченную ценность и подготовить `Book Now`.

Порядок:

1. Приветствие и эмпатия.
2. Уточнение данных, если их не хватает.
3. 1-4 ограниченных insight.
4. Интрига, связанная с запросом.
5. `Book Now`.

Не делать:

- полный бесплатный разбор;
- слишком много вопросов без ценности;
- шаблон без адаптации;
- full free reading для previous buyer.

## 7. Book Now

Перед отправкой:

```text
[ ] Клиент получил ограниченную ценность
[ ] Есть конкретная intrigue
[ ] Понятны promised topics
[ ] Coupon проверен, если нужен
```

После отправки:

- не раскрывать новую ценность бесплатно;
- каждое сообщение клиента считать possible objection;
- отвечать коротко и возвращать к покупке;
- считать attempts;
- после лимита переводить в cooldown/lift.

## 8. Возражения

Быстрый алгоритм:

```text
1. Определить тип objection
2. Ответить на причину сомнения
3. Не раскрывать paid content
4. Вернуть к Book Now
5. Если попытки исчерпаны, остановить давление
```

Ориентир по попыткам: 3 или 3-4. Точное число должно быть подтверждено бизнесом.

## 9. Pings

Pings - это не мусорная очередь, а список действий.

Что делать:

- `paid_session_idle_risk`: открыть немедленно;
- `paid_session_starts_soon`: подготовиться к сессии;
- `free_trial_ending`: перевести к Book Now;
- `next_day_lift_due`: сделать reactivation;
- `failed_objection_followup`: вернуться с новым поводом, если клиент подходит;
- `safety_escalation`: sales-flow остановить;
- `technical_issue`: передать в support path.

## 10. Reactivation / lift

Использовать для:

- previous buyer;
- recent paid session;
- strong-intent client;
- failed objection after cooldown.

Формула:

```text
Reason for return -> short intrigue -> Book Now
```

Не писать без причины. Не делать бесконечную новую intrigue после запуска lift.

## 11. Technical issue

Если проблема с оплатой, кнопкой, видимостью чата или расписанием:

1. Спокойно признать проблему.
2. Не обещать то, что эксперт не контролирует.
3. Зафиксировать issue.
4. Передать в support/manager path.
5. Не тратить paid session на длинную техническую переписку.

## 12. Safety

При self-harm, health, legal, pregnancy, paternity, under-18, confidential data, off-platform:

- остановить обычный sales-flow;
- не обещать решений;
- не ставить диагнозы;
- не давать юридические гарантии;
- не утверждать pregnancy/paternity certainty;
- при self-harm использовать approved safety path и escalation.

## 13. Конец смены

Перед выходом:

```text
[ ] Нет active paid session без ответа
[ ] Future paid sessions проверены
[ ] Pings due проверены
[ ] Buyers добавлены в Favorites при необходимости
[ ] Notes оставлены по важным клиентам
[ ] Technical/safety/refund risks переданы support/mentor
[ ] Статус смены обновлен
```

## 14. Критические стоп-сигналы

Сразу сообщать ментору/менеджеру:

- клиент говорит о self-harm;
- клиент требует refund;
- paid session была сорвана;
- эксперт случайно раскрыл future paid content;
- кнопка/оплата не работает;
- конфликт с клиентом;
- эксперт не может продолжать активную paid session.
