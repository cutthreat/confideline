# QA-чеклист эксперта по чатам

Документ превращает видеоанализ конкурента в проверочный лист для контроля качества работы эксперта. Его можно использовать для ручного ревью диалогов, обучения, mentor feedback и будущей автоматизации подсказок в Confideline.

Основа: `INSIGHTORBA_COMPETITOR_WORKFLOW_FULL_DOCUMENTATION_RU.md`, разделы 6, 7, 8, 10 и 11.

## 1. Шкала оценки

Рекомендуемая оценка по каждому пункту:

| Оценка | Значение |
|---:|---|
| 0 | Не применимо или нет данных |
| 1 | Нарушено / сделано плохо |
| 2 | Частично выполнено |
| 3 | Выполнено нормально |
| 4 | Выполнено сильно |

Итоговая оценка должна учитывать не только сумму баллов, но и критические нарушения. Некоторые ошибки должны блокировать положительное QA независимо от общей суммы.

## 2. Критические нарушения

Если найдено одно из нарушений ниже, диалог требует отдельного разбора:

- эксперт молчал во время активной paid session настолько долго, что возник refund/support risk;
- эксперт раскрыл платный контент до начала будущей paid session;
- эксперт дал полный бесплатный ответ и убрал причину покупать;
- эксперт продолжал давить после исчерпания objection attempts;
- эксперт сделал опасное утверждение по health, pregnancy, paternity, legal или self-harm;
- эксперт проигнорировал self-harm/suicide сигнал;
- эксперт обещал невозможную точность: exact name, точный медицинский/юридический исход, безусловную гарантию;
- эксперт ушел во внешний канал, запросил запрещенные персональные/конфиденциальные данные или нарушил platform boundary;
- эксперт взял чат и не работал его.

## 3. Перед стартом диалога

| Проверка | Хороший результат | Риск |
|---|---|---|
| Прочитана история клиента | Эксперт понимает прошлые покупки, темы, предыдущих экспертов | Повторяет уже сказанное или спорит с историей |
| Определен тип клиента | Новый, previous buyer, repeat topic, duplicate/new chat suspected | Всем дается одинаковый free reading |
| Проверены notes/comments | Эксперт учитывает комментарии, но не верит им слепо | Субъективный негативный ярлык блокирует продажу |
| Проверена стадия | Понятно: free, Book Now, paid, future booking, lift | Эксперт пишет не по стадии |
| Проверен schedule/availability | Нет конфликта с paid session, break, offline | Клиент покупает, но эксперт недоступен |

## 4. Free reading / trial

| Проверка | Хороший результат | Ошибка |
|---|---|---|
| Собраны минимальные данные | Эксперт уточнил нужный контекст, если его не хватает | Отвечает вслепую или задает слишком много лишнего |
| Есть эмпатия | Ответ звучит персонально и поддерживающе | Холодный шаблон |
| Даны 3-4 ограниченных insight | Клиент чувствует ценность, но ключ не раскрыт | Либо пусто, либо слишком много бесплатно |
| Нет полного закрытия запроса | Остается причина купить | Клиент получил ответ и не нуждается в сессии |
| Есть переход к intrigue | Инсайты ведут к конкретному продолжению | Ответ заканчивается без CTA |
| Учитывается previous buyer | Повторному платящему не дают полный новый free reading | Платящий клиент снова обслуживается бесплатно |

## 5. Intrigue

| Проверка | Хороший результат | Ошибка |
|---|---|---|
| Связана с запросом | Интрига вытекает из боли клиента | Общая фраза без привязки |
| Достаточно конкретна | Есть предмет: человек, ситуация, выбор, риск, следующий шаг | Абстрактно: "вижу важное" |
| Не раскрывает paid content | Заинтересовывает, но не отвечает полностью | Бесплатно отдает суть paid session |
| Не повторяется механически | Темы меняются, если клиент не реагирует | Одна и та же приманка много раз |
| Ведет к Book Now | После intrigue есть понятный CTA | Интрига висит без действия |

## 6. Book Now

| Проверка | Хороший результат | Ошибка |
|---|---|---|
| Book Now отправлен вовремя | После ценности и intrigue, без лишнего затягивания | Эксперт болтает и теряет момент |
| Обещанные темы ясны | Клиент понимает, за что платит | CTA без содержания |
| После Book Now нет нового бесплатного ответа | Ответы работают с возражением, а не раскрывают тему | Эксперт продолжает давать value бесплатно |
| Клиентский ответ классифицирован | Явное/скрытое/price/free-info/post-Book-Now objection | Эксперт не видит возражение |
| Попытки ограничены | После 3-4 попыток давление останавливается | Эксперт бесконечно пушит |

## 7. Objection handling

| Тип возражения | Хороший ответ | Плохой ответ |
|---|---|---|
| `price` | Переформулировать ценность, при наличии права дать coupon | Сразу снижать цену без ценности |
| `doubt` | Усилить доверие конкретикой и спокойным тоном | Спорить, обвинять клиента |
| `free-info` | Обозначить границу: это в paid session | Отвечать бесплатно |
| `hidden` | Увидеть уход от оплаты и вернуть к теме покупки | Продолжать бесконечное уточнение |
| `later` | Зафиксировать follow-up/reactivation | Давить прямо сейчас без повода |
| `aggressive` | Сохранять нейтральность, не вступать в конфликт | Отвечать грубо или защитно |

## 8. Coupons / discounts

| Проверка | Хороший результат | Ошибка |
|---|---|---|
| Проверена eligibility | Coupon соответствует платформе, новизне клиента и сроку | Отправлен недоступный код |
| Coupon не заменяет value | Сначала ценность и причина купить, потом discount | "Купи, потому что скидка" |
| Код отправлен копируемым сообщением | Клиент может использовать coupon | Код спрятан или непонятен |
| Expired/used сообщается честно | Эксперт прямо говорит, что coupon уже недоступен | Обещает то, чего нет |

## 9. Paid session

| Проверка | Хороший результат | Ошибка |
|---|---|---|
| Таймер виден и учитывается | Эксперт работает в пределах оплаченного времени | Не следит за временем |
| Сначала закрыты promised topics | Ответы соответствуют тому, что продавалось до Book Now | Эксперт уходит в новые темы |
| Нет долгого молчания | Сообщения идут регулярно; ориентир из видео: 8-9 сообщений за сессию как ожидание/минимум | Клиент платит и ждет |
| Новые темы вынесены в extension | Эксперт объясняет, что нужен новый слот | Все смешано в одну сессию |
| Session завершена корректно | Есть итог/следующий шаг/follow-up | Клиент остается без закрытия |
| Refund risk отслеживается | Долгое молчание или слабый ответ помечается | Риск видят только после жалобы |

## 10. Paid content gating

| Ситуация | Правило |
|---|---|
| Клиент купил будущую сессию | Не выдавать контент до ее начала |
| Между сессиями осталось 5-7 минут | Все равно не раскрывать будущий ответ заранее |
| Клиент просит "скажи сейчас, я уже купил" | Удерживать рамку: тема будет разобрана в сессии |
| Клиент купил вторую сессию и задает новую тему | Новая тема относится к новой оплаченной сессии |

Это один из самых важных revenue-control пунктов. В видео есть пример, где преждевременное раскрытие информации привело к отмене/потере ценности будущей сессии.

## 11. Reactivation / lift

| Проверка | Хороший результат | Ошибка |
|---|---|---|
| Есть причина возвращения | "После нашей сессии я проверила...", "появилось новое..." | "Привет, купи еще" |
| Клиент подходит для lift | Previous buyer, strong-intent, recent session, failed objection | Поднимаются все подряд |
| Сообщение короткое | Есть reason, intrigue, Book Now | Много воды |
| Не добавляется бесконечная новая intrigue | После запуска lift эксперт ведет к покупке | Эксперт снова и снова открывает новые крючки |
| Есть timing | Утро/начало смены/следующий день после сессии | Случайный follow-up |
| Учитывается history | Тема связана с прошлой покупкой или запросом | Эксперт не помнит клиента |

## 12. Sensitive topics и claim precision

| Категория | Требуемая реакция |
|---|---|
| `self-harm` / suicide | Остановить sales-flow, дать safety path, при необходимости escalation |
| `health` | Не ставить диагнозы, не обещать лечение |
| `pregnancy` | Не выдавать рискованные утверждения как факт |
| `paternity` | Не утверждать точное отцовство через "энергию" |
| `legal` / documents | Не давать юридически значимые гарантии |
| `exact names` | Не обещать точные имена/идентичности без основания |
| `18+` | Соблюдать возрастные ограничения |

## 13. Right panel / кабинет

QA должен проверять не только текст, но и использование кабинета:

- эксперт проверил профиль клиента;
- эксперт посмотрел purchase history;
- эксперт заметил previous experts / previous chats;
- эксперт добавил buyer в Favorites, если нужен future follow-up;
- эксперт оставил полезную note/comment;
- эксперт правильно использовал schedule;
- эксперт не ушел на break/offline с активной paid session;
- эксперт сообщил о technical issue в support, а не импровизировал.

## 15. Что можно автоматизировать

Первый слой автоматизации:

- stage mismatch warning;
- paid-session silence timer;
- future paid-session content warning;
- objection attempt counter;
- free-value leakage warning;
- coupon eligibility reminder;
- safety keyword/semantic flag;
- previous buyer reminder;
- reactivation due ping.

Второй слой:

- QA scoring assistant;
- mentor review queue;
- conversation outcome analytics;
- expert coaching recommendations;
- template health monitoring: где шаблоны звучат как copy-paste и снижают конверсию.
