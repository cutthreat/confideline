ТЗ: страница регистрации эксперта для Confideline

Публичная HTML-версия технического задания для программиста. Это отдельный expert application flow, а не доработка обычного signup. Документ привязан к текущему Confideline UI и админ-контуру.

Техническое задание

Result

  • Нужен отдельный поток регистрации эксперта в стиле careers/job application, а не обычный user signup.
  • На фронте уже подготовлен preview-макет: web/expert-registration-mockup.html.
  • Задача backend-разработки: подготовить сущности, маршруты и админ-процесс так, чтобы новый дизайн можно было натянуть без переделки логики.
  • Страница должна быть встроена в визуальную систему текущего confideline.com.

Scope

  • Только подготовка функционала под будущий новый дизайн.
  • Без сложной логики биллинга, расписаний, мэтчинга и real-time.
  • Без полноценного кабинета эксперта на этом этапе.

Done when

  • Есть отдельная сущность заявки эксперта.
  • Есть endpoint для приема формы.
  • Есть thank-you сценарий после отправки.
  • Есть админ-список заявок с фильтрами и карточкой просмотра.
  • Есть статусы и базовый workflow модерации.
  • Есть возможность позже привязать approve-заявку к будущему аккаунту эксперта.

Как проверить

  1. Открыть preview-макет и сверить блоки страницы: hero, benefits, requirements, process, FAQ, form.
  2. Убедиться, что backend принимает форму в отдельную таблицу, а не пишет сразу в user.
  3. Убедиться, что новая заявка появляется в админке со статусом new.
  4. Проверить смену статусов new -> in_review -> approved / rejected / needs_info.
  5. Проверить, что после approved можно безопасно инициировать следующий этап onboarding без ручной пересборки данных.

Контракт фронта

  • Рекомендуемый production route: /experts/apply или /careers/experts.
  • Блоки страницы: hero, преимущества, кого ищем, процесс отбора, FAQ, форма заявки.
  • Страница должна наследовать текущий сайт: header/footer, текущую фиолетово-розовую палитру, существующие кнопки и базовые формы.

Поля формы

full_name display_name email messenger_contact specializations languages experience_range country timezone availability_text about_text portfolio_links consent_moderation consent_test_task consent_truthfulness

Backend-модель

  • Рекомендуемая таблица: expert_application.
  • Поля: id, status, full_name, display_name, email, messenger_contact, specializations_json, languages_json, experience_range, country, timezone, availability_text, about_text, portfolio_links_json, consent_moderation, consent_test_task, consent_truthfulness, source, ip, user_agent, admin_comment, reviewed_by, reviewed_at, created_at, updated_at.

Статусы

new in_review needs_info approved rejected archived

Workflow

  1. Кандидат отправляет форму.
  2. Создается запись expert_application со статусом new.
  3. Кандидат видит thank-you экран или success-блок.
  4. Администратор открывает заявку в админке.
  5. Модератор меняет статус на in_review, needs_info, approved или rejected.
  6. При approved появляется действие на следующий onboarding flow.

Админка

  • Нужен раздел Expert Applications в admin модуле.
  • Список заявок: ID, дата, имя, email, специализация, страна, статус, ответственный.
  • Фильтры: статус, дата, страна, специализация, поиск по имени/email.
  • Карточка заявки: все поля анкеты, комментарий, история смены статуса, approve/reject/request info/archive.

Email и уведомления

  • После отправки формы отправлять подтверждение приема заявки.
  • После смены статуса опционально отправлять уведомление: needs_info, approved, rejected.
  • Тексты уведомлений вынести в отдельные шаблоны.

Технические рекомендации

  • Не использовать существующий RegistrationForm как базовую модель для expert flow.
  • Создать отдельный ExpertApplicationForm.
  • Создать отдельный controller, например ExpertApplicationController.
  • Не создавать User автоматически на submit.
  • Множественные поля хранить как JSON или через связующую таблицу.
  • Сразу предусмотреть защиту от спама: rate limit, honeypot или captcha, логирование IP/user-agent.

Что можно отложить

  • Автоматическое создание профиля эксперта.
  • Автоматический скоринг кандидата.
  • Календарь и расписания слотов.
  • Привязка биллинга/выплат.
  • Сложный медиазагрузчик.

Что важно не перепутать

  • Это не редизайн обычной страницы /signup.
  • Это не замена текущей модели пользователя.
  • Это отдельная воронка с ручной модерацией и отдельной админ-очередью.
