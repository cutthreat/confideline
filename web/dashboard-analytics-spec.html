ТЗ по аналитическому дашборду Confideline

Спецификация для бекенд-интеграции админского дашборда под эзотерические консультации в живом текстовом чате с поминутной оплатой.

Источник правды: `index-admin.php` Активная версия: `v3` Архивные варианты: `v1`, `v2`

Результат

В админке YouDate/Confideline есть рабочая страница дашборда, построенная на существующих админских компонентах и адаптированная под консультационный продукт, а не под дейтинговый сценарий.

application/modules/admin/views/default/index-admin.php

Область задачи

  • Только эзотерические / консультационные услуги.
  • Только живой текстовый чат с поминутной оплатой.
  • Воронка `free -> first paid -> repeat` обязательна.
  • LTV считается отдельным аналитическим слоем, не шагом основной воронки.

Технический стек и ограничения

  • Боевой дашборд собирается на текущем стеке `Yii2 + yii\bootstrap + AdminLTE 2`.
  • Основа админских ассетов подключается через `application/modules/admin/assets/AdminAsset.php`.
  • Используются существующие стили админ-панели: `admin.min.css`, `info-box`, `box`, стандартные таблицы, `ChartJs`.
  • `Bootstrap 4.6` есть в публичной теме сайта, но это другой контур и не источник правды для боевой админки.
  • Файлы из `web/` служат только для передачи и навигации, а не как CSS-слой для переноса в админку.

Готово, когда

  • Верхний экран отвечает на 4 вопроса: спрос, выход в бесплатные минуты, конверсия в первую оплату, повторы.
  • Продуктовый и операционный контуры читаются раздельно.
  • В файле нет дейтинговой логики: лайков, мэтчей, подарков как ядра продукта, приватных фото и т.д.
  • Разметка опирается на существующий админский стек: `info-box`, `box`, таблицы, `ChartJs`.

Как проверить

  • Открыть локальную админку: `http://127.0.0.1:8092/admin`.
  • Убедиться, что рендерятся блоки `Дашборд живых консультаций`, `Фильтры и период`, `Потери между бесплатным этапом и оплатой`, `LTV и когорты`.
  • Проверить синтаксис файла представления: `php -l application/modules/admin/views/default/index-admin.php`.
  • Если нужен rollback, сравнить `index-admin.php` с `index-admin-v1.php`.

Основные блоки дашборда

  • Верхний блок с системными статусами и управляемым периодом.
  • Первый ряд KPI: старт бесплатных минут, конверсия в первую оплату, доля повторных оплат, GMV/чистая выручка.
  • Второй ряд KPI: спрос, принятие, медианный первый ответ, потери между бесплатным этапом и оплатой.
  • Продуктовый контур, воронка, unit-экономика, повторы и выручка, LTV и когорты, драйверы роста, риски и операционка.

Воронка

Просмотр эксперта / каталога → Создан запрос → Принято экспертом → Старт бесплатных минут → Показан экран оплаты → Первая оплаченная минута → Списанные оплаченные минуты → Повторная платная сессия

`LTV D7 / D30 / D90` идут отдельным когортным слоем ниже, а не вставляются внутрь основной продуктовой воронки.

Контракт верстки

  • Порядок секций фиксирован: продуктовый контур, воронка и unit-экономика, повторы и выручка, LTV и когорты, драйверы роста, риски и операционка.
  • Используются только существующие админские компоненты YouDate/Yii2.
  • Фильтры и кнопки действий сохраняют свое место в шапке даже в макетном режиме.
  • Пустые данные не должны скрывать блоки или ломать сетку.

Контракт данных

  • KPI-карточка: `title`, `value`, `description`, `icon`, `color`.
  • Строка воронки: `step`, `count`, `conversion`, `meaning`.
  • Строка очереди: `incident`, `waiting`, `oldest`, `statusColor`, `statusText`.
  • Графики: `labels`, `datasets`, `legend`, `colors`.

Примечание по бекенд-привязке

  • Для верстки и UI-передачи этого ТЗ достаточно.
  • Для реализации без смысловых потерь нужно отдельно зафиксировать источники данных и формулы расчета метрик.
  • Критичные метрики для явного маппинга: `старт бесплатных минут`, `показ экрана оплаты`, `первая оплаченная минута`, `повторная платная сессия`, `LTV D7 / D30 / D90`, `размер очереди`, SLA, платежные инциденты.

Чеклист приемки

  • Верхний экран читается как `free -> paid -> repeat`.
  • Есть отдельный блок потерь и отдельный блок рисков.
  • Есть отдельный LTV-слой.
  • Нет дейтинговых терминов и сущностей.
  • Бекенд может подставить реальные данные без перестройки контракта верстки.
