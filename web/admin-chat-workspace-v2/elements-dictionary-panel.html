Expert Flow: путь от сигнала к бизнес-результату

Вкладка показывает не экранные элементы по отдельности, а рабочую последовательность эксперта: что он видит, почему индикатор нужен, какое действие выполняет и какой результат должен получить.

Итог сценария Chats Клиент получает релевантный ответ, понимает границу free value и покупает или продлевает paid chat.

Сквозной чат не дробится: free trial, Book Now, payment pending, paid session, objection и extend живут в одной истории.

Левая область

1. Выбрать правильный Chat из очереди

Эксперт начинает с фильтров, которые меняют приоритет работы: Reply, SLA, Live, PP, Sell, Favorite, Archive.

Reply/SLA = клиент ждет Live = оплачено PP/Sell = близко к оплате
Центр

2. Понять stage и следующий безопасный шаг

Header и workflow hint фиксируют стадию: free boundary, Book Now, objection, paid live, extend window.

Stage chip Workflow warning Live / PP
Центр

3. Дать value без нарушения free boundary

Эксперт отвечает по сути, но не отдает полный продукт бесплатно. Composer подсказывает шаблон: need data, Book Now, objection или paid topic.

Quick reply Composer guardrail Attachments
Центр + Pay

4. Предложить оплату или продление в уместный момент

Offer используется только когда stage и контекст это оправдывают. При active paid session важнее доставка, при low time - extend.

Offer Start / Stop Timer / Extend
Результат

5. Paid chat продан, продлен или корректно закрыт

Итог фиксируется через payment/session events, resolve или objection state. Если нужна компенсация, эксперт создает request, а не меняет деньги вручную.

Зачем здесь индикаторы

SystemReply, SLA, unread, last activity показывают операционную срочность.
BillingLive, PP, balance, paid status показывают денежное обязательство и шанс оплаты.
WorkflowStage, next action, warning и objection защищают сценарий от хаотичных ответов.
ModeratorРиски и team notes ограничивают pushy sales, safety и quality ошибки.
Expert-privateFavorite/private note помогают самому эксперту вернуться к кейсу, но не маршрутизируют команду.
Итог сценария Pings Ping превращается в осмысленный Chat или убирается из очереди без спама и давления.

Ping - это pre-chat сигнал интереса. Он не должен получать Chat SLA, пока клиент не вступил в диалог.

Левая область

1. Отобрать релевантный Ping

Эксперт смотрит не все подряд, а сигналы с причиной: NEW, Intent, Credits, Lift Due, Future Paid, Favorite.

NEW = свежий сигнал Intent = есть повод Credits = готовность платить
Правая область

2. Проверить причину контакта

Workflow и Client объясняют, почему ping возник: интерес к эксперту, reactivation, кредиты, предыдущая покупка или future paid reminder.

Ping reason Client context Moderator note
Центр

3. Выбрать мягкое первое действие

Send template используется для аккуратного касания. Invite используется, когда есть реальный intent или платежная готовность.

Send template Invite Favorite / Dismiss
Переход

4. Клиент отвечает или принимает invite

После ответа ping перестает быть pre-chat сигналом и становится обычным сквозным Chat с историей, stage и дальнейшей продажей paid chat.

Create/open Chat Attach ping context Start Chat flow
Результат

5. Ping переведен в Chat или закрыт

Если клиент не отвечает или повод слабый, ping закрывается через Dismiss. Если есть потенциал, эксперт может оставить personal Favorite/private note.

Почему Pings отделены от Chats

Нет reply SLAДо ответа клиента это не активный диалог, а сигнал интереса.
Нет paid deliveryStart/Stop paid session появляется только в Chat, не в ping-сигнале.
Нужен поводIntent, Credits и ping reason защищают от случайного массового outreach.
КонверсияЦель Pings - не ответить ради ответа, а перевести подходящий сигнал в Chat.
Личная памятьFavorite/private note помогают эксперту, но не создают глобальный приоритет.
