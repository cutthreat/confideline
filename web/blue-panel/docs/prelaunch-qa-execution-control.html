Pre-launch QA · tester route · PASS/WARN/STOP

Тестировщик запускается только когда есть что доказывать

QA не должен хаотично обходить сайт. Он должен проверить один безопасный контрольный заказ: клиентский путь, админку, исполнителя, уведомления, support, аналитику и итоговый отчет. Пока READY нет, QA-start остается STOP.

PM-решение

Тестировщика запускаем только после двух внешних входов: Игорь показал безопасный рабочий заказ, PM/Ксения допустили минимум одного исполнителя. До этого QA-пакет можно готовить, но проход не стартует.

Зачем эта страница

Она задает один стандарт: что считать READY, какие скрины нужны, как принимать PASS/WARN/STOP и когда после QA можно обсуждать первый трафик.

0accepted runtime proof
0/5экспертов допущено proof-фактами
12proof-точек для QA
STOPpaid traffic до QA verdict

Когда можно запускать тестировщика

1. Safe order READYЕсть test order id, no real charge, marker, checkout/status proof.
2. Исполнитель READYМинимум один эксперт/агент допущен и может ответить под своей ролью.
3. No-send READYСобытия создаются, preview есть, реальные письма/сообщения не уходят.
4. Admin route READYАдмин видит заказ, вопрос, исполнителя, SLA, events, support.
5. QA fixtures READYТестовые роли, вопрос, услуга, expected result, stop conditions.
6. Report shell READYЕсть место для скринов, verdict, ссылок, residual risks и next actions.
PM-правило: если один из первых четырех пунктов красный, QA не стартует. Иначе тестировщик будет фиксировать отсутствие базовой готовности вместо проверки сервиса.

Как PM принимает результат QA

VerdictЧто означаетЧто делает PMВлияние на запуск
PASSСценарий работает, proof полный, риски не блокируют первый тест.Переводит соответствующий слой в зеленый или подтвержденный желтый.Можно двигать следующий gate, но не весь запуск автоматически.
WARNОсновной путь работает, но есть ограничение, ручной обход или scope debt.Фиксирует риск, владельца и срок закрытия.Может быть допустимо для ограниченного QA/первого теста, но не для масштабирования.
STOPЕсть риск платежа, потери заказа/вопроса/ответа, реальной отправки, неуправляемого support или обмана клиента.Возвращает задачу владельцу, трафик закрыт.Запуск запрещен до retest PASS/WARN.

Go / no-go

QA сейчас не стартует: нет safe order proof, нет accepted исполнителя, нет no-send runtime proof, нет admin route proof и нет support/problem proof.
PM может закрывать автономно: маршрут тестировщика, proof-лист, report shell, acceptance rules, связи с Blue Panel и Trello-result. Реальный QA запускается после READY.
