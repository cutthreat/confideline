Глобальный статус проекта: что доказано, что не готово и куда двигаться

Это верхняя контрольная карта по исходной PM-задаче. Она не заменяет детальные страницы, а показывает состояние всех слоев запуска одним взглядом: что уже подтверждено, где есть база, где запуск заблокирован и какой proof нужен дальше.

Главный вывод

Проект имеет сильную основу: backend Confideline, дизайн Oracle/Nebula, Trello-план, Blue Panel, обучение, co2p-пакеты и QA-инфраструктуру. Но MVP нельзя считать готовым к клиентам: нет runtime proof платной консультации и связанных support/notification/analytics сценариев.

Следующий ключевой proof

Один контрольный заказ без реального списания и без реальных писем: клиент создает заказ, задает вопрос, эксперт/агент получает задачу, отвечает, support видит проблему, события фиксируются, QA публикует отчет.

Решение PM: работа идет в правильном направлении, но цель еще не закрыта. Сейчас мы не расширяем хаотично список функций, а закрываем красный маршрут: test order → клиентский путь → эксперт/админка → support → no-send уведомления → QA → legal/payment decisions → малый трафик.
