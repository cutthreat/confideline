PM-вывод

Backend не пустой: есть заказы, сообщения, админский чат, уведомления и жалобы. Но это не доказывает lifecycle платной консультации, пока один test order не пройдет весь маршрут.

Как использовать

Игорю отдавать не “сделать backend”, а конкретные связки: order → question → service session → assignment → chat → events → support → QA proof.

Решение PM

Не переписывать с нуляOrder, messages, admin chat, notifications и reports уже есть как база.
Не считать готовымНи один code-факт не заменяет test order runtime proof.
Главная задача ИгорюСвязать существующие кирпичи в единый route платной консультации.
Главная задача QAПройти один заказ и заполнить публичный QA-report shell реальными evidence.
