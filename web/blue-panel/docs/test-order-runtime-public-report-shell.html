Публичный контейнер отчета по контрольному заказу

Это не доказательство выполнения теста. Это заранее подготовленный формат результата, который будет заполнен после runtime QA: order id, session id, скрины, логи, PASS/WARN/STOP и задачи Игорю.

Где будет жить итог

Публичный shell опубликован в каталоге QA-отчетов: web/qa-reports/nebula-test-order-runtime-qa-shell-2026-06-05.

Текущий статус

Формат готов, runtime proof не заполнен. Все строки остаются красными до фактического прохода.

Правило именования evidence

Зачем это нужно: если QA назовет скрины случайно, Игорь и PM потеряют связь между шагом, доказательством и дефектом. Поэтому evidence именуется по маршруту проверки.

Как shell будет использоваться

До тестаСтраница показывает, что именно нужно собрать и какие proof-файлы должны появиться.
Во время тестаQA идет по именам evidence и не спорит, какие скрины нужны.
После тестаShell заменяется или дополняется фактическим отчетом с реальными скринами/логами.
Для ИгоряКаждый FAIL/WARN получает факт, ожидание, шаги повторения, evidence и retest.
