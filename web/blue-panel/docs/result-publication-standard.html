Процесс

Стандарт публикации результата задачи

После выполнения задачи результат оформляется как веб-страница, а не как набор разрозненных файлов. Trello хранит ссылку на итог, Blue panel показывает смысл, proof и следующий шаг.

Для тебя и PM

Видно, почему задача закрыта, что доказано и что делать дальше.

Для Заказчика

Можно открыть страницу, увидеть результат и согласовать без технического шума.

Для Игоря

Есть понятный пакет: макет, связь с backend, ТЗ, ограничения и критерии готовности.

Для Ксении

Понятно, что именно проверить: тон, обучение, контент, экспертские инструкции.

Для тестировщика

Есть ожидаемый результат и сценарии проверки до запуска трафика.

Поток результата

1. PM закрывает задачу или готовит пакет.
2. Создается страница результата в Blue panel.
3. Если результат завершен, страница публикуется через GitHub Pages.
4. В Trello карточку добавляется ссылка на страницу результата.
5. Если есть Google/Figma/Drive/Trello источники, они аккуратно собраны внутри страницы.
6. Игорь/Ксения/тестировщик получают не “файл”, а рабочую страницу с контекстом.

Что должно быть на странице результата

БлокСодержание

ИсточникиGoogle Docs, Figma, Trello, local KB, QA, competitor research.
Решение PMЧто принимаем как рабочее решение и почему.
ПередачаКому передано и что должен сделать следующий участник.
ПроверкаКак понять, что задача внедрена правильно.
