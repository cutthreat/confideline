Качество доказательств по слоям проекта

Эта страница показывает не просто статус слоя, а силу доказательства. Она отделяет факт на сайте от PM-вывода, Trello, макета, исследования или подготовленного документа.

2 слоя достаточно для PM4 слоя частично/контекст9 слоев требуют runtime/QA/decision
Главный вывод

Большая часть запуска сейчас подтверждена подготовкой, картами и контрактами, но не runtime-фактами. Поэтому запуск остается STOP, даже если PM-инфраструктура стала сильнее.

Как читать

L1-L2 нужны для функций, которые трогают клиента, оплату, ответ, support, уведомления и трафик. L5-L8 годятся для планирования, но не для зеленого запуска.

достаточно для PM

Стратегия и мастер-план

Сейчас: L8 PM-вывод + L5 Trello/Blue Panel

Нужно: L5-L8 достаточно для управленческой основы

Риск: Стратегия не доказывает работоспособность сайта.

 достаточно для PM

Blue Panel / PM cockpit

Сейчас: L3-L5 опубликованные страницы, CSV, proof-ссылки

Нужно: L3-L5 достаточно для управленческого контроля

Риск: Панель может устареть после новых ответов команды.

 только контекст

Trello / задачи месяца

Сейчас: L5 источник намерений и плана

Нужно: L5 для плана, L1-L2 для результата внедрения

Риск: Карточка не доказывает внедрение.

 недостаточно для запуска

Backend Confideline / админка

Сейчас: L3 подготовленные gates и handoff

Нужно: L1 runtime order + L2 QA для зеленого

Риск: Нет единого заказа с вопросом, исполнителем, ответом, событиями и support.

 частично

Frontend/design Oracle/Nebula

Сейчас: L4 design/screen contracts

Нужно: L4+L3 для передачи, L1-L2 для готовности paid-flow

Риск: Макет без backend/action/error states не доказывает функцию.

 красный

Клиентский платный путь

Сейчас: L8/L3 описанный сценарий и контракт

Нужно: L1 runtime path + L2 QA

Риск: Нет прохода offer -> order -> question -> answer -> support.

 красный

Рабочее место эксперта/агента

Сейчас: L3 handoff и требования

Нужно: L1 assignment/answer + L2 QA

Риск: Не доказано, что исполнитель получает и закрывает задачу в системе.

 красный

Школа и первые 5 экспертов

Сейчас: L6 материалы + L8 PM-адаптация

Нужно: L1/L2 admission journal, scorecard, пробный ответ, E01-E05 verdict

Риск: 0/5 экспертов accepted.

 красный

Email, уведомления, события

Сейчас: L3 no-send acceptance

Нужно: L1 event log на order_id + L2 QA

Риск: Шаблоны без trigger/event log не доказывают работу.

 красный

Support и проблемные ситуации

Сейчас: L3 support/failure contracts

Нужно: L1 support_case_id на order_id + L2 QA

Риск: Нет проблемного сценария с владельцем и решением.

 желтый

Документы и checkout доверие

Сейчас: L6/L8 пакет и PM-тексты

Нужно: L3 HTML-ready + founder/legal/payment decision + checkout screen

Риск: PM не утверждает seller/provider/descriptor/refund/geography.

 красный

Маркетинг, трафик, LTV

Сейчас: L7 research + L8 PM-модель

Нужно: L1 purchase analytics + L2 QA + capacity proof

Риск: CAC/LTV без source/session/order/value является гипотезой.

 красный

Аналитика покупки

Сейчас: L3 capture sheets

Нужно: L1 source/session/order/value/currency/service/support row

Риск: Нет связанной строки покупки на одном заказе.

 красный

QA перед трафиком

Сейчас: L3 QA runbook/contract

Нужно: L2 public QA report PASS/WARN/STOP

Риск: QA нельзя стартовать без R01/R02.

 желтый

Founder/legal/payment decisions

Сейчас: L8 список решений и блокеров

Нужно: L5/L3 зафиксированное решение владельца

Риск: PM не может принять юридические и платежные решения сам.

PM-правило: если слой связан с деньгами, клиентом, экспертом, ответом, support, уведомлениями, аналитикой или рекламой, для зеленого статуса нужен L1/L2 proof. Все остальное — подготовка или контекст.
