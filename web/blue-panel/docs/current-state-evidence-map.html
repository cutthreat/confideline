Главный PM-вывод

Мы хорошо собрали план, стратегию и контуры задач. Но сайт как платная консультационная услуга еще не доказан одним безопасным контрольным заказом.

Что считается proof

ID заказа, связанный вопрос, назначенный эксперт, ответ, no-send события, support case, admin timeline, QA-отчет или утвержденное founder/legal/payment решение.

Что не считается proof

ТЗ, макет, Trello-карточка, обсуждение, гипотеза или “это должно быть в backend”.

Карта по слоям

доказано как решение

Стратегия

Факт: принято platform-first направление: сначала универсальная paid P2P-платформа, Nebula как первая ниша.

Ограничение: стратегия не доказывает работу сайта.

 доказано как PM-контур

Мастер-план и Blue Panel

Факт: есть структура: стратегия, план июня, светофор, proof-очередь, R01/R02, daily/weekly/monthly.

Ограничение: панель должна обновляться по фактам команды.

 снимок источника

Trello как план месяца

Факт: снят read-only снимок июньских и стратегических карточек, включая метку “обновить”.

Ограничение: Trello не доказывает внедрение.

 нужен runtime

Backend Confideline

Факт: backend считается базой сервиса.

Не доказано: один маршрут order → question → expert → answer → events → support.

 нужна связка

Frontend Oracle/Nebula

Факт: дизайн и экранные контуры есть.

Не доказано: полный screen → backend action → content → error/empty state → QA по каждому критичному экрану.

 материалы есть

Обучение экспертов

Факт: есть база уроков и школа v1.

Не доказано: допуск 5 экспертов, E01 accepted для QA.

 пакет есть

Email и уведомления

Факт: no-send подход и события описаны.

Не доказано: event log на одном safe order без реальных писем.
