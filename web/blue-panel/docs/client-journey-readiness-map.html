Путь клиента пока не готов к рекламе

Нужно доказать не отдельные страницы, а один связанный клиентский маршрут: оффер → выбор → заказ → вопрос → назначение → ответ → уведомления → support → отчет. Сейчас есть стратегия, макеты и пакеты, но нет одного safe order proof.

runtime proof = 0трафик запрещенпакеты естьмаршрут понятен
Главная проблема

Середина клиентского пути не доказана: заказ, вопрос, назначение эксперта, ответ, no-send, support и аналитика должны пройти по одному order_id.

Что меняет статус

Accepted R01 от Игоря + accepted R02 от Ксении/E01, затем QA PASS/WARN/STOP по этому клиентскому пути.

Что PM делает сам

Держит карту, proof-формы, screen/backend/content разбор и не расширяет путь до подтверждения базового сценария.

12шагов клиентского пути
7красных runtime-блокеров
5желтых подготовленных шагов
0QA-отчетов по пути клиента

Маршрут глазами клиента

CJ01желтый

Понять оффер

Клиент понимает, что покупает текстовую консультацию, срок ответа, ограничения и поддержку.

Proof: экран оффера + CTA contract.

 CJ02красный

Выбрать услугу или эксперта

Клиент выбирает пакет, тему, категорию или эксперта без потери смысла.

Proof: выбор связан с order/session.

 CJ03желтый

Войти без потери заказа

После регистрации/логина клиент возвращается к тому же заказу.

Proof: guest → login → same order.

 CJ04красный

Создать safe order

Заказ создается без реального списания, но с нормальным lifecycle.

Proof: R01 order_id + no-charge marker.

 CJ05красный

Задать вопрос

Вопрос клиента не теряется и связан с консультацией.

Proof: question_id на том же order_id.

 CJ06красный

Увидеть статус ожидания

Клиент понимает, кто отвечает, когда ждать и куда писать при проблеме.

Proof: assignment + deadline + status.

 CJ07красный

Получить ответ

Ответ виден клиенту, эксперту и админу как один результат услуги.

Proof: answer_id + client/admin/expert screens.

 CJ08красный

Получить уведомления

В тесте события формируются, но реальные письма/сообщения не уходят.

Proof: no-send event log.

 CJ09красный

Открыть проблему

Support видит заказ, чат, эксперта, причину и решение.

Proof: support_case_id.

 CJ10approval

Понять правила

До оплаты видны Terms, Privacy, disclaimer, refund/support boundary.

Proof: HTML-ready docs + founder/legal decisions.

 CJ11желтый

Вернуться повторно

Есть причина вернуться: follow-up, новый вопрос, письмо, новый эксперт.

Proof: repeat CTA/event после теста.

 CJ12красный

Попасть в отчет

PM видит source → order → answer → support → outcome.

Proof: QA report + captured IDs.
Критический путь: CJ04-CJ09 и CJ12 сейчас красные. Это означает, что клиентский путь нельзя отдавать в рекламу, даже если лендинг визуально готов.
