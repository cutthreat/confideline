Единый пакет передачи: контрольный заказ

Один маршрут для Алексея, Игоря, QA и PM: что открыть первым, что сделать, какие proof-ссылки приложить и что нельзя запускать до фактического прохождения заказа.

PM-решение

Пока не добавляем новые функции в хаос. Сначала доказываем один безопасный контрольный заказ: без реального списания, без реальных писем, с видимостью в админке, работой эксперта и support-сценарием.

Кому нужен пакет

Алексею — для согласования логики с Заказчиком. Игорю — для внедрения/подтверждения AC01-AC09. QA — для прохождения только после READY. PM — для обновления readiness по фактам.
