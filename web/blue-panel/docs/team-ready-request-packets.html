Готовые запросы команде

Это страница для практического PM-действия: что именно можно отправить Игорю, QA, Ксении, Антону и основателю, какие ссылки приложить и какой результат принять. Trello не редактируется автоматически.

3 срочных runtime-запроса2 параллельных запроса1 PM-правило приемки
Как использовать

Открыть нужную карточку, передать человеку запрос и ссылки. Когда человек вернет результат, проверить его через реестр приема доказательств и только после этого менять статус.

Главная граница

Эти запросы не запускают платежи, письма, рекламу или production-изменения. Они задают формат результата и proof для дальнейшей приемки.

Запросы по ролям

1ИгорьСначала · Красный

Показать безопасный контрольный заказ по AC01-AC09

Запрос: Нужно показать один безопасный тестовый заказ без реального списания и без реальной отправки писем: order, question, session/task, assignment, workspace, answer, no-send events, support case.Вернуть: Order id, session/task id, admin route screenshots, performer workspace screenshots, event log, support case, note no real charge/no real send.Не принимаем: Устное работает; один скрин без ID; реальный платеж; реальное письмо; route без связи с заказом. 2QA / тестировщикПосле READY Игоря · Красный

Пройти контрольный заказ и дать PASS/WARN/STOP

Запрос: После READY пройти путь как клиент, админ, исполнитель и support: оффер, тестовый заказ, вопрос, назначение, ответ, no-send события, problem state, итог.Вернуть: Публичный QA-отчет со скринами, дефектами, severity, raw evidence и итогом PASS/WARN/STOP.Не принимаем: Чеклист без скринов; переписка вместо отчета; отчет без order/session marker. 3Ксения / экспертыДо QA · Красный

Дать хотя бы одного допущенного эксперта для контрольного заказа

Запрос: Проверить материалы как ревизор и помочь закрыть допуск минимум одного исполнителя: регламент, тестовый кейс, пробный ответ, SLA, доступ и назначенная анкета.Вернуть: Строку допуска, пробный ответ, замечания к материалам, оценку понятности, рекомендацию допущен/доработка/не допущен.Не принимаем: “Эксперт готов” без журнала; общие замечания без примеров; отсутствие пробного ответа; нет SLA или доступа. 4АнтонПараллельно после PM-сверки · Желтый

Сверить платную воронку Oracle/Nebula с backend-сценарием

Запрос: Проверить и доработать экраны, которые ведут к платной консультации: оффер, checkout, вопрос, чат/ответ, support, FAQ, error states. Макет должен вести пользователя к рабочему действию, а не быть просто красивым.Вернуть: Ссылка/скрины обновленных экранов и состояний, список нерешенных UX-вопросов, где нужен backend или контент.Не принимаем: Красивый экран без сценария; нет error states; нет связи с backend/action. 5ОсновательПеред финальным checkout · Желтый

Закрыть legal/payment решения, которые PM не может принять сам

Запрос: Нужно принять решения: legal seller, payment provider, descriptor, refund review window, launch geography, one-time vs subscription for Phase 1.Вернуть: Явные решения по каждому пункту или отметка отложено с причиной и владельцем.Не принимаем: Потом решим; нет refund/payment boundary; нет seller/provider path. 6PM / CodexПостоянно · Зеленый

Принимать результаты только через proof-формат

Запрос: Каждый внешний результат должен быть превращен в Blue Panel proof: статус, что доказано, что не доказано, следующий шаг, CSV/ссылка, локальная и внешняя проверка.Вернуть: Публичная proof-страница или обновленный реестр с проверенной ссылкой.Не принимаем: Текст в чате без страницы; ссылка 404; зеленый статус без evidence.
PM-вывод: самые важные запросы сейчас — Игорю по безопасному контрольному заказу и Ксении/экспертам по допуску минимум одного исполнителя. Остальные можно вести параллельно, но они не открывают paid traffic без runtime/QA proof.
