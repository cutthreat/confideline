Confideline backend / admin · gate запуска

Backend готов не тогда, когда “что-то есть”, а когда заказ управляем

Confideline дает платформенную базу: пользователи, чат, админские наработки, email, payment sandbox, QA и отчеты. Но для Nebula запуск доказан только если один контрольный заказ проходит через backend, админку, исполнителя, события, support и QA-отчет.

PM-решение

Backend/admin слой остается красным для запуска, пока нет proof по одному safe test order. Наличие папок, макетов, моделей и старых QA-отчетов переводит область в “есть база”, но не в “можно запускать”.

Go/no-go правило

STOP: если backend не создает безопасный test order, не связывает вопрос с заказом, не назначает исполнителя, не показывает заказ в админке, не пишет no-send события и не создает support-case, первый трафик и реальные платежи запрещены.
Минимальный PASS: один test order имеет order_id, question/session, assignment, workspace исполнителя, ответ, admin timeline, no-send events, problem/support case и QA report со скринами.
