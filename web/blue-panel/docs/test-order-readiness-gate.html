Можно ли начинать контрольный заказ?

Эта страница отделяет подготовку теста от самого теста. Если здесь есть красный пункт, QA не должен начинать проход, потому что результат будет не доказательством работы сервиса, а шумом из-за неподготовленных условий.

сейчас gate не закрытможно готовить данныецель: допуск к QA-проходу
PM-решение

До первого runtime QA нужно закрыть минимальные условия: test checkout без списания, no-send уведомления, тестовые роли, доступ к админке, тестовая услуга, support-сценарий и место публикации отчета.

Что считается успехом gate

Все критические условия в зеленом статусе. После этого QA проходит test order и заполняет отчет PASS/WARN/STOP.

5критических условий пока требуют подтверждения
4условия можно подготовить PM/QA до Игоря
1выход: разрешение на QA-проход
0реальных платежей/писем разрешено

Вердикт на сейчас: начинать реальный QA-проход рано. Можно закрывать подготовку: роли, услуга, вопрос, support-сценарий, доступы, no-send и safe test checkout. После зеленого gate запускается test order.

Решение gate

ВердиктКогда ставитьЧто делать дальше
READYВсе критические условия закрыты, real payment/email отключены, QA знает роли и маршрут.Запускать QA-пакет test order и заполнять отчет.
PREPAREКритические риски не затронуты, но не хватает ролей, вопроса, услуги, support-сценария или before-state.PM/QA готовят данные без обращения к production-платежам/письмам.
STOPНет safe checkout, no-send, доступа к админке или есть риск реальных платежей/писем.Остановить QA и вернуть задачу Игорю/PM с конкретным блокером.

Что делать без участия пользователя

PM сам готовитТекст вопроса, support-сценарий, чеклист evidence, структуру отчета, ссылки в Blue Panel и CSV.
QA сам готовитBefore-state, имена скринов, порядок прохода, фиксацию PASS/WARN/STOP.
Игорю передается только конкретикаSafe test order, no-send, admin visibility, role/workspace, support card. Без общих слов “проверьте сайт”.
Пользователь нужен только при gateЗакрытый доступ, конфликт источников, legal/payment/founder решение или production-риск.
