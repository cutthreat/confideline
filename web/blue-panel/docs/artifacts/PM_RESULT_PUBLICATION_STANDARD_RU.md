# Стандарт публикации результата задачи на веб-панели

## Цель

После выполнения задачи результат не должен жить только в Trello, Google Docs, CSV или локальной папке. Для каждой завершенной или передаваемой задачи создается человекочитаемая страница результата на Blue panel / GitHub Pages.

Эта страница нужна сразу пяти ролям:

- Основатель/PM: быстро понять, что сделано и можно ли согласовывать дальше.
- Заказчик: увидеть результат без технического шума.
- Игорь: получить понятный пакет для внедрения или доработки.
- Ксения: проверить понятность, тон, контент, обучение или экспертскую часть.
- Тестировщик: увидеть ожидаемый результат и сценарии проверки.

## Что считается результатом

Результат задачи = веб-страница с собранным пакетом:

1. Что делали и зачем.
2. Что было исходным состоянием.
3. Что получилось.
4. Где proof: скриншоты, QA-отчет, макет, ссылка на live/local/public страницу.
5. Какие документы использованы: Google Docs, Figma, Trello, QA, local KB, competitor research.
6. Что нужно сделать дальше.
7. Кому передается: Игорю, Ксении, тестировщику, PM или founder decision.
8. Как проверить готовность.

## Где хранится

- Blue panel: рабочая витрина и мастер-план.
- GitHub Pages: публичный доступ к завершенным результатам и QA-отчетам.
- Trello: карточка месяца со ссылкой на итоговую веб-страницу.
- Google Docs/Figma: внешние источники, но не единственное место результата.

## Правило для Trello

В карточке Trello в поле “Результат выполнения” ставится ссылка не на набор файлов, а на страницу результата Blue panel / GitHub Pages. Если в задаче использовались Google Docs/Figma/Drive, они аккуратно перечисляются внутри страницы результата.

## Стандарт страницы результата

- Короткое название задачи.
- Статус: черновик, на согласовании, готово PM, передано Игорю, внедрено, проверено QA.
- Итог для обычного человека.
- Доказательства.
- Связанные источники.
- Решение PM.
- Следующие действия.
- Блокеры, если есть.

## Стандарт для промежуточных дочерних ресурсов

Промежуточный ресурс тоже делается как веб-страница, если его должен читать человек. CSV/JSON/MD остаются вложениями для данных, но не заменяют страницу.

## Что нельзя

- Давать только CSV как результат для Заказчика.
- Давать только Google Doc без контекста в Blue panel.
- Считать локальный файл результатом, если его нельзя открыть из панели.
- Публиковать задачу как готовую без proof.
- Прятать Figma/Google/Trello источники без пояснения, что именно оттуда взято.
