# Пакет готовности к следующему PM-проходу

Дата: 2026-06-04
Цель: чтобы следующий проход был рабочим, а не повторным поиском исходных данных.

## 1. Что теперь есть

1. Полная карта Trello-доски.
2. Карта карточек по спискам.
3. Карта комментариев, вложений, чек-листов и ссылок.
4. Карта внешних ссылок с доступностью.
5. Список важных блокеров доступа.
6. Список пустых/тонких карточек.
7. Первичная карта областей проекта.
8. Стратегическая доска в Blue panel.
9. Launch Readiness Architecture.
10. PM model: Blue panel как мастер-план, Trello как месячная доска.

## 2. Как начинать следующий проход

Порядок:

1. Открыть `trello-full-intake-summary.json`.
2. Открыть `trello-card-area-map.csv`.
3. Выбрать область работы: email, чат, экспертский контур, обучение, legal, marketing, admin, QA.
4. Открыть все карточки этой области из `trello-full-cards-redacted.json`.
5. Открыть внешние ссылки этой области из `trello-important-accessible-links.csv`.
6. Если ссылка находится в `trello-important-link-blockers.csv`, не гадать, а запросить доступ с конкретным URL и причиной.
7. Сформировать PM-вывод: факты, выводы, риски, решение.
8. Обновить Blue panel.
9. Только потом готовить Trello-карточки месяца.

## 3. Приоритет следующего рабочего прохода

Рекомендую идти не по всей доске сразу, а по P0-направлениям:

1. Email/уведомления/рассылки.
2. Admin chat / paid session lifecycle.
3. Экспертский доступ и кабинет.
4. Школа экспертов и регламент.
5. Admin operational dashboard.
6. Failure states + QA до трафика.
7. Legal HTML-package.
8. CAC/LTV и traffic readiness.

## 4. Когда PM должен сигнализировать владельцу

Только если:

- важная Google/Figma/Drive ссылка закрыта;
- нужна реальная legal/payment/founder decision;
- ссылка указывает на внешний документ, без которого нельзя закрыть P0-решение;
- есть противоречие между Trello, банком знаний и текущим backend/runtime;
- нужен доступ в production/admin, который нельзя заменить существующими QA-отчетами.

## 5. Что нельзя делать в следующем проходе

- Не создавать задачи в Trello без утверждения месячного плана.
- Не считать Trello-карточку истиной без проверки вложений и комментариев.
- Не считать доступную ссылку прочитанной, пока ее содержимое не извлечено.
- Не переносить dating-логику в Nebula без классификации: universal / dating-specific / adaptable.
- Не публиковать legal/payment документы без approval gate.

## 6. Готовность

Следующий PM-проход можно начинать полноценно. Теперь есть карта источников и список недочетов. Главная работа следующего прохода - не сбор Trello, а глубокая обработка выбранного P0-направления и превращение его в Blue panel + co2p пакет.
