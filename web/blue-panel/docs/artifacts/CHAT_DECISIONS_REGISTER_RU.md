# Реестр решений и требований из чата

Этот реестр фиксирует рабочие договоренности, чтобы они не терялись между проходами.

## Продуктовая модель

- YouDate — универсальная paid P2P платформа для общения/услуг через платформу.
- YouDate/N / Nebula — первая ниша, рабочее название, эзотерические услуги через текстовый чат.
- YouDate/S и YouDate/D объясняют legacy dating-функции: поиск людей, анкеты, сообщения, роли, модерация, платежи и контент частично универсальны.
- Сначала доводится универсальный функционал платформы, потом делается нишевая эзотерическая упаковка.

## Текущая архитектурная позиция

- Confideline.com / YouDate backend и admin — текущая база реализованного функционала.
- Oracle/Nebula frontend — макеты/лендинг/личный кабинет/чат, которые нужно сверять с backend.
- Из-за риска PHP 8.5/SQL Codex не внедряет backend сам; готовит интерактивные HTML-макеты, ТЗ, co2p пакеты и QA-документы для программиста.

## PM и Blue panel

- Все документы, задачи и описания на русском языке.
- Blue panel — мастер-план и доказательная база для Заказчика/PM, не склад мыслей.
- Главный экран Blue panel показывает мастер-план; стратегия, процесс, зависимости и intake — отдельные вкладки.
- Каждая стратегия должна вести в конкретный шаг мастер-плана или дочерний ресурс.
- Источники должны иметь ссылки и статус: прочитано, извлечено, заблокировано, inference, PM decision.

## Trello

- Trello — месячная доска исполнения для Заказчика и команды.
- В Trello пока ничего не переносить и не менять без команды.
- Карточка Trello: короткий заголовок, развернутая задача, контекст, шаги, ожидаемый результат, оценка времени, результат после выполнения.
- Правая область комментариев Trello является источником; ее читать обязательно.

## P0 для запуска

- P0 = возможность начать полноценную работу с 5 готовыми экспертами и подключить первый трафик после QA.
- Обязательные P0-слои: клиентский путь, эксперт/агент, админка, support/refund, финансы, email/уведомления, переводы, модерация, ranking/visibility, аналитика, QA, legal/trust.
- Нельзя забывать email templates, уведомления, рассылки, платежные письма, support/tickets, языки, модераторские явные/теневые баны, статистику эксперта/агента/админа.

## Обучение и эксперты

- Школа экспертов нужна как отдельный продуктовый модуль.
- На старте можно использовать простую версию: материалы, тесты, ручной допуск.
- У нас уже есть Google Forms/уроки/материалы AskNebula/PbExpert, их нужно найти, извлечь, адаптировать.
- Ксения — ревизор понятности и эзотерического тона, не основной автор методологии.

## Ограничения автономной работы

- Не менять production сайт.
- Не запускать реальные платежи.
- Не отправлять письма/сообщения клиентам.
- Не публиковать внешние материалы.
- Не менять Trello без прямой команды.
- Дергать основателя только по доступам, legal/payment/founder decision blockers.

## План запуска

- Целевой горизонт: сентябрь 2026 — тестовый запуск, октябрь 2026 — боевой запуск при готовности P0.
- Июнь: не только “ТЗ”, а равномерная подготовка и упаковка P0-направлений: email/уведомления, чат в админке, роли/личный кабинет эксперта, обучение, регламент, QA, admin ops, legal package, маркетинг/воронка.
