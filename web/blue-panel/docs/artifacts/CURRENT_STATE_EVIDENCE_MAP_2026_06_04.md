# Карта доказательств текущего состояния проекта
Главный вывод PM: у проекта есть сильная база и много подготовленных пакетов, но готовность к рекламе и первым продажам пока не доказана фактическим сквозным тестом.
Красные зоны: тестовая покупка/консультация, рабочее место эксперта, поддержка/возвраты, юридический approval, аналитика, рекламный запуск.
Желтые зоны: Trello-план, дизайн-сверка, email, школа экспертов, подготовленные handoff-пакеты.
Зеленые зоны: PM-контур, Trello title audit, наличие публичных QA/Blue Panel источников.
- E01. QA / текущий сайт: Красный для запуска, зеленый как источник. Доказано: Есть публичный отчет полного аудита и каталог QA-отчетов. Не хватает: Сквозной тест платной консультации без реального платежа.
- E02. QA / отчеты: Желтый. Доказано: Есть публичный каталог проверок по bans, moderation, messages, auth, email, full audit. Не хватает: Связка каждого отчета с конкретным запусковым условием.
- E03. Trello / июнь: Зеленый. Доказано: Снята история названий 10 карточек списка План на Июнь; исправлено искажение заголовка JUN-07 без служебного кода. Не хватает: Еженедельная сверка изменений и метки обновить.
- E04. Trello / план месяца: Желтый. Доказано: 9 карточек основного июньского плана связаны с Blue Panel; часы распределены на 160. Не хватает: Часть задач требует согласования с Заказчиком и фактического выполнения.
- E05. Перед рекламой: Желтый, методика готова. Доказано: Собрана матрица из 9 условий приемки: клиент, заказ, вопрос, админка, эксперт, уведомления, поддержка, итог, отчет. Не хватает: Фактический проход на сайте и скрины.
- E06. Покупка / консультация: Красный до реализации. Доказано: Описана безопасная модель test order без реального платежа. Не хватает: Рабочая связь order → question → assignment → chat → answer.
- E07. Email / уведомления: Желтый. Доказано: Есть события, шаблоны, переменные, no-send логика и публичный web-контур. Не хватает: Доказательство отправки/логирования событий в полном маршруте без реальных писем.
- E08. Чат / админка: Желтый. Доказано: Есть публичный интерактивный контур по рабочему чату. Не хватает: Доказательство внедрения в backend Confideline и роли эксперта/агента.
- E09. Эксперты / школа: Желтый. Доказано: Найдены материалы обучения, уроки, тесты и места, где доступ закрыт. Не хватает: Полный доступ к закрытым вложениям и заполненный журнал 5 экспертов.
- E10. Эксперты / рабочее место: Красный до runtime proof. Доказано: Описаны роли, задачи, сроки, статусы, качество, начисления и проверка. Не хватает: Фактическая роль в админке и работа с реальной тестовой консультацией.
- E11. Дизайн / фронт: Желтый. Доказано: Есть карта связывания макетов, функций, контента и проверки. Не хватает: Полный screen-by-screen proof по всем экранам Oracle/Nebula.
- E12. Поддержка / возвраты: Красный до runtime proof. Доказано: Описана карточка обращения, статусы, связи с заказом, чатом и решением. Не хватает: Тест проблемного сценария на заказе.
- E13. Юридика / документы: Красный до approval. Доказано: Собраны требования к Terms, Privacy, Refund, дисклеймерам и FAQ. Не хватает: Founder/legal/payment decisions и финальный HTML-ready пакет.
- E14. Маркетинг / трафик: Красный до закрытия условий. Доказано: Есть go/no-go условия, метрики и стоп-сигналы рекламного теста. Не хватает: Оплачиваемый сценарий, поддержка, документы, аналитика и proof.
- E15. Аналитика / экономика: Красный до данных. Доказано: Есть карта событий и логика первых продаж. Не хватает: Фактический отчет test order/source/refund/repeat/quality.
