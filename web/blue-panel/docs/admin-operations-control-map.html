Админка должна доказать управляемость услуги

Для запуска с 5 экспертами не нужен идеальный новый кабинет. Но нужен доказанный операционный маршрут: админ видит заказ, вопрос, исполнителя, SLA, ответ, уведомления, support, качество, начисление и итог без ручного хаоса.

runtime proof = 0admin QA нетпакеты естькарта приемки готова
Главный PM-вывод

Backend Confideline может быть базой, но пока не доказано, что админка управляет платной консультацией как услугой. Нужен один safe order, который проходит через все операционные зоны.

Минимум для MVP

Можно стартовать через admin-based рабочее место по ролям, если закрыты заказ, назначение, SLA, ответ, no-send, support и отчет.

Что меняет статус

Accepted R01 от Игоря и QA-отчет, где админ видит весь маршрут без ручного поиска и догадок.

Что админ должен видеть

A01красный

Единая карточка консультации

Заказ, клиент, вопрос, исполнитель, срок, чат, события, support, начисление и итог в одном route.

Proof: safe order id + admin card.

 A02красный

Очередь новых и зависших заказов

Новые заказы, заказы без вопроса, без назначения, с ошибкой оплаты или ожиданием действия.

Proof: список/фильтр на test order.

 A03красный

Назначение исполнителя

Админ назначает эксперта/агента, видит анкету, язык, нагрузку, доступность и дедлайн.

Proof: assignment на order_id.

 A04красный

Рабочее место исполнителя

Исполнитель видит задачу, вопрос, срок, чат, подсказки, базу знаний и статус ответа.

Proof: скрин под ролью E01.

 A05красный

SLA и просрочки

Видны дедлайн, soon overdue, overdue, escalation, переназначение и последствия.

Proof: deadline/overdue state.

 A06красный

Support и problem states

Жалоба связана с заказом, чатом, исполнителем, причиной, решением и уведомлением.

Proof: support_case_id.

 A07красный

No-send события

Каждый ключевой шаг пишет событие и preview уведомления без реальной отправки.

Proof: event log на одном order_id.

 A08желтый

Качество ответа

Ответ оценивается по сроку, полноте, тону, безопасности, запретам, продажам и жалобам.

Proof: scorecard по E01.

 A09желтый

Модерация и видимость

Warning, hide, visible ban, shadow restriction, boost/freeze и audit log с причиной.

Proof: sanction/visibility route.

 A10желтый

Начисления и удержания

Preview начисления, hold, bonus, deduction, dispute и payout status без реальной выплаты.

Proof: начисление на test order.

 A11красный

Аналитика покупки

Источник, заказ, сумма, валюта, эксперт, support outcome, repeat и итог услуги.

Proof: analytics row.

 A12желтый

Ежедневный итог PM/Admin

Утром и вечером видно: новые, просроченные, проблемные, закрытые, деньги, нагрузка и владельцы.

Proof: daily report после QA-заказа.
Правило: если админ не видит состояние консультации без ручного поиска в разных местах, зона остается красной или желтой. Зеленым ее делает только runtime proof.
