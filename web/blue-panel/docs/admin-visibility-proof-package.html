Админ должен видеть весь путь заказа без ручного поиска

Для запуска с 5 экспертами важна не “красивая админка”, а управляемость: где заказ, кто исполнитель, какой срок, где вопрос, какой ответ, какие события созданы, есть ли жалоба, что с начислением и какой следующий владелец.

runtime proof отсутствуеттребования собранытрафик закрытприемочный пакет готов
PM-решение

Если админ не может утром за 5 минут понять, где деньги, заказы, эксперты и проблемы, сервис нельзя масштабировать. На MVP допустимы ручные действия, но недопустима невидимость.

Что считается доказательством

Один safe/test order проходит весь маршрут, а QA видит скрины/логи админки по заказу, вопросу, назначению, SLA, no-send, support, ответу, закрытию и отчету.

Граница MVP: отдельный красивый кабинет эксперта можно отложить, если текущая админка по ролям закрывает маршрут работы. Но маршрут должен быть доказан.

Как админ управляет днем запуска

УтроНовые заказы, заказы без вопроса, без исполнителя, просрочки, жалобы, события.
ДеньНазначения, ответы, SLA, support, помощь экспертам, качество, ручные решения.
ВечерЗакрытые заказы, зависшие проблемы, начисления, нарушения, отчет PM.
QAТестировщик доказывает, что админ видит путь заказа без догадок.

Что можно принять на MVP, а что нельзя

Допустимо на MVP

Ручное назначение, ручной daily report, ручной support verdict, ручной visibility override, ручной scorecard, если все привязано к заказу и видно в proof.

Недопустимо

Заказ без ответственного, вопрос без заказа, ответ вне платформы, жалоба без связи с заказом, уведомления без no-send, отсутствие дедлайна и невозможность понять статус за 5 минут.
