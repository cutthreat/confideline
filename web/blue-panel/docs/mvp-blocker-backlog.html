Backlog задач, которые снимают блокеры MVP

Это не Trello-доска и не замена карточкам. Это PM-перевод красных и желтых критериев MVP в конкретные задачи с владельцем, приемкой и proof-ссылкой.

Как использовать

Эта страница показывает, что нужно поставить/закрыть в работе. В Trello названия не меняются; при переносе задачи нужно брать человеческий заголовок, постановку, acceptance proof и ссылку на Blue Panel.

Главная граница

Задача считается закрытой не по обещанию, а по proof: скрин, лог, QA-отчет, заполненный журнал или опубликованный пакет.

5задач готовятся параллельно
13задач в backlog
1главная цель: QA verdict
Приоритет: P1 закрывает контрольный заказ и MVP-красные критерии. P2 готовит оффер, экспертов, документы и экраны. P3 готовит первый трафик, но не запускает его.

Задачи backlog

BLK01Показать безопасный тестовый заказ без реального списанияP1 · ИгорьЗадача: Подтвердить или внедрить test/sandbox/mock режим заказа, где создается order id, но нет боевого списания.Приемка: Есть order id, сумма, валюта, статус test/sandbox/mock, подтверждение отсутствия реального списания. BLK02Связать вопрос клиента с заказом и сессиейP1 · ИгорьЗадача: Сделать/показать связку order -> question -> consultation/session -> task/assignment.Приемка: Один order/session/question id виден клиенту, админу и исполнителю. BLK03Показать рабочее место исполнителя на тестовом заказеP1 · Игорь + QAЗадача: Показать, что эксперт/агент видит задачу, срок, вопрос клиента, контекст, чат/ответ и статус после ответа.Приемка: Скрин workspace и proof ответа исполнителя по тестовому заказу. BLK04Показать админскую видимость всего заказаP1 · Игорь + PMЗадача: Показать один заказ в админке по всем зонам: order, question, session, assignment, chat, events, support.Приемка: Набор скринов admin route без ручного поиска и догадок. BLK05Проверить уведомления в no-send режимеP1 · Игорь + QAЗадача: Включить/показать журнал событий без реальной отправки писем по заказу, вопросу, назначению, дедлайну, ответу, support и follow-up.Приемка: No-send event log и preview без фактической отправки. BLK06Проверить один problem state через supportP1 · Игорь + QA + PMЗадача: Смоделировать просрочку или недовольство клиента и связать обращение с order/session/chat/expert.Приемка: Support case имеет статус, решение, связь с заказом и событие. BLK07Допустить первых 5 экспертов по единому журналуP1 · PM + КсенияЗадача: По каждому эксперту заполнить тест/пробный ответ, оценку качества, SLA и решение допуска.Приемка: 5 строк журнала имеют статус готов/доработка/не допущен и причину. BLK08Получить QA verdict по контрольному заказуP1 · QA + PMЗадача: После READY gate пройти контрольный заказ и опубликовать QA report со скринами и verdict PASS/WARN/STOP.Приемка: Публичный QA report с итогом и списком дефектов/решений. BLK09Оформить понятный оффер и состав услуги до оплатыP2 · PM + основательЗадача: Собрать цену, формат результата, срок ответа, ограничения, FAQ и дисклеймер для checkout/LP.Приемка: Клиент до оплаты понимает, что покупает, когда получит и какие есть ограничения. BLK10Проверить регламент эксперта на пробном ответеP2 · PM + КсенияЗадача: Взять один пробный ответ и оценить его по регламенту: тон, качество, продажи, запреты, SLA, escalation.Приемка: Есть пример оценки и список правок в регламент/обучение. BLK11Закрыть экранные контракты платной воронкиP2 · PM + Антон + ИгорьЗадача: Для offer, checkout, question, waiting/chat, answer/result, support, profile связать экран, backend, текст, ошибки и QA.Приемка: По каждому ключевому экрану есть статус экран/backend/content/QA. BLK12Подготовить HTML-ready документы и дисклеймерыP2 · PM + founder/legalЗадача: Собрать Terms, Privacy, Disclaimer, Refund/FAQ и места показа с переменными для сайта.Приемка: Пакет готов к ревизии, но помечен как не финальный до legal/payment решений. BLK13Подготовить go/no-go первого трафикаP3 · PM + основательЗадача: Сформировать условия запуска первого трафика: QA verdict, capacity, legal/payment, support readiness, stop-сигналы, CAC/LTV поля.Приемка: Есть decision sheet: запускать/не запускать/запускать с ограничениями.
