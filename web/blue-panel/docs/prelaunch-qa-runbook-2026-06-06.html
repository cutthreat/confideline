QA не стартует сейчас. Эта страница фиксирует, что именно будет проверяться после READY: один безопасный заказ, связанный вопрос, исполнитель, ответ, уведомления без отправки, support, админка, аналитика и публичный отчет PASS/WARN/STOP.

PM-решение

Тестировщик не должен “просто пройти сайт”. Он должен собрать доказательства по QAR01-QAR14. Только публичный отчет с proof может изменить светофор запуска.

До QA должны быть accepted: BA01-BA08 минимум, E01 accepted for QA, fixture sheet, no-send safety и admin route.

Готовый текст задачи QA

Задача: пройти один контрольный заказ Nebula/YouDate-N после READY gate и опубликовать доказательный отчет. До старта проверить: есть safe order/no-charge marker, E01 accepted, admin route, workspace исполнителя, no-send режим, support context. Что пройти: 1. Оффер, CTA, документы и disclaimer до оплаты. 2. Safe checkout/test order без реального платежа. 3. Вопрос клиента и связь с order_id/session. 4. Назначение эксперта/анкеты и SLA. 5. Рабочее место эксперта и отправка тестового ответа. 6. Видимость ответа у клиента и админа. 7. No-send события и preview без реальной отправки. 8. Support/problem case по заказу. 9. Admin timeline и daily visibility. 10. Минимальные analytics поля source/session/order/value. 11. Failure states и понятные recovery actions. Результат: публичный QA-отчет с URL, скринами, ID, event logs, support_case_id, defects, owners и verdict PASS/WARN/STOP. STOP: реальный платеж, реальная отправка, нет order/question binding, нет исполнителя, нет admin visibility, нет support owner, нет публичного отчета.
