Связать sandbox checkout с тестовой консультацией

Платежная песочница уже доказана. Теперь нужно закрыть главный продуктовый разрыв: после fake success должен появиться не только завершенный платеж/баланс, а рабочая консультация с вопросом, админской видимостью, назначением эксперта, чатом, событиями и поддержкой.

payment sandbox PASSsandbox hook найден в sourceconsultation runtime RED
PM-решение

Игорю нужно передавать не “сделать оплату”, а конкретную связку: fake payment success → order → question → consultation → expert/agent task → chat → no-send events → support.

Ограничения

Только local/test. Не production, не реальные Stripe keys, не реальные карты, не реальные письма.

Целевой вариант требует подтверждения

`Chat/README.md` говорит, что в `Confideline/Chat` несколько вариантов и нет единого canonical source по умолчанию.

Sandbox hook в BalanceController есть

`actionStripeCreateSession()` уже возвращает `checkoutUrl`, если задан `CONFIDELINE_STRIPE_API_BASE`.

Sandbox hook в StripeCheckout есть

`configureStripe()` уже переопределяет `Stripe::$apiBase` через env.

Success сейчас закрывает credits

`successPayment()` увеличивает баланс и переводит `Order` в `COMPLETED`, но консультация этим не доказана.

Ключевой вывод: найденная кодовая база уже частично подготовлена к sandbox. Но бизнес-цель Nebula не “пополнить кредиты”, а “купить консультацию и получить ответ”. Поэтому нужно доказать или добавить доменную связку консультации после оплаты.

Acceptance criteria

Оплата

Fake checkout открывается через `checkoutUrl`; реальные деньги и Stripe не используются.

Заказ

После fake success order виден в админке как completed/test.

Консультация

Есть рабочая сущность консультации, связанная с order и вопросом клиента.

Исполнитель

Эксперт/агент получает задачу, срок, контекст и чат.

События

События фиксируются как no-send; реальные письма не уходят.

Проблемы

Cancel/fail/refund/support видны как problem states и не создают ложную продажу.
