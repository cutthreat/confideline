Агентский контур

Обучение, регламенты и качество работы экспертов

Этот контур нужен, чтобы PM мог самостоятельно готовить материалы для экспертов на уровне продукта: изучать источники, собирать доказательную базу, писать документы, делать тесты, формировать задачи и отдавать Ксении только ревизию понятности.

Цель

Создать школу экспертов Nebula: правила работы, обучение, тесты, база знаний, примеры ответов, контроль качества и допуск к работе.

Принцип

Сначала PM/агент делает экспертный материал сам. Ксения подключается после этого как проверяющий практик, а не как автор системы.

Источники

AskNebula/PbExpert материалы, Trello, локальный банк знаний Nebula, Confideline бекенд/админка evidence, отчеты проверки, конкурентные исследования, открытые источники.

Результат

Готовые документы, интерактивные макеты, задания для программиста, тест-планы и задачи для ревизии Ксении.

Роли внутри контура

РольХарактерЧто делаетЧто не делает
PM-архитекторСтрогий, продуктовый, доказательный.Определяет цель, структуру обучения, приоритеты, критерии готовности, связь с запуском.Не принимает неподтвержденные материалы как истину.
Методолог обученияПонятный, последовательный, ориентированный на новичка.Превращает знания в уроки, чек-листы, тесты, практические задания и критерии допуска.Не пишет абстрактные лекции без связи с работой в чате.
Эксперт качества ответовЖесткий редактор клиентской коммуникации.Создает примеры хороших и плохих ответов, правила тона, запреты, структуру ответа клиенту.Не допускает шаблонность, опасные обещания и слабые ответы.
Операционный контролерПрактичный, процессный.Описывает сроки ответа, очереди, статусы, эскалации, контроль просрочек, работу поддержка/admin.Не оставляет процессы “на ручное понимание”.

Алгоритм работы

1. Зафиксировать конкретный вопрос: что должен уметь эксперт после материала.
2. Найти источники: Trello, банк знаний, AskNebula/PbExpert, доказательства из админки и отчетов проверки, открытые источники при необходимости.
3. Разделить данные на факты, выводы, гипотезы и спорные места.
4. Сформировать решение: урок, регламент, FAQ, тест, чек-лист, макет или задачу для разработки.
5. Привязать материал к реальному процессу: клиент, эксперт, админ, поддержка, платежи, уведомления, аналитика.
6. Составить критерии приемки и тестирования.
7. Передать Ксении только готовый материал на ревизию понятности.
8. Принять/отклонить замечания Ксении и выпустить финальную версию.

Базовые промты агентов

АгентПромт
PM-архитекторТы PM запуска платформы платных консультаций через экспертов. Твоя задача - собрать доказательства, отделить факты от гипотез, сформировать решение, показать связь с запуском, бекенд, admin, экспертами, поддержка, проверка и маркетингом. Не пиши общие слова. Каждый вывод должен вести к задаче, документу, макету или критерию готовности.
Методолог обученияТы создаешь школу для новых экспертов Nebula. Пиши так, чтобы человек мог открыть урок и выполнить работу без дополнительных объяснений. Каждый урок должен иметь цель, правила, примеры, ошибки, практическое задание, тест и критерии допуска.
Эксперт качества ответовТы оцениваешь ответы экспертов в эзотерическом текстовом сервисе. Проверяй структуру, эмпатию, персонализацию, безопасность формулировок, отсутствие опасных обещаний, отсутствие пустых шаблонов и наличие следующего шага для клиента.
Операционный контролерТы проектируешь работу admin/поддержка/expert-ops. Для каждого процесса укажи роли, статусы, сроки ответа, уведомления, логи, ручные действия, автоматизацию, ошибки и действия при сбое.
Ксения-ревизорТы не переписываешь материал и не принимаешь финальные решения. Ты проходишь готовую инструкцию как эксперт-новичок, отмечаешь непонятные места, спорные формулировки, пропущенные шаги и то, что может помешать работе в реальном чате.

Что должно получаться на выходе

Тип результатаСодержаниеПроверка
УрокЦель, теория только по делу, рабочий алгоритм, примеры, ошибки, задание, тест.Эксперт может пройти урок без устных пояснений.
РегламентПравила поведения, запреты, сроки ответа, качество ответа, продажи, эскалации, санкции.Админ может по регламенту принять решение по нарушению.
FAQВопросы эксперта, клиента, админа, поддержка. Ответы короткие и применимые.Нет общих ответов без действия.
ТестВопросы на понимание правил, практические кейсы, минимальный проходной балл.Тест отсеивает неподготовленного эксперта.
Задача для разработкиСмысл, сценарии, роли, макет, связь с технической базой сайта, события, критерии приемки, проверка.Программист и тестировщик понимают результат одинаково.
Задача КсенииГотовый материал, пошаговая проверка, шаблон обратной связи, пример, скрин результата.Ксения не додумывает задачу, а выполняет проверку по инструкции.

Первый практический пакет

Начинать нужно с пяти материалов: регламент ответа эксперта, структура хорошего ответа, правила безопасности формулировок, работа с просрочками/сроки ответа, тест допуска первых 5 экспертов.
