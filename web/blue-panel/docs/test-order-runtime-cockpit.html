Пульт первого контрольного заказа

Это центральный рабочий вход для перехода от документов к фактам. Один заказ должен доказать: клиент оформляет тестовую услугу, вопрос связан с заказом, исполнитель отвечает, админ видит путь, уведомления пишутся без отправки, support обрабатывает проблему.

QA пока не стартуетреклама запрещенанужно закрыть gateцель: один доказанный заказ
Текущий PM-вердикт

Контрольный заказ пока нельзя считать готовым к runtime QA: не доказаны безопасный checkout, no-send, связка order/question/session, рабочее место исполнителя и admin visibility.

Граница безопасности

Никаких реальных списаний, реальных писем, внешней рекламы и production-изменений без отдельного решения.

Главное правило: “пакет собран” не меняет светофор. Светофор меняет только runtime proof: скрин/лог/order id/session id/event log/QA-report.

Кто что делает

PMДержит scope, готовит фикстуры, не дает уходить в маркетинг до proof.
ИгорьПоказывает безопасный тестовый заказ, no-send, order-question-session, assignment, workspace, support и event log.
QAПроходит маршрут только после READY и публикует PASS/WARN/STOP с evidence.
Эксперт/агентПолучает тестовую задачу, отвечает по регламенту, без общения с реальным клиентом.
