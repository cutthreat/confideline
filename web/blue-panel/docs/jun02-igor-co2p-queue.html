JUN-02 · co2p

Очередь пакетов для Игоря

Из 10 старых Trello-ТЗ выделены только те блоки, которые реально нужны для запуска Nebula или ближайшего стабильного контура платформы. Email не дублируется: он уже закрыт отдельным пакетом.

Что закрывает

Закрывает checklist-пункт “Сформировать пакеты задач для передачи Игорю” в карточке “Прогнать все макеты готовых ТЗ через Codex”.

Правило

Это очередь подготовки co2p-пакетов, а не команда Игорю немедленно внедрять все шесть блоков.

6пакетов в очереди
3критичны до рекламы
2можно после service_session
1P1 после MVP

Пакеты

P1

Поддержка и проблемные ситуации

Без поддержки нельзя покупать трафик: клиент может не получить ответ, оплатить ошибочно, запросить возврат или пожаловаться.

Backend
ticket/support_case, связь с payment/order/service_session, статус, SLA, причина, refund review.
Frontend
Кнопки “нужна помощь”, причины обращения, статус обращения, понятные тексты.
Admin
Очередь обращений, история клиента, связь с консультацией, эскалация, решение.
QA
Создать обращение по оплате, нет ответа, плохой ответ, refund; проверить статусы.

Нужен co2p-пакет Игорю

P2

Модерация контактов и запретов в чате

Защищает платформу от ухода клиента/эксперта в обход оплаты и от нарушений правил.

Backend
Фильтр контактов, лог срабатываний, ручные исключения, санкции, теневой/явный бан.
Frontend
Мягкое предупреждение в чате без раскрытия правил обхода.
Admin
Журнал нарушений, карточка нарушителя, ручная санкция или снятие.
QA
Проверить email/phone/social patterns, false positives, историю нарушений.

Нужен co2p-пакет Игорю

P3

Рейтинг, отзывы и поднятие экспертов

Определяет доверие клиента и порядок экспертов в списке; влияет на конверсию и качество.

Backend
review, rating, completed_session only, moderation status, ranking score.
Frontend
Рейтинг, отзывы, бейджи, количество консультаций, сортировка.
Admin
Модерация отзывов, ручная корректировка, visibility boost, антифрод.
QA
Оставить отзыв после завершенной консультации, скрыть/одобрить, проверить сортировку.

MVP-упрощение, затем P1

P4

Аналитика событий запуска

Без событий нельзя понять CAC/LTV, SLA экспертов, возвраты и готовность к масштабированию.

Backend
events: visit, signup, paid_order, assigned, first_response, completed, refund, repeat.
Frontend
Не требуется для клиента; нужны события на фронте.
Admin
Дашборд продаж, SLA, экспертская нагрузка, refund, repeat.
QA
Проверить фиксацию событий на тестовом заказе без реальных денег.

После service_session, но готовить сейчас

P5

Диалоговые окна платной воронки

Модалки влияют на оплату, подтверждение, ошибки, доверие и поддержку.

Backend
Зависит от действия: payment, confirm, support, moderation, refund.
Frontend
Единый стиль Oracle/Nebula, ясный CTA, fallback, empty/error states.
Admin
Если действие создает событие, нужен лог в admin/support.
QA
Проверить payment modal, error modal, support modal, contact block modal.

Связать с Антоном и Игорем

P6

Переводчик и языки в чате

Не блокер англоязычного MVP, но нужен для разных языков клиента и эксперта.

Backend
Оригинал/перевод, язык, provider, стоимость, retry, privacy.
Frontend
Переключатель оригинал/перевод, пометка AI translation.
Admin
Настройки языков, лимиты, журнал ошибок.
QA
Проверить два языка, сохранение оригинала, отказ provider.

P1 после MVP или минимальный ручной режим
