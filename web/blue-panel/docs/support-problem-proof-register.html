PF09 · support runtime proof · 05.06.2026

Проблема клиента должна быть видна и управляемая в одном месте

Этот реестр переводит support/refund в проверку контрольного заказа. QA должен доказать не “у нас есть поддержка”, а что конкретная проблема связана с заказом, чатом, исполнителем, событиями, решением и последствиями.

runtime proof сейчас 0support блокирует трафикPF09 чек-лист готов
Решение PM

Для первого запуска достаточно не всех возвратных правил, а одного доказанного support problem state на контрольном заказе. Если support не видит контекст без ручного поиска, слой остается красным.

Безопасная граница

Реальные возвраты, списания и письма не делаем. Принимаем только test-mode статусы, no-send preview, screen proof и QA verdict.

0доказанных support runtime cases
8problem states в реестре
1минимум должен пройти в PF09
5связей обязательны: order, session, chat, expert, events
Главный критерий: support-сценарий считается готовым только если из карточки обращения видно клиента, заказ, вопрос, чат, исполнителя, события/уведомления, платежный/test status, решение, владельца и следующий шаг.
