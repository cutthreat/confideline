1
ИгорьBackend/admin · отправить сейчаскрасный блокер
пакет заказаадминкаno-send
Что попросить

Показать один безопасный контрольный заказ без реальной оплаты и без реальной отправки писем: заказ, вопрос клиента, назначение исполнителя, рабочее место, ответ, события, support case.

Игорь, нужно показать безопасный тестовый маршрут платной консультации. Важно: без реального списания и без реальных писем. Верни order id, question/session/task id, performer/profile id, answer id, event/no-send log, support case id, скрины админки и рабочего места.
Примем если

Есть ID, скрины, admin route, no-send marker, support route и подтверждение test/no real charge/no real send.

Вернем если

Нет связи заказа с вопросом, есть только устный ответ, один скрин без ID или есть риск реального платежа/письма.

Ксения + первый экспертЭкспертный контур · отправить сейчаскрасный блокер
5 экспертовшколарегламент
Что попросить

Закрыть минимум E01 для контрольного заказа: эксперт понимает регламент, SLA, формат ответа, имеет пробный ответ, оценку качества, доступ/анкету и готовность работать в тесте.

Ксения, задача не писать методологию, а проверить готовность первого эксперта как ревизор. Нужны: кто E01, какая анкета/язык, SLA, пробный ответ на тестовый кейс, замечания по понятности материалов, вердикт: допущен / мелкие правки / не допущен.
Примем если

Есть строка допуска E01, пробный ответ, scorecard, SLA, доступ/анкета и конкретный вердикт.

Вернем если

“Эксперт готов” без примера ответа, без SLA, без оценки или с общими замечаниями без привязки к материалу.

Проверить платную воронку в дизайне: оффер, выбор/профиль, checkout, вопрос, ожидание ответа, чат/ответ, support, FAQ, ошибки и возврат клиента.

Антон, нужно сверить Nebula/Oracle макеты с рабочим сценарием платной консультации. По каждому ключевому экрану верни: ссылка/скрин, что делает пользователь, какие состояния ошибки есть, где нужен backend/action или текст.
Примем если

Вернем если

Экран красивый, но неясно, что пользователь делает, что видит при ошибке и что должен поддержать backend.

QA / тестировщикНе отправлять до READYждет готовности
QAзаказsupport
Что будет после READY

Пройти путь клиента, админа, исполнителя и support. Итог должен быть публичным QA-отчетом PASS/WARN/STOP со скринами и order id.

QA-задачу отправлять только после READY: safe order route, E01, no-send, admin route и support route. После READY тестировщик проходит контрольный заказ и возвращает PASS/WARN/STOP отчет.
Примем если

Есть отчет со скринами, ID, дефектами, severity, воспроизводимостью и итоговым вердиктом.

Вернем если

Есть чеклист без скринов, нет order id или отчет не показывает путь клиента/эксперта/admin/support.
