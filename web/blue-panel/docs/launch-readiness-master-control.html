Готовность запуска Nebula / YouDate

Одна верхнеуровневая карта после прохода PM по backend, frontend, экспертам, админке, support, уведомлениям, маркетингу и QA. Здесь видно, почему запуск клиентов пока запрещен и что конкретно закрывать дальше.

боевой запуск нельзя трафик нельзя подготовку вести можно
Решение PM

Проект имеет сильную базу и много готовых PM/co2p-пакетов, но запуск не доказан runtime. Главный следующий шаг — один test order без реального списания, который проходит путь от оффера до ответа, support, no-send уведомлений, админ-контроля и QA PASS/WARN/STOP.

14слоев запуска
8красных блокеров
5частично готово
1можно опираться
Практическое решение: не расширять список функций хаотично. Закрывать красный маршрут: test order → вопрос → назначение → ответ → события/no-send → support/refund → админка → QA proof → только потом малый трафик.

Красный маршрут закрытия

1. Test orderЗаказ без реального списания, вопрос клиента, статус и карточка консультации.
2. ЭкспертНазначение, SLA, рабочее место, ответ в чате, качество ответа.
3. АдминкаОперационная очередь, статусы, дедлайны, события, начисления.
4. УведомленияNo-send preview по заказу, вопросу, назначению, ответу и проблемам.
5. SupportПроблемный сценарий: просрочка, плохой ответ или payment issue.
6. QAPASS/WARN/STOP отчет со скринами и выводом: можно ли идти к малому трафику.
