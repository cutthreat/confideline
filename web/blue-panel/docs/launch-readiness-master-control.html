Запуск пока красный: нет доказанного контрольного заказа

Проект хорошо собран как стратегия, план, задачи и пакеты передачи. Но клиентов, рекламу, реальные платежи и реальные письма нельзя запускать, пока не пройден один полный контрольный заказ с QA-отчетом.

Решение PM

Не считать документы и ТЗ готовностью запуска. Сначала доказать один путь услуги: заказ, вопрос, исполнитель, ответ, события, support, QA. После этого обновлять статусы и решать вопрос первого трафика.

Правило светофора

Зеленый = можно опираться. Желтый = база или пакет есть, нужна ревизия/внедрение/проверка. Красный = блокирует запуск клиентов и рекламы.

2слоя можно считать основой
6слоев частично готовы
8слоев блокируют запуск
0контрольных заказов с QA-отчетом

Главная граница: “пакет готов” не равно “можно запускать”. Для запуска нужен хотя бы один контрольный заказ без реального списания и писем, плюс QA-отчет с решением “можно / можно с замечаниями / нельзя”.

Как QA-отчет пересчитывает запуск

PM-правило: светофор запуска меняется только после публичного QA-отчета по PF01-PF12. Документы, ТЗ, скрины отдельных экранов и устное “работает” не меняют статус.

Почему запуск все еще красный, хотя источники дособраны

Разделение уровней: Google-исследования, дизайн-источники, Trello snapshot и runtime contract теперь оформлены как proof. Но запуск меняется только после факта: безопасный контрольный заказ, no-send timeline, support-case и QA PASS/WARN/STOP.
