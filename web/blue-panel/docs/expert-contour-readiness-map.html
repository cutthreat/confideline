Первые 5 экспертов пока не готовы к трафику

Материалы, школа и регламент есть как база. Но запусковый proof отсутствует: 0/5 экспертов допущены, E01 не подтвержден для QA, рабочий доступ и ответ на safe order не доказаны.

0/5 acceptedcapacity трафика = 0школа v1 естьE01 нужен для QA
Главный PM-вывод

Наличие “5 готовых экспертов” не считается proof. Каждый должен иметь обучение, пробный ответ, SLA, профиль/анкету, рабочий доступ и PM verdict.

Что меняет статус

R02: E01 accepted для QA. Для первого трафика: E01-E05 accepted или явный capacity-limit с ограниченным запуском.

Роль Ксении

Ксения проверяет понятность и реалистичность материалов как ревизор. Архитектуру, методологию и финальный допуск держит PM.

Зоны экспертского контура

EX01желтый

Школа экспертов v1

Есть минимальная структура обучения: правила, примеры, практика, тест и ручной допуск.

Не доказано: прохождение конкретными E01-E05.

 EX02желтый

Материалы AskNebula/PbExpert

Исходные материалы собраны как сырье для нашей школы и регламента.

Не доказано: все источники доступны и адаптированы.

 EX03желтый

Регламент работы

Есть v1 по срокам, тону, качеству, запретам, эскалациям и санкциям.

Не доказано: эксперт понял и применил регламент.

 EX04красный

Допуск E01-E05

Нужен journal: обучение, пробный ответ, SLA, анкета, доступ, verdict.

Proof: E01 accepted для QA, E01-E05 для трафика.

 EX05красный

Пробный ответ и качество

Каждый эксперт должен дать ответ по единому тестовому вопросу.

Proof: scorecard accepted / returned / blocked.

 EX06красный

Рабочее место

Эксперт видит задачу, вопрос, SLA, чат, подсказки и может ответить.

Proof: runtime screen под ролью E01.

 EX07красный

Назначение и ответ

Order должен перейти в assignment, задача - к эксперту, ответ - клиенту.

Proof: order_id → assignment → answer_id.

 EX08красный

SLA и доступность

Нужно знать часы работы, срок ответа, лимит заказов и backup.

Proof: availability + deadline на test order.

 EX09желтый

Рейтинг и видимость

Сильные эксперты должны быть выше; слабые ограничиваются или уходят на обучение.

Нужно: P0 формула и admin override.

 EX10красный

Жалобы и последствия

Плохой ответ или просрочка должны влиять на quality, visibility и начисление.

Proof: support case на order_id.

 EX11желтый

Начисления

Эксперт должен видеть, за что начислено, что удержано и почему.

Proof: preview начисления на test order.

 EX12желтый

Переход к классическому набору

Bootstrap 5 экспертов не должен ломать будущую публичную систему набора.

Позже: expert application/admission pipeline.
Правило: capacity для трафика считается нулевой, пока нет accepted E01-E05 или явного решения запускать ограниченный тест с меньшим числом экспертов.
