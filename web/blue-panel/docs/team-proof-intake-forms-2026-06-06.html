Формы приема ответов команды

Эта страница нужна в момент, когда команда возвращает результат. PM не принимает “готово” словами: ответ должен закрывать обязательные поля, иметь носитель доказательства и завершаться вердиктом.

Главное правило

Если обязательного поля нет, статус запуска не меняется.

Три решения PM

Принято, вернуть на доработку или заблокировано. Без одного из этих решений proof не существует.

Быстрая логика приемки

Принято
  • Есть ID или ссылка на объект.
  • Есть скрин/лог/страница/файл.
  • Понятно, какой gate закрыт.
  • Есть следующий шаг или отметка “не нужен”.
Вернуть
  • Нет ID, связи или носителя proof.
  • Скрин без контекста.
  • Ответ не покрывает запрос.
  • Нужно доуточнить без остановки проекта.
Заблокировано
  • Функции нет или route невозможен.
  • Нужен доступ/решение владельца.
  • Есть риск real payment/send.
  • QA нельзя запускать безопасно.

Шаблоны по ролям

1

Ответ Игоря по контрольному заказу

Нужен для перехода QA gate из STOP в READY по backend/admin части.
обязателен
Обязательные поля
  • test_run_id / дата теста.
  • order_id, question_id, session/task_id.
  • performer/profile_id, answer_id.
  • event/no-send log id.
  • support_case_id или proof, что support route создан.
  • Скрины админки и рабочего места.
  • Подтверждение: no real charge / no real send.
Что меняет
  • Может открыть READY-проверку QA.
  • Может закрыть часть admin visibility.
  • Может показать конкретный backend-блокер.
  • Не открывает рекламу без QA и E01-E05.

2

Ответ Ксении по E01

Нужен минимум один допущенный исполнитель для контрольного заказа; пять — до первого трафика.
обязателен
Обязательные поля
  • Кто E01 и какая анкета.
  • Язык, график, SLA.
  • Пробный ответ на тестовый кейс.
  • Scorecard качества ответа.
  • Что в материалах непонятно.
  • Доступ/роль/готовность к тесту.
  • Вердикт: допущен / мелкие правки / не допущен.
Что меняет
  • Может разрешить использовать E01 в QA.
  • Не закрывает capacity до всех 5 экспертов.
  • Если не допущен — QA остается STOP.
  • Комментарии Ксении не заменяют PM-методологию.

3

Ответ Антона по экрану/воронке

Нужен для сверки frontend design с реальным backend/action и контентом.
параллельно
Обязательные поля
  • Ссылка/скрин экрана.
  • Что делает пользователь.
  • Какой backend/action нужен.
  • Какие состояния ошибки есть.
  • Какой текст/FAQ/disclaimer нужен.
  • Что еще не решено.
Что меняет
  • Обновляет screen/backend/content matrix.
  • Дает Игорю понятную связку frontend → backend.
  • Не открывает трафик без runtime proof.
  • Красивый макет без сценария не принимается.

4

Ответ QA после READY

QA не запускается сейчас. Эта форма нужна после safe order, E01, no-send, admin и support route.
после READY
Обязательные поля
  • Ссылка на публичный QA-отчет.
  • test_run_id и order_id.
  • Путь клиента, админа, исполнителя, support.
  • Скрины и дефекты.
  • Severity и воспроизводимость.
  • Итог PASS / WARN / STOP.
Что меняет
  • PASS/WARN пересчитывает launch readiness.
  • STOP возвращает конкретные дефекты владельцу.
  • Не заменяет legal/payment решения.
  • Без скринов и ID отчет не принимается.
