Главное правило

Мы принимаем не “экран” и не “модель”, а доказанный маршрут первой платной консультации в безопасном тестовом режиме.

До выполнения: трафик, реальные платежи, реальные письма и финальный запуск запрещены.

Маршрут, который нужно доказать

1. КлиентСоздает тестовый заказ услуги без реального списания.
2. ЗаказВ заказе есть вопрос, сумма, валюта, услуга, язык и test marker.
3. АдминкаАдмин видит заказ, статус, срок, исполнителя, чат и проблему.
4. ЭкспертИсполнитель получает задачу, отвечает, ответ виден клиенту и админу.
5. КонтрольУведомления, support, качество и QA фиксируются без риска для реальных клиентов.

Как будет приниматься результат

Accepted

Все ключевые шаги показаны на одном тестовом заказе. Есть номера, скрины/логи, no-send подтверждение, support case и QA понимает, что проходить.

Returned

Есть отдельные экраны, но нет сквозной связи. Нет test marker. Нет вопроса в заказе. Нет executor workspace. Нет no-send. Нельзя запускать QA.

PM-вывод: если Игорь закрывает этот пакет, мы не считаем проект запущенным, но снимаем главный технический STOP для pre-launch QA. После QA уже обновляем светофор запуска по фактам.
