Контрольный заказ · ожидаемый сценарий

Один таймлайн для Игоря, QA и PM

Эта страница собирает в один путь то, что раньше было разнесено по страницам: тестовый заказ, вопрос клиента, назначение исполнителя, рабочее место, ответ, no-send события, проблемный кейс support и итоговый QA-отчет.

runtime не доказансценарий готов для передачиреальные письма и платежи запрещены
PM-решение

QA должен проверять не отдельные экраны, а один связанный заказ. Если хотя бы один критичный шаг не имеет ID, скрина или лога, статус запуска не меняется.

Что это дает

Игорь видит expected backend/admin результат, QA видит порядок прохождения, PM видит какие факты принимать в proof-inbox.

10шагов одного контрольного заказа
0шагов доказано runtime-фактами сейчас
1support problem state включен в сценарий
STOPесли ушло реальное письмо или списание
Безопасность: этот сценарий выполняется только в safe/test/no-send режиме. Нельзя запускать реальные платежи, реальные письма или реальные сообщения клиентам.
