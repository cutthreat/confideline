Карта готовности страниц, контента и backend-связей

Эта карта соединяет дизайн Oracle/Nebula, текущий backend Confideline, публичные документы, контент и QA. Страница или экран не считается готовым, если есть только макет или только backend. Для запуска нужен один проверяемый сценарий: что видит человек, какое действие делает, какая сущность появляется в backend, какой текст он читает и как QA это доказывает.

PM-решение

До первого трафика нельзя оценивать готовность “по внешнему виду”. Каждая страница должна иметь контракт: экран, backend, контент, ошибка, аналитика и proof.

Главный блокер

Сейчас большинство сценариев красные не потому, что “ничего нет”, а потому что нет принятого runtime proof на safe control order.

Правило готовности: зеленый статус возможен только когда есть доказательство связки “экран → действие → backend entity → текст/условие → failure state → QA proof”. Макет без backend или backend без понятного экрана остается желтым/красным.
