Frontend / Oracle-Nebula / backend-content gate

Макет считается готовым только если связан с backend, текстом и QA-состояниями

Для запуска недостаточно иметь красивый экран в Oracle/Nebula. Каждый критичный экран должен иметь назначение в клиентском пути, backend-связь в Confideline, контент/FAQ/дисклеймеры и проверяемые состояния ошибок.

дизайн и карты естьruntime-связь не доказанатрафик запрещен до QA
PM-решение

Frontend/design слой остается желтым: макеты и карты собраны, но запусковый PASS появится только после связки ключевых экранов с backend и runtime proof.

Критерий

Экран считается готовым не по Figma, а по цепочке: макет → верстка/страница → backend route/action → контент → error/empty states → QA screenshot.

Go/no-go правило

STOP: если любой критичный экран ведет в dead-end, не связан с backend-сущностью, не имеет понятного текста или не дает support/action при ошибке, трафик запрещен.
Минимальный PASS: landing → package → checkout/test order → question → success/status → expert workspace → answer → client view → support case подтверждены скринами и связаны с order id.
