Дизайн-источники существуют, но это еще не готовность запуска

Задача PM здесь — отделить факт наличия Figma/экспортов/верстки от факта готовности коммерческого пути. Локальный контур сильный, но каждый P0-экран должен пройти screen contract: источник → страница → backend/admin → контент → ошибки → QA.

Главный PM-вывод

SRC13 больше не красный “нет данных”. Данные есть. Статус должен быть желтым: источники дизайна найдены, но запуск блокирует отсутствие screen-by-screen acceptance и runtime-связки с paid consultation.

Правило для задач Антону и Игорю

Нельзя ставить “сделать как в макете”. Нужно ставить экранный контракт: какой экран, какая функция, какой контент, какие ошибки и чем проверяем.

Как теперь использовать дизайн-контур

1. Для Заказчика: показываем не “все макеты есть”, а что по каждому важному сценарию есть источник, статус и следующий шаг.
2. Для Антона: правки по макетам формулируются через клиентский сценарий и экранный контракт, а не через субъективный визуальный вкус.
3. Для Игоря: frontend-задача передается только вместе с backend dependency: заказ, вопрос, чат, support, уведомления, админская видимость.
4. Для QA: приемка страницы должна проверять действие пользователя и failure state, а не только совпадение картинки.
