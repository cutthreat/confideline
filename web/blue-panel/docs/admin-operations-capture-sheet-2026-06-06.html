Лист приема админского операционного контура

Заполняется на одном safe test order и проблемном сценарии. Цель — доказать, что админка управляет консультацией как процессом: заказ, вопрос, исполнитель, SLA, чат, события, support, качество, санкции, начисления, аналитика и daily control видны без ручного хаоса.

admin runtime proof = 0трафик запрещен без visibilitybackend-кирпичи естьлист приема готов
Что принимается как proof

Скрины/ссылки на admin route, где видны order_id, client_id, question_id, performer/profile_id, SLA, event_id, support_case_id, quality decision, moderation action, payout preview и daily status.

STOP-сигналы

Админ ищет данные вручную по разным местам; нет order lifecycle; нет владельца проблемы; нет SLA; нет no-send log; нет audit trail по модерации; QA не может повторить проверку.

PM-правило: для первых 5 экспертов допустим admin-based кабинет по ролям, но только если он закрывает весь путь консультации и дает QA proof.

Правила приемки

PASS

AOC01-AOC07, AOC14 и AOC15 доказаны на safe order; AOC08-AOC13 имеют минимум рабочий manual/admin proof и понятные owners. Можно переходить к ограниченному QA/traffic после остальных gates.

WARN

Основной жизненный цикл заказа виден, но качество, модерация, ранжирование, языки, начисления или KPI пока частично ручные. Допустимо только для контролируемого теста.

STOP

Нет единой карточки/связки заказа, нет SLA, нет no-send, нет support owner/decision, нет QA proof или админ должен догадываться о состоянии консультации.
