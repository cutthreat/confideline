Три вещи, без которых контрольный заказ нельзя запускать

PM уже подготовил сценарий, услугу, вопрос, standard ответа и support-сценарий. Теперь Игорю нужно снять технический STOP: безопасный тестовый заказ, режим без отправки уведомлений и понятный маршрут в админке.

FX08 и FX09 блокируют QAFX11 нужен для приемкиPM-сценарий готов
Результат Игоря

Не “посмотреть сайт”, а дать проверяемый proof: order id в test mode, no-send event preview и admin route, где QA видит заказ, вопрос, консультацию, исполнителя, чат, события и support.

Правило внедрения

Перед изменениями в Confideline нужно выбрать правильный рабочий вариант/путь, не редактировать архивы и не смешивать ветки реализации. Для будущей разработки это фиксируется в задаче Игоря.

1safe test order без real charge
2no-send события без реальной отправки
3admin route для QA-приемки
READYтолько после proof по всем трем
PM-вердикт: пока эти три пункта не доказаны, QA не стартует и запуск рекламы запрещен. Если Игорь не может закрыть один из пунктов, результатом должна быть не “не получилось”, а точный STOP: что отсутствует, где упирается и какой минимальный следующий шаг нужен.
