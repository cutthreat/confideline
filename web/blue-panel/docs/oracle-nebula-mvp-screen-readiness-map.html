Вывод PM

Дизайн и публичная верстка Nebula существуют, но ни один коммерческий экран пока нельзя считать полностью готовым к трафику, пока не доказана цепочка: экран → действие клиента → заказ → вопрос → эксперт → ответ → поддержка → отчет.

Рекомендация: сначала закрывать не всю красоту Nebula, а минимальный оплачиваемый путь: главная/услуга → регистрация → экран перед оплатой → вопрос → кабинет/чат → support → уведомления → админ-контроль. Остальные страницы можно доводить параллельно, но они не должны отвлекать от доказанного платного сценария.

Что делать дальше

Для АнтонаДорабатывать макеты вокруг клиентского маршрута покупки, а не вокруг отдельных красивых экранов: offer, checkout, fallback, кабинет, paid chat, support.
Для ИгоряДоказать backend-связку paid consultation: заказ, вопрос, назначение, чат, статусы, support, события и no-send уведомления.
Для PMКаждую страницу превращать в экранный контракт: бизнес-смысл, источник дизайна, backend-связь, контент, failure states, QA proof.
Для запуска рекламыНе включать трафик, пока красные зоны не стали хотя бы желтыми с runtime proof по тестовому заказу.
