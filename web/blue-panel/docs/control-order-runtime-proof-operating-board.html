Что должно быть доказано, чтобы перейти от плана к запуску

Эта страница фиксирует не сценарий теста, а правила приемки proof. PM принимает только факты: ID заказа, скрины, логи событий, no-send markers, support case, admission journal и публичный QA-verdict. Описания “работает” недостаточно.

PM-решение

Контрольный заказ является главным доказательством готовности платформы. До него Blue Panel, Trello, ТЗ и макеты остаются подготовкой, но не основанием для трафика.

Безопасность

Все proof снимаются без реального платежа, без реальных email/SMS/push, без внешней рекламы и без production-изменений вне согласованного тестового контура.

9STOP-proof обязательны до QA verdict
4желтых proof можно закрывать параллельно
0фактов принято сейчас
PASSтолько после публичного QA-отчета

Короткий порядок

1. Игорь дает backend/admin proofSafe order, order/question/session, assignment, workspace, event log, support context.2. PM допускает исполнителяМинимум один исполнитель для QA, все 5 экспертов для первого трафика.3. QA стартует только после READYЕсли есть риск реального платежа/письма или нет safe order, QA не запускается.4. Итог меняет светофорPASS/WARN/STOP отчет обновляет готовность запуска и июньский план.
Запрет: скрин красивого экрана, Trello checklist или устное “работает” не принимаются как runtime proof.

Как меняется статус после proof

ВердиктКогда ставитсяЧто можно делатьЧто нельзя делать
PASSВсе STOP-proof приняты, QA-отчет опубликован, критических дефектов нет.Готовить ограниченный preflight первого трафика с лимитами и legal/payment gates.Масштабировать без capacity/economy control.
WARNОсновной путь работает, есть некритичные ограничения: язык, ручной support, ручные начисления, UX-долги.Планировать малый тест только после явного принятия рисков и stop-rules.Запускать широкую рекламу или скрывать ограничения.
STOPНет safe order, no-send, assignment, answer, support proof или QA-report.Только исправления и повторный контрольный заказ.Платежи, письма, реклама, внешний запуск.
PM-позиция: если есть хотя бы один STOP по safe order, no-send, order binding, executor admission, answer delivery, support case или public QA verdict, запуск остается красным.
