Кто следующий должен дать факт, чтобы запуск сдвинулся

Эта страница переводит сводный красный статус в конкретные входы от людей. Здесь нет новых задач для Trello: только ближайшие proof-результаты, которые реально меняют готовность проекта.

PM-решение

Пока нет accepted proof от Игоря и минимум одного допущенного исполнителя, остальные работы остаются подготовкой. QA, трафик, боевые платежи и реальные письма не запускаются.

Как использовать

Каждый ответ команды проходит через accepted / returned / blocked. Accepted меняет статус. Returned возвращается владельцу с точным списком недостающих фактов.

2критичных proof-входа до QA
3параллельных подготовительных владельца
0accepted runtime proof сейчас
1PM-инфраструктура ведется

Короткий порядок действий

1. Игорь: safe orderБезопасный заказ, admin route, workspace, no-send, support, без реального списания/отправки.2. PM/Ксения: исполнительМинимум один эксперт/агент с пробным ответом, SLA, языком, доступом и verdict.3. PM: READY gateЕсли два входа accepted и no-send/admin/support proof есть, QA можно запускать.4. QA: PASS/WARN/STOPТолько после READY. Отчет меняет светофор запуска.
Фокус недели: не расширять список функций, а принять или вернуть эти входы. Если они не accepted, запуск не движется, даже если документы и макеты улучшились.

Что сейчас не делать

Не запускать: QA без READY, paid traffic, реальные платежи, реальные email/сообщения, публичный checkout, внешние публикации и изменение production.
Делать: принимать/возвращать proof-входы, уточнять экранные контракты, держать PM-пакеты готовыми, обновлять Blue Panel ссылками и статусами.
