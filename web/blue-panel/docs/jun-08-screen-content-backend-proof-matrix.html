Решение PM

Сопоставление с Oracle/Nebula можно считать собранным как PM-артефакт: источники дизайна, публичная верстка и экранные группы связаны с функциями запуска. Контент нельзя считать готовым: по каждому экрану указано, какой контент нужен, но финальные тексты/FAQ/legal/email/переводы еще должны быть подготовлены и вставлены в конкретные страницы.

сверка экранов собрана контент не финализирован реклама запрещена до runtime proof

Что доказано

Есть Figma-источник, публичная верстка Nebula, 20 страниц site-map, 14 экранных групп и 89 блоков из таблицы.

Что не доказано

Ни одна ключевая платная страница не прошла полный путь: экран → backend → контент → состояние ошибки → QA proof.

Как использовать

Эта таблица становится входом для задач Антона, Игоря, Ксении и QA: не “нарисовать/сверстать”, а закрыть конкретную связку.

Что можно закрыть, а что нет

Можно закрыть как PM-артефакт: пункт “сопоставить страницы с макетами Oracle/Nebula”, потому что страницы, группы, backend-зависимости и ссылки на источники собраны в одну проверяемую матрицу.

Нельзя закрыть как готовность к запуску: пункт “добавить нужный контент для каждого экрана”, если понимать его как финальные тексты на сайте. Сейчас закрыта только контентная инвентаризация: какой текст нужен и где он должен быть.
