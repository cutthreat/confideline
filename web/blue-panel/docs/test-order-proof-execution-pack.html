Первый runtime proof: test order

Это исполнительный пакет, который должен впервые доказать, что сервис способен провести платную консультацию без реального списания: от оффера до ответа, support, событий и QA-вывода.

без этого запуск нельзя пакеты готовы платежи не запускаем
Решение PM

Все дальнейшие разговоры о рекламе, масштабировании, CAC/LTV и полноценном запуске упираются в этот proof. Если test order не проходит, мы не спорим о маркетинге, а закрываем конкретный сломанный шаг.

10шагов proof
0реальных платежей
1итог: PASS/WARN/STOP
Граница безопасности: не запускать реальные платежи, не отправлять реальные письма клиентам, не менять production. Проверка должна идти в test/no-send режиме с фиксацией скринов, логов и статусов.

Кто что делает

PMДержит маршрут, фиксирует proof, не дает расширять scope до прохождения test order.
ИгорьПодтверждает или связывает backend/admin: order, question, assignment, chat, events, support.
QAПроходит маршрут, снимает скрины, заполняет PASS/WARN/STOP отчет.
Эксперт/агентПолучает тестовую задачу, отвечает по регламенту, не работает с реальным клиентом.
SupportПроверяет один проблемный сценарий и решение без реального возврата.
