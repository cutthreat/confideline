Уведомления, support и аналитика должны доказаться одним заказом

Этот слой отвечает за управляемость после действия клиента. Один safe order должен показать: событие создано, реальное письмо не ушло, support видит проблему, решение зафиксировано, а аналитика может связать источник, заказ, сумму, эксперта и итог.

no-send proof = 0support proof = 0analytics proof = 0приемка описана
Главный PM-вывод

Нельзя принимать email, support и аналитику отдельно. Они должны быть связаны одним `order_id/test_run_id`, иначе это не доказывает готовность запуска.

Почему это блокер

Без этой связки мы не узнаем, получил ли клиент нужный статус, где зависла проблема, кто владелец и можно ли считать CAC/LTV.

Support принял решение

Кейс получает решение, закрытие, no-send статус и влияние на готовность/качество.

Источник связан с заказом

PM может восстановить путь: источник → сессия → клиент → заказ.

Proof: source/session/client/order row.

 CSA08красный

Деньги и услуга связаны

Сумма, валюта, услуга и эксперт связаны с тем же заказом.

Proof: value/currency/service/expert row.

 CSA09красный

Проблема, refund-risk или решение support отражаются в строке заказа.

Proof: support_case_id in analytics.

Proof: daily report row.

 CSA11красный

Тестировщик проверяет, что события, support и аналитика связаны одним marker.

Правило приемки: no-send preview без `order_id`, support case без `order/session`, analytics row без `source → order → value` не принимаются как запусковый proof.

Готовый запрос Игорю/QA

Нужно на одном safe test order вернуть связанный комплект: Игорь: 1. Event log: order, question, assignment, answer, support с event_id, preview и external_send=false. 2. Support case: case_id, reason, owner, decision, closure. 3. Analytics row: source, session_id, client_id, order_id, value, currency, service_session_id, expert/profile_id, support_case_id. 4. Daily report row или место, где эти данные видны PM. QA: 1. Проверить, что все CSA-факты связаны одним test_run_id/order_id. 2. Проверить, что реальные письма/сообщения не ушли. 3. Проверить, что support case не живет отдельно от заказа. 4. Проверить, что analytics row не является ручной сводкой без первичных proof. 5. В публичном QA-отчете указать PASS/WARN/STOP по CSA.
