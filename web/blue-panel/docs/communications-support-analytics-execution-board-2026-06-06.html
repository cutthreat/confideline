Уведомления, support и аналитика должны доказаться одним заказом

Этот board соединяет no-send события, проблемный support-case и purchase analytics. Для запуска важно не наличие отдельных шаблонов, а то, что один безопасный заказ дает связанные события, жалобу/решение и строку данных для будущего CAC/LTV.

accepted events = 0support proof = 0analytics proof = 0контур приемки готов
PM-решение

Не принимаем no-send, support и analytics отдельно друг от друга. Они должны быть связаны одним test_run_id/order_id, иначе это не доказывает готовность запуска.

Готовый запрос Игорю/QA по CSA

Нужно на одном safe test order вернуть связанный комплект CSA01-CSA12. Игорь: 1. События order/question/assignment/answer/support с event_id, preview и external_send=false. 2. Support case по проблемному сценарию: case_id, reason, owner, decision, closure. 3. Analytics row: source, session_id, client_id, order_id, value, currency, service_session_id, expert/profile_id, support_case_id если есть. 4. Daily report row или место, где эти данные будут видны PM. QA: 1. Проверить, что все CSA-факты связаны одним test_run_id/order_id. 2. Проверить, что реальные письма/сообщения не ушли. 3. Проверить, что support case не живет отдельно от заказа. 4. Проверить, что analytics row не является ручной сводкой без первичных proof. 5. В публичном QA-отчете указать PASS/WARN/STOP по CSA.
