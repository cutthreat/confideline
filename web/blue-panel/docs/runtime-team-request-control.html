Runtime control · что отправить и что ждать

Один экран управления запросами до контрольного заказа

Это оперативная доска PM: кому что отправить, что ждать обратно, когда можно запускать QA и какое решение принять после каждого ответа. Она не заменяет proof-inbox, а показывает порядок действий.

4 красных шага до QA/traffic2 PM-шагa приемкиQA сейчас STOP
Текущая правда

Запуск остается красным. Сейчас нужно получить два входа: результат Игоря по safe order и минимум одного допущенного исполнителя от Ксении/экспертов. Только после этого проверяем READY gate и отправляем QA-запрос.

Что не делаем

Не запускаем рекламу, реальные платежи, реальные письма и production-изменения. Trello не меняется с этой страницы.

Оперативный порядок

1ИгорькрасныйКогда: СначалаДействие: Отправить копируемый запрос ИгорюВернуть: test_run_id, order_id, session/task id, performer_id, answer_id, support_case_id, screenshots, no real charge/send2Ксения / экспертыкрасныйКогда: Параллельно с ИгоремДействие: Отправить запрос Ксении по допуску экспертовВернуть: статус 5 экспертов, пробные ответы, SLA, язык/анкета, verdict3PMкрасныйКогда: После ответов Игоря и КсенииДействие: Проверить QA start gateВернуть: READY/STOP по каждому условию gate4QAкрасныйКогда: Только после READYДействие: Отправить копируемый QA-запросВернуть: PASS/WARN/STOP, ID, скрины, дефекты Игорю, residual risks5PMжелтыйКогда: После каждого ответаДействие: Занести результат в proof-inboxВернуть: обновленная строка inbox, ссылка на proof, следующий владелец6PMжелтыйКогда: После accepted proofДействие: Обновить светофор запускаВернуть: обновленный readiness, proof ledger, июньский план, при необходимости Trello-ссылка
PM-правило: если ответ пришел не в нужном формате, он не меняет статус. Его нужно вернуть как returned с конкретным недостающим фактом.
