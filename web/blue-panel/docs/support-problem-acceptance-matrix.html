Какие проблемы должны быть обработаны до первых клиентов

Эта матрица переводит support/refund в приемку. Для каждого проблемного сценария указано: что должен увидеть support, что должен сделать backend/админка, какой no-send event нужен, как это влияет на эксперта и какой proof принимает QA.

PM-решение

Перед рекламой нам нужен минимум один проверенный support problem state на контрольном заказе. Полные refund rules можно закрывать позже, но карточка проблемы и операционный маршрут должны быть доказаны сейчас.

Граница

Реальные возвраты не запускаем. Проверяем только test-mode статусы, no-send уведомления, связи с заказом и видимость для команды.

Минимум для первого контрольного заказа

Обязательный support scenarioКлиент недоволен ответом: “The answer feels too generic and does not address my question.”
Обязательный ticket contextOrder id, service_session id, chat, expert/agent, question, answer, reason, status, decision.
Обязательный no-sendsupport_ticket_created и support_review_needed должны появиться как preview/log без реальной отправки.
Обязательный QA verdictPASS только если support видит контекст и может принять test-mode решение без ручного поиска.
