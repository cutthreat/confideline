Конкретные тестовые данные для первого контрольного заказа

Это набор данных, который PM может подготовить сам до участия Игоря и QA. Он нужен, чтобы test order проверял реальную услугу, а не случайный текст и непонятные статусы.

Что это закрывает

Тестовая услуга, вопрос клиента, ожидаемый тип ответа, support-сценарий, no-send события, test marker и rollback правило.

Что не закрывает

Не доказывает работу backend, платежа, админки или уведомлений. Это входные данные для будущего runtime proof.

PM-набор фикстур

Правило: эти данные можно использовать как стартовый сценарий. Если Игорь или QA меняют значения, изменение фиксируется в отчете, чтобы proof оставался воспроизводимым.
