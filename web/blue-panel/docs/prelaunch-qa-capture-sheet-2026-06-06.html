Лист приема pre-launch QA

Заполняется тестировщиком после READY gate. Цель — не “покликать сайт”, а доказать контрольный путь: клиент покупает безопасный тестовый заказ, эксперт отвечает, админ видит процесс, события создаются без отправки, support управляет проблемой, аналитика и отчет дают PM решение PASS/WARN/STOP.

Что QA должен вернуть

qa_run_id, test_order_id, test_user_id, expert/profile_id, screenshots, admin links, event IDs, support_case_id, purchase analytics row, final verdict, blockers и retest path.

STOP-сигналы

Риск реального платежа, реальная отправка email, потеря заказа/вопроса/ответа, отсутствие исполнителя, support без владельца, админка не видит lifecycle, отчет без доказательств.

Граница: этот лист не запускает QA сам по себе. QA стартует только после safe order READY, минимум одного accepted эксперта, no-send/admin route READY.

Правила приемки

PASS

QAC01-QAC15 закрыты, публичный отчет опубликован, critical STOP отсутствует. PM может пересчитать readiness, но paid traffic открывается только если остальные launch gates тоже готовы.

WARN

Основной путь работает, но есть ручные обходы, UX-долг или неполная аналитика. Допустимо только для ограниченного теста с владельцем и сроком закрытия.

STOP

Риск реальной оплаты/отправки, потеря заказа/вопроса/ответа, нет исполнителя, support неуправляем, админка не видит путь, нет публичного отчета.
