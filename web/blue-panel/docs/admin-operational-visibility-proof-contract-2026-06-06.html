admin visibility proof · 06.06.2026

Админка готова только если видит весь заказ без ручного расследования

Этот контракт задает, что именно должен увидеть PM/admin/support по одному safe order. Если заказ, вопрос, эксперт, SLA, ответ, уведомления, support и аналитика разбросаны без единого маршрута, запусковый статус админки остается красным.

admin runtime proof = 0контракт готовQA ждет R01/R02трафик STOP
PM-решение

Для MVP допустима не “идеальная ERP”, а управляемая админка по ролям. Но она обязана дать администратору одну рабочую картину консультации и понятные действия при проблемах.

Что считается proof

Скрин/route/log с одним order_id, где видны ключевые статусы и переходы: создан, вопрос, назначение, ответ, уведомление, support, analytics, итог.

Что не принимается

Скрин отдельной таблицы без order_id, ручная сводка без первичных экранов, “это можно найти”, устное подтверждение.

12обязательных зон видимости
0зон доказано runtime
1контракт приемки для Игоря/QA
STOPQA не стартует без R01/R02

Операционный маршрут админки

1Карточка заказаorder_id, клиент, услуга, сумма/test marker, текущий статус.2Вопрос и сессияquestion_id, session/card консультации, текст вопроса, клиентский путь.3Исполнительperformer/profile, назначение, SLA, workspace, ответ.4События и supportno-send log, support case, owner, decision, close.5Аналитикаsource/session/order/value/service/expert/support/outcome.6QA verdictPASS/WARN/STOP по админскому маршруту и paid-flow.
Минимум перед QA: order card, question binding, assignment, workspace, admin timeline, no-send log. Без этого тестировщик проверяет не сервис, а набор разрозненных страниц.

Готовый запрос Игорю/QA по админке

Нужно вернуть admin visibility proof по одному safe order. Игорь: 1. Показать route/скрин карточки заказа с order_id и test marker. 2. Показать question_id внутри этой карточки или связанным route. 3. Показать assignment: performer/profile/deadline/SLA. 4. Показать workspace под ролью E01/эксперта. 5. Показать answer_id и вид ответа в admin/client/expert контуре. 6. Показать no-send event log: event_id, template, variables, external_send=false. 7. Показать support_case_id, owner, decision, closed_at. 8. Показать analytics row: source/session/order/value/service/expert/support. 9. Показать, где PM видит daily status по этому заказу. QA: 1. Проверить, что все пункты относятся к одному test_run_id/order_id. 2. Проверить, что админ не собирает состояние вручную из несвязанных экранов. 3. Поставить PASS/WARN/STOP по каждой зоне AOC01-AOC12. 4. Если зона не доказана, вернуть конкретный missing proof, а не общий комментарий.
