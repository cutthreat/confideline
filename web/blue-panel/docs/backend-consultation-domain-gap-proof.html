Платная консультация как backend-сущность не доказана

Текущий YouDate/Confideline backend дает важную базу: пользователи, анкеты, сообщения, заявки экспертов, order/payment, админка и аналитика. Но платная консультация Nebula требует отдельного доменного слоя, который связывает оплату, вопрос клиента, исполнителя, чат, события, поддержку и качество.

универсальная база естьэкспертский контур частично естьconsultation domain RED
Проверенный source

`Confideline/Chat/youdate-2.0.2-yii2/Source/youdate_extracted/application`.

Ограничение

`Chat/README.md` говорит, что в `Confideline/Chat` несколько вариантов. Для внедрения Игорь должен подтвердить актуальный runtime source.

Короткий вывод PM

Решение: не считать существующие `Order + credits + Message` готовой платной консультацией. Это база платформы, но для Nebula MVP нужен минимальный service-layer: `Order → вопрос → консультация → назначение эксперта/агента → чат → события → поддержка/возврат → качество/начисление`.

Что реально найдено

Order/payment есть

`Order` хранит платежный статус и payment id; Stripe flow переводит order в `COMPLETED`.

Credits/balance есть

`successPayment()` увеличивает баланс пользователя. Это не равно покупке консультации.

ExpertApplication есть

Заявка эксперта и certification status есть, но модель сама говорит, что paid-session access не выдается.

Message/chat есть

Есть `Message`, `Conversation`, admin chat shell и expert CRM preview. Это транспорт, а не lifecycle консультации.

Analytics есть

`PartnerInteractionAnalyticsService` считает взаимодействия client/expert, но не оплаченные консультации.

Consultation не найдена

Модели `Consultation`, `Question`, `PaidSession` или явной связи с order не обнаружены.

Минимальная backend-модель для MVP

consultation

`id`, `order_id`, `client_id`, `question_text`, `status`, `test_mode`, `created_at`.

assignment

`consultation_id`, `expert_id/agent_id`, `assigned_by`, `deadline_at`, `status`.

chat link

`consultation_id`, `conversation_id` или явная связь с thread/chat id.

events

`checkout_complete`, `question_submitted`, `consultation_created`, `expert_assigned`, `answer_sent`, `overdue`.

support

`ticket_id`, `order_id`, `consultation_id`, причина, решение, refund state.

quality/payments

оценка ответа, нарушение SLA, начисление исполнителю, удержание.
