Notifications / no-send · proof acceptance · 05.06.2026

Уведомление считается готовым только когда событие видно, а наружу ничего не ушло

Эта страница фиксирует критерии приемки email/notification контура. Для запуска важен не список красивых шаблонов, а доказательство: событие создано в правильный момент, привязано к заказу, получатель и переменные определены, preview доступен, no-send marker стоит, реальной отправки нет.

no-send proof = 0реальные письма запрещенышаблоны/события частично готовыкритерии приемки сформированы
Решение PM

Email и уведомления остаются красными до safe test order с event log и preview по заказу, назначению, ответу и support. Устное “шаблон есть” не принимается.

Почему это gate

Если клиент, эксперт, support или админ не видят статус, сервис выглядит сломанным даже при рабочем чате. Если в QA уйдет реальное письмо, тест небезопасен.

Рабочий маршрут приемки

1. Запустить safe test orderСоздать заказ, вопрос, назначение, ответ и problem state без реального платежа и без реальных писем.2. Снять no-send registerПо каждому событию показать event id, role, recipient, template, variables, preview и suppression marker.3. Проверить support eventsЖалоба и решение support должны создавать события без отправки клиенту наружу.4. Передать события в аналитикуsource/order/session/value/support status должны попадать в purchase proof и daily report.
Запрет: не отправлять реальные email/SMS/push/сообщения клиентам или экспертам во время QA. Принимается только preview/log/no-send marker.
