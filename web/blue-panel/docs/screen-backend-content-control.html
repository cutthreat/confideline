Экраны, backend, контент и проверка: что реально готово для запуска

Эта страница собирает в одно место то, что раньше было размазано по дизайну, backend-картам, QA-отчетам и задачам. Она нужна, чтобы не спорить “есть ли страница”, а видеть полную связку: экран найден, backend обслуживает, контент готов, ошибки продуманы, проверка возможна.

Правильная модель оценки

Confideline — backend и универсальная платформа. Oracle/Nebula — будущий фронт и личный кабинет. Для запуска важна не картинка сама по себе, а связка: клиентский экран → действие → backend → админка/эксперт → уведомления → support → аналитика.

Главный вывод PM

Дизайн-источники найдены: публичные страницы, LK-пак на 19 экранов и дизайнерские gap-brief документы. Но коммерческий путь платной консультации еще не закрыт: checkout, вопрос, paid lifecycle, результат, follow-up, support и analytics требуют доработки и proof.

19экранов LK в локальном source pack
20+публичных Nebula HTML-страниц
7частично готовых связок
7красных блокеров запуска
Решение: в июне нельзя просто “доверстать макеты”. По каждой строке ниже нужно закрывать связку экран + backend + контент + состояния + QA. Если строка красная, ее нельзя пропускать перед рекламой. Если желтая, можно готовить пакет, но нужен proof.

Следующее PM-действие

Сначала закрывать красный маршрут: checkout/test order → question intake → paid chat lifecycle → expert/admin workspace → support/refund → notifications/no-send → analytics proof. Параллельно Антону отдавать только конкретные недостающие состояния, а не общий запрос “улучшить дизайн”.
