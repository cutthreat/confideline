Как фактически допустить первых 5 экспертов

Это рабочий пакет для PM, Ксении и первых экспертов. Он превращает “у нас есть 5 экспертов” в проверяемый допуск: данные, обучение, тест, пробный ответ, оценка, SLA, решение PM и связь с контрольным заказом.

0 экспертов допущено proof-фактамиметодика и школа естьжурнал 5 экспертов пустойКсения = ревизор
PM-решение

Пока EP01-EP09 не закрыты хотя бы по одному исполнителю, контрольный заказ нельзя запускать. Для первого трафика нужны EP01-EP10, capacity/SLA и понятный лимит по всем 5 или явное ограничение запуска.

Роль Ксении

Ксения проверяет понятность и практичность готовых материалов. Методологию, архитектуру, критерии допуска и финальный verdict держит PM.

5экспертных слотов пока пустые
10gates EP01-EP10 на каждого
1школа v1 как методическая база
0готовая capacity для трафика
STOP: “эксперт готов включаться” не является proof. Proof = строка в журнале + тест/ответ/scorecard/SLA + решение PM.
Минимум для контрольного заказа: один эксперт может быть “условно допущен только для test order” как минимальный вход до QA, если EP01-EP08 закрыты, EP09 содержит явное ограничение, а EP10 подтверждается Игорем/QA на workspace.

EP01-EP10: что закрываем по каждому эксперту

EP01Паспорт экспертакрасныйКто: PMЧто собрать: Код, имя, роль, язык, часовой пояс, специализация, контакт, анкета/profile_id.Приемка: Понятно, кто работает, под какой ролью и каким профилем.
EP02Выдача школы v1 и регламентакрасныйКто: PMЧто собрать: Ссылка/скрин выдачи материалов, дата, версия, список модулей.Приемка: Эксперт получил актуальную версию школы и регламента.
EP03Подтверждение прохождениякрасныйКто: Эксперт + PMЧто собрать: Форма/отметка, что эксперт прошел материалы.Приемка: Нет устного “прочитал”; есть фиксированный факт прохождения.
EP04Тест правил и безопасностикрасныйКто: PM + Ксения reviewerЧто собрать: SLA, границы сервиса, запреты, escalation, dangerous wording.Приемка: Нет критичных ошибок; проходной результат зафиксирован.
EP05Пробный ответкрасныйКто: ЭкспертЧто собрать: Ответ на тестовый клиентский кейс с marker.Приемка: Ответ персональный, структурный, безопасный, с next step.
EP06Оценка качества ответакрасныйКто: PM / Answer QualityЧто собрать: Scorecard: эмпатия, персонализация, структура, ясность, безопасность, next step.Приемка: Verdict ready / minor fixes / blocked с причиной.
EP07SLA и графиккрасныйКто: PM + экспертЧто собрать: Доступность, максимальное время ответа, дневной лимит, что делать при просрочке.Приемка: Можно рассчитать безопасную capacity и escalation.
EP08Support/failure пониманиекрасныйКто: PM + Ксения reviewerЧто собрать: Сценарии: жалоба, просрочка, опасный запрос, конфликт, refund/escalation.Приемка: Эксперт знает, когда отвечать, когда остановиться и когда эскалировать.
EP09Решение PM о допускекрасныйКто: PMЧто собрать: Допущен / условно для test order / доработка / не допущен; дата и причина.Приемка: Есть явный verdict по каждому эксперту.
EP10Привязка к test order роликрасныйКто: PM + Игорь + QAЧто собрать: Роль, доступ, profile_id/anketa_id, workspace, назначение в контрольный заказ.Приемка: QA знает, кого проверять; исполнитель видит задачу; RP05A можно закрывать runtime-proof фактами.

Задача Ксении как ревизору

Цель: проверить подготовленный PM-пакет допуска первых 5 экспертов как эксперт-новичок. Материал: first-five-expert-admission-execution-pack.html, expert-school-v1-operational-pack.html, expert-work-regulation-v1.html, expert-trial-answer-quality-scorecard.html. Роль: не переписывать методологию, не менять архитектуру, legal, оплату и приоритеты. Проверить понятность и практичность. Шаги: 1. Открыть материалы. 2. Пройти маршрут как эксперт-новичок. 3. Отметить непонятные места, нереалистичные требования, рискованные формулировки, недостающий контекст. 4. Дать verdict: ready / minor fixes / blocked. 5. Приложить короткий список комментариев по конкретным местам. Результат: комментарии + verdict + скрин/ссылка на feedback.
