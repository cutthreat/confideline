Это рабочий вход PM после того, как команда присылает результат. Здесь видно, какой proof мы ждем, что уже получено, какой статус может измениться и какое решение PM должно быть принято: accepted, returned или blocked.

Почему это важно

Без inbox команда будет присылать разрозненные скрины и комментарии, а PM снова начнет руками вспоминать, что это закрывает. Здесь каждый входящий факт сразу привязан к статусу и proof-странице.

Текущее решение

Пока нет принятого runtime proof. Самые важные ожидаемые входы теперь оформлены как копируемые запросы: Игорь по safe order, Ксения/эксперты по допуску исполнителя, QA по PASS/WARN/STOP после READY. Входящие ответы принимаются только через accepted / returned / blocked.

4красных runtime-входа блокируют MVP
2желтых источника готовятся параллельно
1PM-публикация уже стандарт
0accepted runtime proof сейчас
Что не принимается: устное подтверждение, скрин без ID, ссылка 404, Trello-карточка вместо результата, макет без сценария, отчет QA без PASS/WARN/STOP.
PM-правило: каждый входящий proof получает один из статусов: accepted, returned или blocked. Только accepted proof может менять светофор запуска.
