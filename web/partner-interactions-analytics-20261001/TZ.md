# №59. Панель взаимодействий — ТЗ для Игоря

Реализовать экран «Взаимодействия»: кто из клиентов и экспертов с кем взаимодействовал, какие действия совершал и сколько раз. Вид и расположение элементов — по [админскому макету](admin.html), [макету агента](partner.html) и [макету эксперта](expert.html). Сведения в HTML — пример наполнения; на сайте показывать фактические данные.

## 1. Экран и управление

Порядок: **сводка по применённой выборке → открытый блок «Фильтры отчёта» со свободной настройкой → вкладки «Таблица / Графики» → содержимое вкладки**. Применённые даты и область видны над карточками сводки; время актуальности — под ней. Свободные поля фильтров не скрываются при выборе набора или после применения. Сводка, таблица и графики используют одну выборку.

Фильтры: один/несколько/все доступные профили экспертов, период/даты, направление, клиент по имени/username/ID, минимум событий активности. У администратора профили сгруппированы по текущим агентам. Групповая галочка выбирает все профили агента; можно оставить произвольное подмножество у каждого из нескольких агентов. У агента отображаются только его назначенные профили, у эксперта выбор профиля отсутствует. Поиск по агенту/профилю не меняет отмеченный набор. Периоды: сегодня, последние 7×24/30×24 часа, вся история, произвольный диапазон. Даты включительно, Europe/Minsk; сегодня — до текущего времени. Изменения полей не меняют отчёт до «Применить фильтры»; применение обновляет весь отчёт и возвращает первую страницу. Прежний контекст действует до успешного обновления; ввод во время обновления сохраняется неприменённым. «Отменить изменения» возвращает применённые значения. Ошибка дат или минимального порога сохраняет прежний отчёт; фокус переходит в ошибочное поле. Порог — целое неотрицательное число, пустое поле означает 0. Enter в поле применяет фильтры.

Отчёт показывает фактические цифры. Скорость ответа и оценка соблюдения регламентов/SLA исключены из этой задачи; наличие ответа не означает соблюдение срока. Подробности расчётов описаны ниже; подсказки на карточках поясняют их область.

### Визуальная и техническая интеграция

Редакция r17 от 09.10.2026 продолжает переданные admin/contact-filter стили. В таблицах: Inter 12px, заголовки 600, padding ячеек 8px, линии #e4e9ef/#edf1f5, фон заголовка #fbfcfd, вторичный текст #526879, прямоугольная рабочая область без тени. Поля фильтра — 30px на компьютере; ниже 768px — 44px. Горизонтальная прокрутка ограничена таблицей/графиком. Сохранять исходный хедер, ширину меню 230px, breakpoint 768px и согласованный порядок блоков. Межбуквенный интервал — 0.

В автономный макет включён локальный Inter с лицензией; при внедрении использовать уже подключённый Inter и штатные Bootstrap/AdminLTE/иконки. Подключать только страничные дополнения через AssetBundle после общих ресурсов, контроллер — один раз вне PJAX. Общие CSS/JS сайта, хедер и контроллеры не дублировать; полный demo HTML и демонстрационный источник в рабочий backend не переносить. Значения в статическом макете не заменяют действующие модели/права.

Пользовательские подписи, title/ARIA, ошибки и статусы реализации локализовать через существующий Yii::t и словари проекта. Автономный макет русскоязычный; английская проверка длинных подписей подтверждает только устойчивость вёрстки, а не готовность перевода продукта. На стенде принять реальные RU/EN строки отдельно.

## 2. Таблица

Внутри блока «Показатели таблицы», между заголовком и ручным выбором столбцов, расположены «Готовые наборы»: Обзор, Нагрузка, Обращения, Результат, Качество. Один клик меняет только столбцы таблицы. Полная сводка, фильтры и неприменённый ввод, настройки/участники/точные значения графика сохраняются; таблица возвращается на первую страницу, неподходящая сортировка заменяется сортировкой по первому выбранному показателю. «Обзор» выбирает шесть основных столбцов. Ручная правка столбцов отмечается как «Свой набор»; изменение графика не меняет выбранный набор. Повторный выбор набора восстанавливает его состав. Отдельная кнопка «Основные» не нужна.

- Нагрузка: просмотры, избранное, новые Chats, новые Pings, сообщения клиента.
- Обращения: новые Chats, новые Pings и сообщения обеих сторон.
- Результат: оплаченные консультации, повторы и накопленный LTV; платформенные показатели доступны только администратору.
- Качество: жалобы, блокировки и повторные консультации с экспертом. Жалобы не обозначать подтверждёнными нарушениями.

Ручной выбор показателей постоянно открыт под заголовком таблицы и примечанием о LTV. Далее идут сортировка и режим заголовков, затем таблица — как в исходной компоновке. Сортировка кликом по заголовку остаётся непосредственно в таблице. Постоянные поля: **Кто / Кому / Направление**; участник — имя, username, ID. Плитка добавляет/убирает столбец, выбранное подсвечено с галочкой. По умолчанию шесть: просмотры, избранное, новые Chats, сообщения клиента/эксперта, оплаченные консультации. Набор «Обзор» восстанавливает их; есть «Все показатели» и «Снять выбор».

Заголовки: значок и короткая подпись, полное название при наведении/фокусе; «Только значки» доступно на большом экране. При открытии сортировка по просмотрам убывает; выбранное значение всегда видно. Сортировка по выбранным столбцам — сразу; страницы по 50/100/250/500 строк не меняют общие итоги и графики.

У пары две строки направлений. Направление влияет на действия/сообщения; факты Chats/Pings, консультации, повторы и LTV — общие для пары. В зеркальной строке — ссылка на уже учтённое значение. Итоги без удвоения; платформенный LTV — один раз на клиента. Пара с накопленным LTV остаётся в выборке и без активности за период.

## 3. Какие данные учитываем

Найти фактические сведения для расчётов:

- Клиенты, профили экспертов и агенты: ID, имя, username, роль, текущее назначение профиля агенту.
- История действий: кто, кому, какое действие, когда; идентификатор отдельного факта.
- История создания Chats отдельно от Pings: идентификатор чата/пинга, клиент, профиль эксперта, момент появления именно Chat (включая переход Ping → Chat), связь с предшествующим Ping.
- Полная история личных сообщений клиента и эксперта: отправитель, получатель, Chat, дата. Текст сообщений для панели не нужен.
- Текущее закрепление профилей экспертов за агентами. Один профиль принадлежит одному агенту; агент лично общается и консультирует от лица любого числа закреплённых профилей.
- Консультации: отдельная консультация, её клиент и эксперт, фактические начало и завершение; история прежних консультаций, включая состоявшиеся пробные.
- Успешные оплаты консультаций и связанные подтверждённые возвраты: сумма credits, дата подтверждения, консультация и пара; вся история до конца периода.
- Доступность и полнота сведений по каждому показателю, время актуальности данных.

Учитывать только клиент↔эксперт; исключить действия с самим собой, служебные/тестовые аккаунты и сообщения, обращения в поддержку. Дубли одного факта не увеличивают счётчики.

| Показатель | Какие сведения и как считать |
|---|---|
| Просмотры профиля | Зафиксированные посещения профиля за период по выбранному направлению; повторные посещения учитываются, это не уникальные посетители. |
| Добавления в избранное | События добавления за период. Текущий состав избранного и удаления не заменяют историю добавлений. |
| Новые Chats (обращения) | Факты появления нового Chat за выбранный период. Сообщения в существующем Chat не создают новых обращений. Дата предшествующего Ping сама по себе не является датой нового Chat. |
| Pings | Факты создания Ping за выбранный период; считать отдельно от Chats. |
| Сообщения клиентов | Сохранённые личные сообщения клиента эксперту за период. |
| Сообщения экспертов | Сохранённые личные сообщения эксперта клиенту за период; это количество сообщений, а не количество ответов. |
| Оплаченные консультации | Каждую фактически начатую консультацию считать один раз, если её первая подтверждённая успешная оплата с положительной суммой попала в период. Покупка credits, предложение консультации и выбор платного режима оплатой консультации не являются. |
| Повторные с экспертом | Консультации, фактически начавшиеся в периоде, если ранее уже завершилась консультация этой же пары. |
| Повторные на платформе | Консультации, фактически начавшиеся в периоде, если ранее у клиента завершилась консультация с любым экспертом. |
| LTV пары, credits | Все подтверждённые оплаты консультаций этой пары минус связанные подтверждённые возвраты, накопленно до конца выбранного периода. |
| LTV клиента на платформе, credits | Тот же накопленный результат клиента со всеми экспертами. Фильтр одного эксперта не ограничивает этот показатель его консультациями. |
| Блокировки | Действия блокировки между клиентом и экспертом за период по направлению. Блокировка модератором сюда не относится. |
| Жалобы на пользователя | Зафиксированные жалобы клиента на эксперта и наоборот за период по направлению; обращения в поддержку не учитывать. |

В повторах учитываются и ранее завершённые пробные консультации. Дополнительные списания за одну консультацию увеличивают LTV, но не число консультаций. Возврат уменьшает LTV по дате подтверждения; последующая отмена/возврат не стирает состоявшийся факт успешной оплаты. Пополнение кошелька, бонусы и выплаты эксперту в LTV не входят. Дробные credits отображать без потери точности исходного значения.

Статистика принадлежит профилю эксперта. При передаче профиля новому агенту вся его история входит в сводку нового агента и перестаёт входить в сводку прежнего. События, значения и даты не перезаписываются и не стираются. Сводка агента использует текущий набор закреплённых профилей и их историю за выбранный период.

Граница HTML-примера r14: «Новые Chats» пока вычисляются по первому сообщению клиента в паре; отдельные Pings ещё не реализованы. Выбор нескольких профилей, сводка по этой выборке и агентские агрегаты реализованы на демонстрационных данных; реальные назначения/источники/backend/RBAC требуют отдельной приёмки. Целевые определения выше приоритетны для внедрения и требуют отдельной приёмки.

## 4. Сводка

Активные эксперты — эксперты с событиями активности в выборке (у эксперта карточка «Активность анкеты»: Есть/Нет); пары и клиенты — уникальные участники выборки. Сообщения — сумма сообщений обеих сторон. **События активности** — просмотры + добавления в избранное + сообщения клиентов + сообщения экспертов + блокировки + жалобы. Именно эта сумма используется для минимального порога; «Активные пары 10+» — пары с суммой от 10.

«Диалоги с клиентом» — пары с клиентским сообщением в периоде, включая ранее начатые диалоги. Счётчики ответов считаются по обеим сторонам отобранных пар, независимо от направления; фильтр направления не превращает существующий ответ в «Без ответа». «С ответом» — эксперт написал позже клиента в этом периоде; «Без ответа» — разница; доля — с ответом / диалоги × 100%. Без клиентских диалогов доля неизвестна. «Пары без входящих» — количество пар с сообщениями эксперта и без клиентских сообщений в периоде. Остальные карточки — итоги соответствующих показателей.

## 5. Графики

Порядок по макету: показатель → разрез/вид → открытые настройки сравнения/группировки → участники → график/легенда → раскрываемые точные значения. Сравнение участников выполняется наложением их рядов в существующей вкладке «Графики». Отдельная основная сравнительная таблица не требуется. Столбцы и страницы таблицы не меняют графики.

Разрезы: агент/профиль эксперта/клиент/пара, в пределах прав; LTV пары — агент/профиль/пара в пределах прав; у эксперта — пара. Платформенный LTV — только клиент. Виды по макету: линия/столбцы/доли/структура/таблица; структура только для активности, LTV только линия/столбцы/таблица. LTV накопленно на конец интервала, остальные показатели за интервал. Группировка: день/неделя/месяц.

Агентский ряд включает только выбранные в общих фильтрах профили этого агента; рядом — число выбранных из доступных ему профилей, в подсказке — их имена/ID. Смешивание профиля с агентским агрегатом в одном сравнении исключено. Выбранные профили без событий сохраняются как нулевые ряды, если источник известен. Порядок/цвета участников стабильны при смене подмножества.

Участники: выбор/все/снять выбор, количество и итог. Их галочки меняют только отображение графика; состав агентских агрегатов задаётся общим выбором профилей. Смена показателя сохраняет их при том же разрезе. Сравнение — предыдущий период равной длительности для тех же участников и пар из текущей выборки, с датами и различимым отображением; только линия/столбцы/таблица. Для платформенного LTV сохранять тот же набор клиентов, включая их прежние оплаты другим экспертам до первого взаимодействия с выбранным экспертом. Для всей истории недоступно. Неизвестные значения не заменять нулями и не соединять линией через пропуск.

## 6. Права и состояния

- Администратор — доступные ему данные по выбранным профилям и агентским агрегатам.
- Агент — только назначенные ему профили; эксперт — только собственный профиль.
- LTV клиента и повторы на всей платформе — только администратору с соответствующим доступом; у агента/эксперта эти показатели отсутствуют во всех частях отчёта.

Состояния определяются автоматически. Ошибка обновления сохраняет прежнюю выборку/фильтры/время; отказ доступа скрывает старые данные. Достоверный ноль — `0`, неизвестное — «Нет данных / Нет источника» с причиной. Неизвестное слагаемое делает итог активности неизвестным и отключает её минимальный порог. Отдельные сообщения: пустая выдача, не выбраны столбцы, не выбраны участники графика.

В итоговом интерфейсе нет тестовых наборов, переключателей состояний, ролевых ссылок, ссылок на ТЗ, симуляторов и отметок прототипа.

## 7. Как принять

Сверить фильтры/итоги таблицы и графиков, отсутствие двойного счёта, подтверждение оплат, историю повторов/LTV и права ролей. Проверить сортировку/пагинацию/выбор показателей, пустые и ошибочные состояния, точные значения, подсказки/клавиатуру и телефон.

Вкладки доступны с клавиатуры (стрелки, Home/End), меню сворачивается, на телефоне закрывается по Escape или выбору раздела. Левое меню визуально повторяет исходный каркас кабинета; при внедрении использовать действующую навигацию. Виды отчёта переключаются вкладками «Таблица / Графики».

## Текст интерфейса

Видимая копия содержит названия, значения, текущую область, ошибки и краткие состояния. Не добавлять пояснения реализации, адаптивности, наведения/фокуса и очевидных кликов. Удалённые служебные строки не возвращать при внедрении. Условия расчётов остаются в этом ТЗ и смысловых подсказках; единицы/даты LTV, область платформенного LTV и легенда сравнения периодов доступны в интерфейсе.


## 8. Выбор профилей и критерии r14

- Общий выбранный набор применяется одновременно к сводке, таблице и графикам. Он пересекается с текущим разрешённым набором аккаунта; нельзя расширить доступ подменой ID, роли или DOM.
- Передавать expertIds: null для всех доступных профилей либо массив конкретных ID. Пустой массив не означает «все». UI требует минимум один профиль; ошибка сохраняет последнюю применённую выборку. Порядок ID не создаёт ложного признака изменений.
- Общий фильтр остаётся черновиком до применения. Наборы столбцов/сортировка/вкладки/галочки рядов не стирают черновик. Отмена восстанавливает применённый набор.
- Агент А: профили 1 и 3; агент Б: профиль 5 — сводка и таблица только по 1/3/5; разрез «Агенты» содержит сумму 1+3 и отдельную сумму 5, разрез «Профили экспертов» — три отдельных ряда.
- Одна/несколько/все анкеты одного агента, выбор нескольких агентов с разными подмножествами, нулевой профиль, пустой выбор, поиск, отмена, применение, клавиатура и mobile должны быть проверены отдельно.
- При передаче профиля его история остаётся у профиля, а текущая агентская группировка следует актуальным назначениям. Не переписывать даты, события или авторство.
- Фактические разрешения и актуальные назначения определяет сервер. Технические partner/partnerId/partner.html в HTML сохранены для совместимости; их соответствие реальной агентской роли/связи подтверждается при интеграции.
- В r16 LTV пары дополнен агентским разрезом: суммировать LTV разных пар клиент–профиль по выбранным профилям текущего агента. Общий LTV клиента на платформе не приписывать агенту и не суммировать по профилям; его разрез — клиент. SLA не добавляется.

## 9. Доработка r16 и приёмка внедрения

### Источник фактов Chat/Ping

Для макета используется авторитетный снимок `conversations`: `id` — стабильный ID жизненного цикла, `clientId`, `expertId`, `pingCreatedAt`, `chatCreatedAt`. Даты — ISO 8601 с часовым смещением или Z; явный `null` означает, что соответствующий факт ещё не наступил. Прямой Chat без Ping имеет `pingCreatedAt: null`. Переход существующего Ping в Chat сохраняет его дату Ping и добавляет отдельную дату Chat. Повторный просмотр, outreach эксперта и новые сообщения в уже существующем Chat не создают новые факты. Исторический Ping остаётся фактом после конверсии/истечения: показатель считает создания за период, а не размер текущей очереди.

Это контракт адаптера отчёта, а не утверждение о названиях таблиц/API сайта. Если Chat и Ping имеют разные серверные ID, адаптер связывает их по реальной сохранённой связи и выдаёт один стабильный lifecycle ID. Нельзя получать ID, дату создания или связь из номера пары, первого сообщения, просмотра или текущего бейджа. Новый Ping после истечения предыдущего учитывается отдельно только при наличии отдельного подтверждённого ID жизненного цикла. Один lifecycle ID даёт не более одного создания Ping и одного появления Chat; ID и даты не переписываются при назначении другому агенту.

Полнота объявляется независимо: `sources.chats`, `sources.pings`; отсутствие коллекции или поля не равно пустому источнику/нулю. Идентичные дубли одного ID игнорируются. Конфликт ID/пары/дат, некорректная календарная дата и Chat раньше предшествующего Ping делают соответствующий итог неизвестным; противоречие общей идентичности делает неизвестными оба показателя. Одна недоступная метрика не скрывает другие известные показатели. Внедрение должно вернуть причину и актуальность источника, без текста сообщений.

В текущем примере: Chat A создан 01.09 после Ping 31.08; Ping B создан 11.09, Chat B появился 12.09. В диапазоне 07–15.09 итог новых Chats = 1, новых Pings = 1. Это демонстрационные данные. Пары с сообщениями клиента = 2; показатель не переименовывать в количество новых обращений.

### Финансовые агрегаты и сравнение

LTV профиля — сумма LTV его пар, LTV агента — сумма по выбранным у него профилям, накопленно на конец периода. Дата начала периода не обнуляет историю. Если клиент оплатил разным профилям, списания относятся к разным парам и складываются; одно списание/возврат не дублируется. LTV агента — объём по его текущему набору профилей, не прибыль, выплата, комиссия или отдельная оценка эффективности. Покупка credits, пополнение кошелька и выплата агенту в этот LTV не входят.

Платформенный LTV относится к клиенту, включает все его разрешённые для администратора оплаты на платформе и учитывается один раз. Он не является выручкой конкретного агента. Сравнение предыдущего равного периода сохраняет текущие профили/участников и пары текущей выборки, как в разделе 5; новые участники и пары предыдущего периода автоматически не добавляются. У графика видны даты и одинаковый цвет текущего/предыдущего ряда. Цвет зависит от типа и ID участника, а не от его позиции в списке или выбора других участников. При большом количестве рядов сохраняются имена, ID в составе профилей, легенда и точные значения; один цвет не является идентификатором.

Текущие назначения обязаны быть однозначными. Идентичный дубль назначения не удваивает сумму; конфликт разных текущих владельцев исключает профиль из доступа обоих агентов, а у администратора блокирует обновление выбранной неоднозначной выборки до исправления. Сервер проверяет это независимо от интерфейса. Профиль без текущего агента остаётся доступен администратору в группе «Без агента» и не открывается произвольному агенту.

### Экран → действие → результат при внедрении

| Экран и действие | Ожидаемый результат / проверяемый факт |
|---|---|
| Фильтры: у нескольких агентов выбрать разные подмножества профилей и применить | Сводка, таблица и графики используют один разрешённый набор ID; агентский ряд содержит только выбранные его профили. |
| Фильтры: очистить выбор, применить; затем отменить изменения | Ошибка и фокус на выборе; прежние данные/даты сохранены. Отмена возвращает применённый набор. |
| Клиент: повторно открыть профиль с действующим Ping | Счётчик созданий Ping не увеличивается, срок жизни исходного Ping не сбрасывается. |
| Клиент: отправить первое сообщение в Ping; обновить аналитику | Chat учитывается по фактической дате перехода, Ping остаётся фактом своей даты. Повторные сообщения не добавляют Chat. |
| Таблица: оба направления / одно направление, страницы и наборы столбцов | Действия фильтруются по направлению; Chats/Pings/LTV учитываются один раз, зеркальная строка содержит ссылку. Итоги не зависят от страницы или видимых столбцов. |
| Графики: LTV пары → «Агенты», изменить общий выбор профилей | Сумма по выбранным парам, накопленная на указанную дату; возвраты учтены, кошелёк/выплаты исключены; цвета оставшихся участников сохраняются. |
| Назначения: передать профиль агенту B, повторить отчёт A/B | A теряет доступ и всю историю профиля, B получает её; даты/ID/авторство фактов не меняются. Старый API/экспорт/кэш A не раскрывает профиль. |
| Агент/эксперт: подменить роль, ID профиля, URL API или экспорт | Сервер отказывает в чужих данных, глобальных повторах и платформенном LTV; проверять payload и экспорт, не только скрытие элементов. |
| Источник: удалить/задержать факты одной метрики, вернуть ошибку или отозвать доступ | Неполный источник → «Нет данных» с причиной, известный пустой → 0; ошибка обновления сохраняет прежний отчёт и время, отзыв доступа скрывает прежние данные. |
| Графики/таблица: клавиатура, телефон, длинный состав и нулевой профиль | Все действия доступны; нулевой профиль остаётся выбранным; таблица прокручивается внутри своего блока без расширения всей страницы. |

Статический r17 проверяет отображение и расчёты на примере. Server/API/RBAC, реальные источники Chats/Pings/финансов и передача профиля принимаются только на именованном стенде по этой карте. Макет сам по себе их готовность не подтверждает.
