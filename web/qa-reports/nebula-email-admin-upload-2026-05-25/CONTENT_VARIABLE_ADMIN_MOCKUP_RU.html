Translation rule

Ключи не переводятся. Переводятся только значения переменных с политиками translate, enum_i18n и locale_phrase. Для HTML-блоков нужен whitelist тегов.

Fallback rule

Если перевод отсутствует, показываем EN master только для безопасных service/admin значений. Для публичного SEO/email текста отсутствие перевода должно попадать в audit.

Where the same key is used

Usage badges должны подтягиваться сканером из email templates, SEO fields, notification templates и global settings. Это защищает от удаления переменной, которая используется в другом контуре.

Context helper

В формах Email templates и Geo SEO нужен не отдельный словарь, а sidebar с доступными переменными, подсказками и статусом перевода из этого центрального раздела.

Resolver order

  • 1. Load template/page/notification context.
  • 2. Resolve configured content variables by locale.
  • 3. Format date, money, duration and enum labels.
  • 4. Validate required keys and block unknown variables.
  • 5. Render final HTML/text and save audit result.

Blocked dependency

{{cityName}}, {{countryName}}, {{serviceName}} and similar keys must not be used as universal inline replacements in SEO sentences. Use localized page fields or complete blocks.

Allowed nested variables

HTML blocks may reference safe config values like {{siteName}} or {{supportEmail}} only if the dependency is declared and tested by the audit.

History

Every value change should keep old value, new value, language, editor, reason and timestamp. This mockup saves local draft history to show the expected UX.

Unknown variablesNo issue in mock data

At save time, forms should reject keys that are not in Content variables or event available_params.
