Реестр переменных и переводимых значений

Факт: ключи переменных переводить нельзя. Переводить нужно только значения тех переменных, которые являются управляемым пользовательским текстом или HTML-блоком. Имена, URL, ID, суммы, даты и значения из user/entity payload не переводятся; они подставляются или форматируются по локали.

79ключей в объединенном реестре
13нужно вынести в i18n/variable panel
10нельзя делать inline-переменными
56не переводить, только подставлять/форматировать

Как реализовать

1. Variable Registry

Одна админ-панель для ключа: key, тип значения, область применения, HTML allowed, fallback locale, статус, владелец, комментарии и usage badges.

2. Translation Values

Для переводимых значений хранить EN master и переводы по языкам. Для enum: хранить код, а label отдавать из словаря. Для HTML-блоков включить whitelist тегов.

3. Resolver

Рендерер получает event/page context, подтягивает значения по locale, проверяет required variables, форматирует даты/деньги и запрещает неизвестные ключи.

Рекомендация: не переводить все переменные в одной таблице как строки. Делить по типам: text/html_block переводятся, enum мапится code -> label, date/money форматируется, url/id/name не переводится.
