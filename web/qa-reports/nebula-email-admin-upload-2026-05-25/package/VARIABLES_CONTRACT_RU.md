# Контракт переменных email-шаблонов

Дата: 2026-05-27

Этот документ выделяет отдельным списком переменные, которые предложены в пакете, но не подтверждены по live-аудиту конкретного шаблона id=1. Это не означает, что их точно нет в production-коде. Это означает, что программист с Codex обязан подтвердить их в актуальном backend-контракте перед импортом.

## Жесткое правило

- Не добавлять произвольные новые переменные в текст шаблона.
- Если переменная отсутствует в доступном списке конкретного template/event, это отдельная backend-задача.
- Для каждой неподтвержденной переменной нужно выбрать: подтвердить в коде, заменить на существующую, убрать из текста или добавить backend-контракт.

## Подтверждено live-аудитом id=1

Подтвержденные в audited template id=1 переменные/блоки:

- confirmUrl
- password
- showPassword
- siteName
- tokenUrl
- userName

Из них текущий RU-пакет использует:

- confirmUrl - email_confirmation
- siteName - advisor_chat_reply_ready, chat_message_received, chat_sla_delay, d2_chat_reflection, email_confirmation, minor_or_age_restriction_notice, paid_chat_no_message_reminder, password_reset, payment_failed, payment_started, payment_success_receipt, refund_case_update, refund_confirmed, review_request, safety_notice, same_advisor_followup_offer, security_change_alert, support_reply, support_ticket_opened
- userName - advisor_chat_reply_ready, chat_message_received, chat_sla_delay, d2_chat_reflection, email_confirmation, minor_or_age_restriction_notice, paid_chat_no_message_reminder, password_reset, payment_failed, payment_started, payment_success_receipt, refund_case_update, refund_confirmed, review_request, safety_notice, same_advisor_followup_offer, security_change_alert, support_reply, support_ticket_opened

Подтверждены в id=1, но текущим RU-пакетом не используются:

- password
- showPassword
- tokenUrl
