Старт внедрения email-шаблонов для Игоря

Это главный вход в пакет. Он объясняет порядок действий для человека-программиста и показывает, какие шаблоны можно переносить в админку сразу, а какие сначала требуют backend-событий, переменных и проверки очереди.

Главное правило: наличие события в dropdown не доказывает, что письмо реально отправляется. Перед импортом каждого шаблона нужно подтвердить три вещи: событие вызывается в коде, payload содержит все переменные, а очередь повторно проверяет состояние перед отправкой delayed-писем.

Как действовать

Открыть эту страницу и не начинать с ZIP

Сначала понять группы внедрения ниже. ZIP нужен для передачи файлов, но решение о порядке внедрения принимается по этой панели.

Проверить текущий механизм EmailTemplate

Найти модель, таблицу, языковые записи, сохранение HTML/TXT, поля event_name, condition_id, delay и фактическую очередь отправки.

Начать с двух существующих live-шаблонов

Сначала обновить регистрацию и подтверждение email, потому что это самые проверяемые сервисные сценарии.

Для остальных идти по статусу

Если событие или переменная отсутствует, не импортировать письмо как готовое. Сначала добавить backend-trigger, payload, queue-binding и suppression-правила.

Проверить RU и EN отдельно

Для каждого импортированного шаблона проверить subject, HTML, TXT, comment, переменные и тестовый render без пустых URL и сломанных блоков.

Готовый prompt для Codex

Ты работаешь в репозитории Confideline. Нужно внедрить пакет email-шаблонов из папки или ZIP.

Маршрут:
1. Открой START_HERE_FOR_IGOR_RU.html и прочитай порядок внедрения.
2. Проверь текущую модель EmailTemplate, таблицу, языковую модель, поля subject_email/body_email_html/body_email_txt/comment_about, event_name, condition_id и delay.
3. Сопоставь ADMIN_UPLOAD_INDEX_RU_EN.json с реальными events, conditions и queue-binding в коде.
4. Для каждого шаблона проверь EVENT_VARIABLE_COMPATIBILITY_RU.csv и IGOR_MISSING_BACKEND_VARIABLES_RU.csv.
5. Шаблоны из блока "обновить существующие" можно внедрять первыми только после проверки render.
6. Шаблоны из блока "сначала backend" не импортируй как готовые, пока не реализованы event, payload и queue-binding.
7. После импорта проверь render RU/EN без пустых ссылок, undefined и сломанных handlebars-блоков.

На выходе дай: что импортировано, что заблокировано backend-доработками, какие файлы изменены, какие проверки выполнены.

Стоп-условия

Не импортировать шаблон как готовый, если нет события в backend, нет источника для обязательной переменной, sanitizer ломает HTML/handlebars, delayed-письмо не проверяет состояние перед отправкой или тестовая отправка может уйти реальному клиенту.
