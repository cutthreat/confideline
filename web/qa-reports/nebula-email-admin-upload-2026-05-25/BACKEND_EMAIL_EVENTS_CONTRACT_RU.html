Фактический backend-контракт email-уведомлений

Сверка предложенного комплекта с реальными event_name, available_params и condition_id, которые сейчас есть в механизме email-шаблонов.

Conditions10
Шаблонов в пакете19
Совместимы без новых params2

Вывод для внедрения

Механизм работает как комбинация: event_name + condition_id + delay. На каждую значимую комбинацию создается отдельный EmailTemplate. Для user.register допустимы отдельные follow-up шаблоны с условиями NOT_LOGGED_1_DAY, NOT_LOGGED_3_DAYS, NOT_LOGGED_7_DAYS.

Для текущей продуктовой модели онлайн чат-консультации часть предложенных писем требует не только загрузки HTML, но и расширения backend payload: chatUrl, advisorName, consultationId, checkoutUrl, receiptUrl, supportCaseId, refund/status context.
