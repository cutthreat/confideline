Для Игоря

FAIL

PHOTO-ACCESS-ACTION-NO-REQUEST-SUCCESS-001

Факт: если вызвать /en/settings/photo-access-action для пользователя, у которого нет существующего photo access request к текущему владельцу, сервер все равно возвращает {"success":true}.

Ожидание: если request не найден и PhotoManager::approveOrRejectPhotoAccess() возвращает false, controller должен вернуть ошибку/404/validation JSON, а не success.

Как воспроизвести: войти как U166, убедиться на /en/settings/access-requests, что U184 отсутствует в списке, затем POST /en/settings/photo-access-action?fromUserId=184&action=1.

Где смотреть: application/controllers/SettingsController.php::actionPhotoAccessAction() и application/managers/PhotoManager.php::approveOrRejectPhotoAccess(). Сейчас controller игнорирует boolean result manager-а.

Ретест: для отсутствующего request endpoint должен вернуть отказ; approve/reject для существующего request должны продолжить работать.

PASS

PHOTO-ACCESS-APPROVE / REJECT

Факт: happy path approve/reject не сломан: запросы создаются, владелец видит их в access requests, действия owner-side отвечают success.

Не чинить как дефект: сам базовый механизм approve/reject работает. Исправлять нужно только false-success edge case.
