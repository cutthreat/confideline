ТЗ: переводчик в чате экспертной админ-панели

Публичная HTML-версия технического задания для программиста. Это тот же самый контент по интеграции переводчика в Confideline, но в удобном для показа и обсуждения виде.

Основное ТЗ

Result

  • В админ-чате эксперта появляется действие Translate, которое переводит входящее сообщение через выбранный провайдер.
  • В админке появляется системный раздел Translator settings, где администратор включает и выключает переводчик и хранит ключи провайдеров.
  • Архитектура сразу допускает три провайдера: DeepL, Google Cloud Translation, Amazon Translate.

Scope

  • Контур: Yii2 admin module.
  • Чат эксперта: /en/admin/message/chat.
  • Настройки: admin/settings/translator.
  • Локальный исходник для разработки: H:\GPT-Codex\Confideline\Chat\youdate-2.0.2-yii2\Source\youdate_extracted\application.

Функциональные требования

1. Настройки переводчика
  • Добавить страницу Translator settings.
  • Поля: глобальный enable, default provider, fallback, cache, target language, блоки ключей для DeepL, Google и Amazon.
  • Доступ только для Admin.
  • Если глобальный флаг выключен, кнопка перевода в чате не показывается.
2. Перевод в чате эксперта
  • Кнопка Translate размещается внутри карточки входящего сообщения.
  • Показывается только для текстовых входящих сообщений и только если глобально включен переводчик.
  • По клику отправляется AJAX-запрос на отдельный admin-endpoint.
3. Отображение результата
  • Под оригинальным текстом появляется вторичный блок перевода.
  • В блоке есть translated text и мета-строка: provider, source language, target language, translated at.
  • Оригинальный текст всегда остается основным.
4. API и backend-контракт
  • Новый endpoint: POST /admin/message/translate.
  • Вход: messageId, опционально provider, опционально targetLanguage.
  • Выход: success, translation, provider, sourceLanguage, targetLanguage, cached, translatedAt.

Данные и хранение

  • Рекомендуемая таблица: message_translation.
  • Поля: message_id, provider, source_language, target_language, source_text_hash, translated_text, raw_response, timestamps.
  • Перевод хранится как производный артефакт, а не как замена оригинального сообщения.

Краткое резюме

Facts
  • В проекте уже есть `SettingsAction` и механизм хранения системных настроек.
  • Чат эксперта уже переведен на shell-интерфейс с endpoints `conversations`, `messages`, `send`.
  • В админке уже есть системный раздел `Settings`, куда логично встраивать переводчик.
Inference
  • Переводчик нельзя класть в `Languages`, потому что это каталог языков сайта, а не runtime-интеграция.
  • Переводчик нельзя прятать только внутри чата, потому что ключи и режимы работы должны жить на системном уровне.
  • Базовый UX должен быть двухуровневым: системный пункт меню и кнопка перевода внутри bubble сообщения.
Recommendation
  • DeepL использовать как default provider.
  • Google и Amazon держать как fallback-ready интеграции.
  • Исходное сообщение никогда не перезаписывать переводом.

Done when

В админке есть отдельный пункт Translator, настройки сохраняются штатным Yii2 settings-механизмом, а в чате на входящем сообщении можно вызвать перевод без изменения оригинального текста.

How to verify

  • Открыть admin/settings/translator под `Admin`.
  • Сохранить настройки и проверить повторное чтение значений.
  • Открыть /en/admin/message/chat.
  • Проверить кнопку Translate на входящем сообщении.
  • Проверить, что перевод появляется как отдельный блок под оригиналом.
