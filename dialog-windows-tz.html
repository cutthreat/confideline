Техническое задание по унификации диалоговых окон Confideline

Документ подготовлен по структуре и уровню детализации, аналогичным образцу Google Doc “ТЗ 11 - разработка доски объявлений на сайте”, но применительно к фронтовым и административным диалоговым окнам.

Проект: Confideline / YouDate Yii2 Дата: 06.04.2026 Основание: текущий live + локальный Yii2 source

Описание задачи

Необходимо привести к единому визуальному и поведенческому стандарту все диалоговые окна и уведомления на сайте Confideline: как на пользовательском фронте, так и в административной панели Yii2. Сейчас окна используют разные стили, разные механики вызова и разный уровень информативности. Требуется описать все найденные сценарии, задать единый шаблон, определить состояния окна и дать HTML-шаблоны для внедрения.

Цель и ожидаемый результат

1. Инвентаризация

Получить полный перечень диалоговых окон: где находятся, когда появляются, каким кодом вызываются и какой тип действия подтверждают.

2. Единый стиль

Задать общий визуальный язык для модалок, confirm-окон, flash-alert и toast-уведомлений с едиными цветами, кнопками, иконками и отступами.

3. Внедрение

Подготовить HTML-шаблоны и правила интеграции в Yii2 admin asset layer и в пользовательский шаблон без точечной ручной переписи каждой view.

Текущая проблема

Факт

  • В админке одновременно используются `data-confirm`, `bootbox.confirm`, прямой `window.confirm`, Bootstrap modal, flash-alert и Messenger.
  • На фронте подтверждены отдельные модалки для upload/premium и отдельные inline alert-блоки.
  • Сейчас разные сценарии показывают разные размеры окна, кнопки, цвета и плотность текста.

Следствие

  • Пользователь не получает единый паттерн поведения.
  • Администратор видит смесь браузерных confirm-окон и кастомных модалок.
  • Доработка становится дорогой, если менять каждую точку вызова вручную.

Требования к новому стилю

Красное состояние

danger

  • Ошибки
  • Удаление
  • Блокировка
  • Необратимые действия

Синее состояние

info

  • Нейтральная информация
  • Предупреждение о переходе
  • Служебные окна и подсказки

Зелёное состояние

success / important

  • Подтверждение
  • Верификация
  • Выдача прав
  • Важное действие с позитивным исходом

Единые визуальные правила

  • Скругление окна: 12-14 px
  • Тень: мягкая, глубокая, без чёрного “грязного” контура
  • Заголовок: 21-24 px, semibold/bold
  • Тело текста: 15-16 px
  • Кнопки: pill shape, одна главная, одна вторичная
  • Слева обязательна круглая иконка состояния

Поведенческие правила

  • `data-confirm` должен отрисовываться через общий JS helper, а не браузерный native dialog.
  • Прямые `window.confirm` должны быть заменены на общий helper.
  • Flash alerts и Messenger должны использовать ту же цветовую семантику, что и модалки.
  • На фронте и в админке должен сохраняться один язык компонентов, даже если стек плагинов отличается.

HTML-шаблоны

Ниже приведены шаблоны для confirm/error/info/important, которые можно использовать и во фронте, и в админке.

<div class="cfd-dialog__body">
  <span class="cfd-dialog__icon">
    <i class="fa fa-info-circle"></i>
  </span>
  <div class="cfd-dialog__copy">
    <p class="cfd-dialog__message">
      Вы действительно хотите удалить это сообщение?
    </p>
    <p class="cfd-dialog__hint">
      Действие выполнится сразу и без дополнительного шага.
    </p>
  </div>
</div>
Подтвердите действие

Вы действительно хотите удалить это сообщение?

Действие выполнится сразу и без дополнительного шага.

Upload error

Файл “video.mp4” слишком большой. Допустимый размер не должен превышать 30 MiB.

Выберите другой файл или сожмите текущий перед повторной загрузкой.

Использовать для ошибок, удаления, блокировки и необратимых действий.
Информация

У вас есть несохранённые изменения. При переходе они будут потеряны.

Использовать для нейтральных предупреждений и служебных пояснений.

Важное действие

Вы уверены, что хотите подтвердить аккаунт пользователя?

Использовать для подтверждения, верификации и выдачи прав.

Техническая реализация в Yii2

Факт

  • В админке уже есть `bootbox.min.js`, `BootstrapAsset`, `BootstrapPluginAsset`, `YiiAsset`, `FontAwesome`.
  • Следовательно, безопасно централизовать confirm-окна через переопределение `yii.confirm`.
  • Прямые `window.confirm` остаются только в отдельных JS-файлах и подлежат адресной замене.

Что нужно внедрить

  • Подключить общий CSS для `modal`, `bootbox`, `alert`, `messenger`.
  • Добавить общий JS helper с методами `confirm()` и `alert()`.
  • Переопределить `window.yii.confirm`.
  • Заменить оставшиеся прямые `window.confirm` в custom JS.
В локальной реализации это уже вынесено в `modules/admin/static/css/admin-dialogs.css` и `modules/admin/static/js/admin-dialogs.js`, а также подключено в `modules/admin/assets/AdminAsset.php`.

Критерии приёмки

  1. Все административные `data-confirm` больше не показывают нативное браузерное окно.
  2. Все delete/block/irreversible сценарии используют красное состояние с иконкой.
  3. Все neutral/info сценарии используют синее состояние.
  4. Все confirm/verify/grant-access сценарии используют зелёное состояние.
  5. Flash alerts и Messenger соответствуют той же цветовой системе.
  6. Фронтовые окна upload/info визуально совпадают по языку компонентов с админкой.
  7. Поведение и внешний вид одинаковы на desktop и mobile.
