## Macro resolver implementation (2026-08-16)

`m260816_110000_migrate_chat_message_template_macro_names` makes the approved
one-time source change in both `body_ru` and `body_en`:

- `client_first_name` → `client_name`;
- `expert_public_name` → `expert_name`;
- `consultation_price_credits_per_minute` → `price_min`;
- `trial_minutes` → `trial_min`;
- `consultation_date_local` → `consult_date`;
- `consultation_time_local` → `consult_time`;
- `client_timezone` → `timezone`.

`pause_deadline_local` intentionally has no replacement in the canonical
short list. The migration does not destroy such source text; the catalog hides
that template until an administrator rewrites it.

The resolver currently has these authoritative sources:

- `client_name`: first part of the client's public profile name, otherwise
  their public username;
- `expert_name`: represented Expert's public profile name only, never the
  internal operator;
- `price_min`: frozen `pricing_snapshot_json` for an open session, otherwise
  the current settings-backed effective rate. The current local product has a
  global rate, so per-Expert pricing remains a future source rather than a
  fabricated value;
- `trial_min`: an open session's frozen trial snapshot or the existing
  one-per-client entitlement resolver;
- `timezone`: validated client profile timezone;
- `consult_date` / `consult_time`: the actual `started_at` of a live
  consultation, localized to the client timezone. There is no appointment
  scheduler in this product, so they are unavailable before actual start;
- `topup_link`: the existing authenticated server route to `/balance/buy`.

There is still no exact client deep link to a selected conversation/session
and no authoritative new support route. Therefore `consult_link` and
`support_link` are deliberately unavailable; a template using either is not
shown. This is fail-closed, not a missing raw URL fallback.

The source editor rejects raw URLs and HTML. The catalog returns metadata only
after checking every source macro in the current conversation. Template
selection resolves the draft server-side; normal Chat V2 send, edit, image
caption and generic attachment caption forms reject raw `{{...}}` tokens, so a
forged browser request cannot send an unresolved placeholder. The resolver
caches values inside the small catalog pass, avoiding repeated entitlement or
profile queries for several templates.

## Recommended implementation order

### 1. Product-alignment safety patch

No new table is needed:

- turn the four deferred workflow controls into disabled/feature-flagged UI;
- reject their mutation endpoints and stop automatic workflow transitions;
- audio/voice removal is **not** included in the current local patch: the
  implementation owner chose to retain it temporarily despite the package;
  record and reconfirm this production-policy divergence later;
- add the active paid/pause reassignment guard.

This is the safest immediate block because it prevents behavior that the new
Product Owner package explicitly forbids without destroying historical data.

### 2. Finish templates on the approved lean model

- Expert-scoped template management is implemented under assignment/permission checks;
- RU fallback, language-mismatch prompt, conversation-level effective-language
  override and its small Chat setting are implemented;
- the short canonical macro migration/resolver and raw-placeholder send guard
  are implemented;
- later product work must provide per-Expert pricing (if prices diverge), an
  appointment source, exact client session deep link and support route before
  templates that require those values can appear.

### 3. Message-history and mutation correction

- allow permitted Expert-message edits after read and derive the client
  `edited` marker from the pre-edit read position;
- keep old versions for super-admin readback;
- replace ordinary operator delete with a staff hide command requiring reason
  and audit;
- design immutable assignment/policy readback without relying on a physically
  deleted `chief_under` row.

### 4. Production security boundary for content

- centralize document/image limits in Chat settings;
- define a quarantine/inspection status and adapter boundary;
- integrate approved malware plus QR/OCR/contact-data inspection before
  enabling broad production attachments;
- implement message censorship as one server policy, safe recipient payload
  and audited original—not a browser-only text replacement.

Steps 3 and 4 are larger than a visual iteration and need their own migration,
ACL, idempotency and runtime proof plan.

## Open implementation gates

- Existing historical audio/voice messages must be retained; the package does
  not state whether ordinary users may still play them after the ban. Safest
  default is no new upload and no normal-user playback, with audit access
  preserved for super-admin until a retention decision.
- There is no AV/OCR/QR provider in the local application. The contract
  requires an explicit scan/quarantine decision before production document
  delivery; MIME validation alone must not be represented as completion.
- Full historical readback requires an assignment/policy snapshot strategy.
  Current messages preserve the actual actor but not enough to recover a
  deleted/reassigned `ChiefUnder` relation reliably.
