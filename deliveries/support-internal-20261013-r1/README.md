# Внутренний чат: пакет для Игоря

Редакция передачи: 21.10.2026, исправлена изоляция CSS. Начните с [index.html](index.html): пять макетов, входы по ролям, ТЗ и архив. Это интерактивная верстка и требования к результату, не готовый backend.

## Граница CSS И Подложки

Работаем только с кнопкой запуска, панелью чата, его диалогами и уведомлением. Стили нового функционала: `developer/css/internal-widget.css` и последующий `developer/css/internal-widget-adapter.css`. Все селекторы ограничены корнями виджета; адаптер не является альтернативным дизайном.

Не подключать вместе с виджетом `css/custom.css`, `vendor/`, `references/`, `js/custom.js`, `js/demo-shell.js` и `js/chat-header-preview.js` как обновление всего сайта. Это исходная подложка и демонстрационные зависимости. В рабочем проекте используются существующие ресурсы и текущий layout. `demo-shell.js` меняет только подписи тестовой роли и блокирует посторонние переходы в статическом примере; контроллер виджета не переписывает профиль в шапке и не задаёт права фоновой странице.

Исходные `custom.css`, vendor CSS и стили Chat V2 сохранены без нормализации и переписывания. Шапка, боковое меню и футер в подложках восстановлены из предоставленных HTML. Существующие инструменты оператора в Chat V2 сохранены; новых правил для их оформления в CSS виджета нет. Изменения общего layout отдельно согласовываются, не следуют из этого макета.

На приёмке сравнивать фон без новых стилей и с ними, при открытии/закрытии и изменении ширины. Внешние области и их собственные состояния не должны меняться. На мобильном допустима временная блокировка фокуса фона для модального виджета; исходный `inert` восстанавливается. Глобальная блокировка `overflow`, смена классов/стилей `body` и оформление чужих `.cl-i-*` элементов не применяются.

## Названия и сценарии

Виджет — «Внутренний чат». Вкладки: «Тикеты» и «Рабочие чаты».
Агент/эксперт создает обращение в «Тикетах» либо выбирает сотрудника по никнейму и общается без тикета в «Рабочих чатах». Сотрудник может первым написать доступному агенту. Клиент в админку не входит.

## Внедрение

Черновик формального ответа хранит question_id и revision назначения. Отмена/переназначение во время набора блокируют отправку с явным конфликтом; текст и связь не сбрасываются. Превращение в обычное сообщение — только отдельный выбор. Служебная история содержит вопрос, адресатов, приватную причину, автора и время; участнику причина не выдается.

Support подключает агента/эксперта к тикету независимо от автора. Переписки аудиторий разделены. Связанный ответ, отмена, продолжение ожидания и переназначение сохраняют исходный вопрос и срок. Стартовая гипотеза: напоминание через 12, срок ответа 24 календарных часа; настройки влияют только на новые внутренние вопросы. SLA и отдельное окно подтверждения решения не заменяются. Тестового пульта в интерфейсе нет; настройка сроков относится к существующим настройкам Support.

В «Действиях» остаются подключение агента/эксперта, запрос ответа, открытие проверенного клиентского канала, отправка решения и исключительное закрытие без решения. Заметки, обновление автору и запросы операций доступны через «Сведения о тикете». У каждой аудитории своё поле итога. Ролевой вход сотрудника использует подложку очереди, как вход агента; исходная карточка Support не перерабатывается.

Полная тема открывается нажатием без расширения шапки; агенту выдаются только безопасные сведения своего тикета. Над лентой остаются ожидающие вопросы. Меню сообщения учитывает края ленты, клавиатуру и закрытие по клику снаружи.

ТЗ содержит датированную сверку существующего Support и конкретный checklist внедрения. Приоритеты Support и Chat V2 требуют согласования серверного intake. Права автора на приёмку/возврат решения проверяются в текущем checkout, а не выводятся из demo authorCapabilities. Критерии приемки и границы подтвержденного результата — [developer/ACCEPTANCE.md](developer/ACCEPTANCE.md).

Переиспользовать принятый YouDate/AdminLTE layout и компоненты Support/Agent Chat. Не менять фоновые страницы; убрать исходную вкладку Internal из карточки и подключить сквозной виджет. Сохранить серверные audience/membership, вопросы, lifecycle/SLA и защищенные запросы. Личные рабочие пары и actor-scoped summary требуют отдельного серверного контракта, не копии полного Support DTO.

Подключенные стили виджета — `developer/css/internal-widget.css` и отдельный scoped-адаптер `developer/css/internal-widget-adapter.css`, поведение — `developer/js/internal-widget.js`, модель демонстрационных вопросов — `developer/js/ticket-policy.js`. `references/` содержит только зависимости примера Chat V2; это не второй макет и не альтернативная реализация виджета. `THIRD-PARTY-NOTICES.md` сохраняет сведения об исходных библиотеках.

internal-widget.js использует синтетические роли, ID и localStorage. Это демонстрационный controller, не production auth/API. CSP/custom.js ограничивают demo-операции, не задают production security. Реальные права, transport, retries, upload/scan, платежи и service_session этим пакетом не проверены.

Из корня распакованного комплекта: `node developer/tests/policy.test.cjs` (23 проверки модели) и `node developer/tests/draft-conflict.test.cjs` (8 проверок конфликтов). Это не HTTP/RBAC/транзакционная приемка. При ошибке storage текст сохраняется в памяти вкладки, но перезагрузка при недоступном storage не гарантирует восстановление. Текущая демонстрация использует отдельное хранилище и не импортирует данные прошлых тестовых запусков.

Для совместного просмотра двух ролей нужен один HTTP origin. Отдельный file://-просмотр возможен, но браузер может ограничивать storage; запускать обычный локальный static server. Виджет не добавляет CDN. В оригинальном AdminLTE сохранён прежний внешний @import Inter с rsms.me; без сети применяется исходный font stack. Эта зависимость подложки не является новой настройкой шрифтов проекта. Production AssetBundle/шрифты не менять из-за демонстрации.

ZIP содержит те же макеты, зависимости, ТЗ в Markdown/HTML, критерии приемки, тесты, README, notices и MANIFEST.json. Манифест фиксирует размер и SHA-256 каждого файла, кроме самого манифеста и ZIP. Архив содержит манифест, но не самого себя. Рабочая память, история обсуждений, скриншоты, внутренние QA-отчеты и резервные копии в поставку не входят.
