## Условия допуска и состояния

| Состояние | Условие | Клиент | Эксперт / публичный профиль | Администратор |
| --- | --- | --- | --- | --- |
| Недоступно | Сессия не завершена, не принадлежит клиенту, бесплатная или уже имеет отзыв | Кнопки отзыва нет; прямой запрос отклонен | Ничего | Видит техническую причину только при наличии права |
| Доступно | Собственная завершенная платная сессия, допустимая для отзыва | Может открыть форму | Ничего до публикации | Видит запись после отправки |
| Опубликовано | Отзыв сохранен и не скрыт/не удален | Видит свой отзыв и факт отправки | Входит в список и рейтинг | Может скрыть или удалить с причиной |
| Скрыто | Модератор временно снимает публичную видимость | Видит уведомление о статусе своего отзыва, без возможности создать второй | Не входит в список и рейтинг | Может вернуть публикацию; история причины сохранена |
| Удалено | Модератор принимает окончательное решение | Видит уведомление, что публикация удалена; второй отзыв на ту же сессию не создается автоматически | Не входит в список и рейтинг | Хранится аудит действия, автора и причины; исходный текст не возвращается публично |

## Рекомендация PM по спорным правилам

1. **Публикация:** Заказчик 30.09.2026 подтвердил публикацию сразу после серверной валидации, с последующей модерацией. Рейтинг меняется по опубликованным отзывам. Премодерация каждого отзыва на старте не требуется.
2. **Редактирование:** не разрешать редактировать уже отправленный отзыв в первой версии. Это сохраняет правило «одна консультация — один отзыв» и не меняет историю рейтинга без отдельной политики.
3. **Возврат:** до принятия правила возврат сам по себе не удаляет отзыв. Уполномоченный модератор получает основание для пересмотра; финансовая операция и изменение рейтинга остаются разными действиями.
4. **Удаление:** технически soft-delete с неизменяемой аудит-историей; публичный API не отдает текст или идентификатор удаленного отзыва.

Решение о порядке публикации принято. Скрытие/удаление и журнал являются обязательными действиями для уполномоченного модератора.

## Данные и серверные правила

| Сущность / поле | Правило |
| --- | --- |
| `review.id` | Неизменяемый идентификатор отзыва |
| `consultation_id`, `client_id`, `expert_id` | Проставляются сервером из допустимой завершенной сессии, не принимаются как доверенные значения клиента |
| `stars` | Целое 1--5; обязательное |
| `text` | Необязательный либо ограниченный серверным лимитом; безопасно экранируется при отображении |
| `status` | `published`, `hidden`, `deleted`; при премодерации добавляется `pending` |
| `moderation_reason`, `moderated_by`, `moderated_at` | Обязательны при `hidden`/`deleted` |
| Уникальность | Уникальный индекс по `consultation_id`; повторный POST возвращает существующий результат, не второй отзыв |

Рейтинг эксперта: `avg(stars)` и `count(*)` только для `published` отзывов. Скрытие, удаление и восстановление выполняют пересчёт в той же транзакции или из проверяемой очереди с немедленным статусом пересчёта. При нуле опубликованных отзывов карточка и профиль показывают честное пустое состояние, а не `0.0`, `4.8`, фиктивное число отзывов или текст из макета.

## Права

| Роль | Разрешено | Запрещено |
| --- | --- | --- |
| Клиент | Создать отзыв только по своей допустимой сессии; читать опубликованные отзывы | Создать повторный, писать за другого, модерировать, читать скрытый/удаленный текст |
| Эксперт | Читать только публичный агрегат и опубликованные отзывы о себе | Изменять/скрывать/удалять отзыв, видеть клиента через скрытые данные |
| Модератор отзывов | Просматривать, скрывать/восстанавливать с причиной | Выполнять возврат из карточки отзыва без отдельного денежного полномочия |
| Администратор | Те же действия в пределах permissions, аудит решений | Обходить журнал и серверные ограничения |

Проверка делается на сервере для UI и прямых запросов. Решение о возврате создаёт связанный запрос Support, а не денежную операцию внутри отзыва.

## UI и сценарий

1. На завершенной сессии доступно `Write a review`; в модальное окно передаются только серверно подтвержденные `consultationId` и `expertId`.
2. Клиент выбирает 1--5 звезд, при необходимости пишет текст, отправляет. Закрытие окна не создаёт отзыв.
3. При успехе форма подтверждает сохранение и больше не предлагает второй отзыв по этой сессии. При неизвестном результате клиент сначала получает статус существующего отзыва, а не повторную отправку.
4. Кнопка жалобы из этого экрана открывает один связанный Support-тикет; она не скрывает отзыв и не выполняет возврат.
5. Профиль и карточка эксперта используют один агрегат и один публичный список. Демо-числа макета не переносятся в production.
