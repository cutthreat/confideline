# #62: пункт 6 для Игоря

Редакция `reviews-rating-20261008-r3`, 08.10.2026. Требование владельца: «Добавить в админ-панель возможность задать рейтинг, количество голосов, написать отзыв от лица выбранного профиля.» Это дополнение к r2, не перепроектирование YouDate. Макеты используют прежнюю оболочку админки и анкеты.

## Экран И Действия

| Экран | Действие | Системный результат |
| --- | --- | --- |
| Отзывы экспертов | Выбрать эксперта | Таблица, счётчики и агрегат относятся только к этому эксперту. Фильтры сбрасываются. |
| Задать рейтинг | Выбрать «Задать вручную», заполнить рейтинг, голоса, причину; сохранить | Сохраняется точная пара и режим manual. Показываются отдельно эффективные данные и фактические опубликованные отзывы/средняя. |
| Задать рейтинг | Вернуться к «По опубликованным отзывам»; указать причину; сохранить | Override отключается; текущие опубликованные оценки формируют среднюю и голоса. |
| Добавить отзыв | Выбрать существующий профиль автора; оценку 1--5; текст и основание; опубликовать | Создаётся опубликованный отзыв для выбранного эксперта и автора. Источник admin; фактический actor - администратор сессии, не выбранный автор. |
| Таблица отзывов | Скрыть/восстановить/удалить административный отзыв с причиной | Прежняя модерация и аудит. Auto пересчитывается; manual остаётся неизменным. |
| Любая форма | Отмена/крестик/Escape/ошибка | Нет записи, нет изменения агрегата, нет аудита успешного действия; фокус возвращается к кнопке открытия. |
| Анкета | Просмотреть эффективный рейтинг | При положительных голосах видны звёзды, рейтинг и число голосов; при нуле вся строка скрыта без зазора. Список отзывов независим. |

## Числа И Расчёт

- Режим `auto` по умолчанию: средняя оценка всех опубликованных отзывов данного эксперта, округление до одного десятичного знака; голоса = число таких отзывов. Административный опубликованный отзыв входит наравне с клиентским, скрытый/удалённый не входит.
- Режим `manual`: точные `rating` и `vote_count`, без взвешивания или сложения с auto. Это один override, не накопительная прибавка. Число голосов не обязано совпадать с числом текстовых отзывов.
- Рейтинг 1.0--5.0, не более одного десятичного знака; в UI допустима запятая. Голоса - целое неотрицательное число. В макете предел Number.MAX_SAFE_INTEGER; реальный предел DB/API Игорь согласует до реализации и применяет одинаково на клиенте и сервере.
- Ноль голосов допускается и сохраняет `rating=null`; поле рейтинга недоступно. Отдельная оценка 0 или 5.1 недопустима. `auto` не валидирует неиспользуемые manual-поля.
- Модерация/новый отзыв обновляет фактический auto-агрегат, но не переписывает manual. Переключение обратно в auto учитывает все текущие статусы, не снимок на момент включения override.
- Ноль эффективных голосов скрывает строку рейтинга даже при наличии отзывов. Положительный manual допускает рейтинг при пустом списке отзывов; вместо фиктивных строк остаётся пустое состояние списка.

## Данные И Права

Имена полей ниже - семантический контракт, не подтверждённые имена таблиц Yii2.

| Сущность | Обязательная семантика |
| --- | --- |
| Rating override | expert_id, mode, rating nullable, vote_count nullable, version, updated_by_actor_id, updated_at |
| Admin review | expert_id, author_profile_id, stars, text, source=admin, consultation_id=null, status=published, created_by_actor_id, created_at |
| Audit | operation, target/expert, selected author (для отзыва), actor из auth-сессии, before/after, reason, timestamp, request/idempotency ID |

Отдельные серверные права: управление override и создание admin-review; существующее право модерации не означает автоматически оба новых права. Привязать к реальному RBAC проекта; названия permission/role в макете не являются решением о выдаче доступа. Клиент, эксперт и администратор без соответствующего права получают отказ на прямой API-запрос, не только скрытую кнопку. Объектный scope эксперта также проверяется сервером.

Выбранный профиль должен существовать и быть допустимым автором по серверной политике. Поиск/выбор - по стабильному ID с отображаемым именем, не произвольная строка. Не выполняются Login as user, смена сессии, подделка actor, консультации, оплаты или согласия. Публичный административный отзыв получает отметку «Добавлен администратором», а не «После завершённой консультации». До production подтвердить основание/право на публикацию от имени профиля; интерфейс сам это не доказывает.

Клиентский путь не расширяется: только собственный отзыв за допустимую завершённую оплаченную консультацию, один на consultation; отзыв без текста по baseline остаётся допустимым. Административный путь отделён: текст 1--1000 символов, выбранный автор и основание 1--500 обязательны, нет вымышленного consultation_id. Правило «один отзыв на консультацию» не должно запрещать все admin-review из-за NULL; нужна корректная условная уникальность для client-source.

## Серверная Реализация

- Два отдельных административных действия: обновить/отключить override и создать admin-review. CSRF, серверная валидация, RBAC, объектный scope, безопасный вывод текста и стандартные ошибки Yii2 обязательны.
- В одной транзакции сохранять изменение и аудит; сбой записи не должен оставлять половину операции. При создании admin-review пересчитать auto либо инвалидировать его кеш; effective aggregate использует режим override.
- Идемпотентность повторного submit на уровне сервера: один request key даёт один отзыв/изменение и один результат. UI-проверка закрытого диалога в макете не доказывает серверную защиту от гонок.
- Optimistic version/конфликт обновления: не терять параллельные изменения silently. Устаревшие данные вернуть в UI с возможностью перечитать, не перезаписывать автоматически.
- Ответ после сохранения содержит canonical effective aggregate, actual aggregate, persisted review/override version и audit identity. Анкета и админка production читают единый источник, обновляют кеш согласованно.
- Уведомления от добавления admin-review не реализованы/не санкционированы макетом. Их политику, шаблоны и получателей согласовать отдельно; не выдавать этот путь за сообщение от вошедшего клиента.

## Границы Макета

`reviews-admin-panel-20260930.html` - актуальная админка r3; имя файла сохранено для совместимости ссылок. В нём два тестовых эксперта, три профиля автора и независимое состояние в памяти страницы. Ничего не отправляется на сервер, профиль не переключается, состояние сбрасывается reload. `reviews-rating-model.js` общий для валидации/admin и публичного примера. Публичные URL-параметры демонстрируют только состояния макета, не служат production API.

Кнопка со стрелкой открывает анкету с текущими manual rating/votes; она не переносит созданные отзывы и не является E2E синхронизацией. В индексе есть отдельные фиксированные примеры admin-review, manual без отзывов, zero votes и обычного client-path. Не внедрять query-параметры как источник реального рейтинга.
