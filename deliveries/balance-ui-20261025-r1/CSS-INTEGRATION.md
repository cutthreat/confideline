# CSS: отличия источников и границы правок

Решение владельца: styles за пределами поставленной области не менять. global_custom не редактировать, архивную шапку баланса не переносить. Отдельная страница сохранена по прямому поручению; её наличие не дефект.

Датированная сверка v9 от25.10.2026: balance_custom.css, transactions_custom.css, order_custom.css и partner_custom.css совпали с файлами действующего сайта. Их hashes — SOURCE.json / customer_site_css. Боевой сайт дополнительно использует financial-adapter.css, отсутствующий в архиве02.10. Он влияет на таблицы, owner, даты и пагинацию; сравнивать cascade, порядок assets и DOM. Не удалять адаптер и не переписывать совпадающие файлы ради внешнего сходства.

В старой поставке global_custom менял шапку баланса; более поздний документ заказчика20.10 и правило владельца требуют сохранения общей шапки. Эта поставка не содержит правок общей оболочки. Сохранены текущие исходные site/vendor CSS и библиотеки для автономного просмотра; в preview они лежат побайтно без модификаций, это не файлы для замены сайта.

Единственный поставляемый дополнительный CSS — integration/payout-feature.css, прежний согласованный слой для карточки выплаты/реквизитов, ограниченный .cl-my-payouts. Корень только внутри функционального содержимого. История и остальные таблицы используют существующие стили сайта. Нет нового общего CSS для финансов, минификации или объединения vendor-файлов.

preview/shared/period-preview.css (в assets) и локальные JS нужны только для независимого просмотра фиксированных строк. Для production повторно использовать текущий общий компонент периода; второй календарный CSS не создавать. EN-показ только заголовков, не новая полная локаль.

Сверка CSS заказчика с сайтом датирована исходным аудитом v9, а не заявляется новым live-аудитом сегодняшней реализации. При внедрении Игорю сверить текущие версии assets и тот же viewport; неожиданные изменения за пределами контейнера устранять локальным адаптером, не global_custom.
