# Списки клиентов и экспертов

Редакция 9 от 10.11.2026. Начни с [основного ТЗ для Игоря в Google Docs](https://docs.google.com/document/d/16Ogc9FnUUOMAKoHERz4bEqezbzjqsn4R91KFPH2SU_w/edit). Для работы с архивом используй [снимок той же редакции](../TZ.html). Если текст в Google Docs изменился после публикации, сначала сверь редакцию и актуальность приложений.

| Раздел ТЗ | Что использовать при реализации и проверке |
| --- | --- |
| [1. Клиенты](../TZ.html#clients) | Источники и отображение столбцов из таблицы раздела 1. Проверь значения аккаунта, дату в поясе отображения, ноль и отсутствие данных по пункту 1 приёмки. |
| [2. Эксперты](../TZ.html#experts) | Источники из таблицы раздела 2 и правила идентификаторов из технического приложения. Проверь создание анкеты, поиск по дополнительному городу в свёрнутой строке и назначение через ChiefUnder по пунктам 2–3. |
| 3. Общие правила | Проверь отбор по типу записи, права по роли и по конкретной записи, сортировку при открытии и сбросе, пересчёт выдачи после действий и изоляцию CSS. Пункты 3–5 приёмки. |
| 4. Приёмка на тестовом сайте | Пройди пункты 1–5 из [таблицы приёмки](../acceptance.xlsx) и приложи результаты, снимки обоих списков и открытые замечания. |

Работай по инструкциям репозитория продукта. Макеты [клиентов](../preview/clients.html) и [экспертов](../preview/experts.html) задают внешний вид. Демонстрационные данные и скрипты относятся к макетам. Используй штатные стили админки. Новые правила подключай отдельным файлом на целевых страницах и ограничивай контейнерами списков и форм.

Перед переключением передай владельцу продукта найденные спорные ID по правилам раздела 3. Для создания эксперта переиспользуй действующую форму согласно разделу 2 и сохраняй тип анкеты при создании. Используй тип, права и идентификаторы из основного ТЗ при проверке прямых переходов и серверных операций.
