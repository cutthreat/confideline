# Отзывы #62: r4, роли, анонимность и политика публикации

Дата: 08.10.2026. Это дополнение имеет приоритет над r3 POINT6-HANDOFF.md и унаследованными CONTRACT.md/HANDOFF.md в части изменённых сценариев. r3 остаётся неизменной исторической поставкой.

## Граница поставки

Это исполняемый статический макет и контракт для реализации Игорем. Боевой сайт, Yii2, база данных и реальные роли не изменены и не проверены. `?role=` переключает только демонстрационный экран: это НЕ авторизация. Нельзя переносить клиентскую проверку ролей или localStorage в production как механизм безопасности.

Обычные страницы одной поставки/одного origin разделяют только синтетические данные в ключе `confideline_reviews_r4_synthetic_v1`. Reload сохраняет демосостояние. Query fixtures `reviews=empty` / `ratingMode=manual` / `moderation=off` изолированы в памяти текущей страницы. Никакие cookies, сессии или данные реальных клиентов не используются. Данные макета не отправляются на сервер.

## Права

В админке ровно три страницы: **Отзывы** (модерация), **Написать отзыв** (супер-администратор), **Настройки отзывов** (супер-администратор). Переключатель модерации и управление рейтингом находятся только на третьей странице, не в очереди и не в форме создания. Прямой URL любой из двух закрытых страниц запрещён модератору.

| Действие | Клиент | Модератор | Супер-администратор |
| --- | --- | --- | --- |
| Оценить свою завершённую консультацию | Да, один раз на консультацию | Нет | Не этим маршрутом |
| Просматривать очередь с действительным автором | Нет | Да | Да |
| Одобрить / отклонить / скрыть / восстановить / удалить | Нет | Да | Да |
| Страница «Написать отзыв» от выбранного профиля | Нет | Нет | Да |
| Ручной рейтинг и число голосов | Нет | Нет | Да |
| Переключатель модерации | Нет | Нет | Да |
| Закрытый аудит с реальным инициатором и источником | Нет | Нет | Да |

Роли здесь являются предлагаемыми capabilities. Игорь должен сопоставить их с фактическим Yii2 RBAC. Сервер обязан проверять права каждого запроса и возвращать 403, а не полагаться на видимость меню. Прямой URL создания в макете для модератора показывает отказ и удаляет форму.

## Экран → действие → результат

| Экран | Действие пользователя | Результат системы |
| --- | --- | --- |
| Админка → Отзывы | Выбрать статус, эксперта, поиск / фильтры колонок | Отфильтрованная очередь; pending не входит в публичный рейтинг |
| Супер-администратор → Написать отзыв | Выбрать действительный профиль, эксперта, 1–5 звёзд, необязательный текст, анонимность и основание | Новая запись от выбранного профиля, без выдуманной консультации; статус определяется актуальной серверной политикой |
| Та же форма | Отмена | Возврат в очередь без создания записи |
| Та же форма | Повторная отправка той же операции | Тот же id, без второго отзыва/голоса/аудита; изменённый payload с тем же ключом: конфликт |
| Очередь → На проверке | Одобрить + причина | pending → published; проверивший актор в закрытом аудите; пересчёт рейтинга |
| Очередь → На проверке | Отклонить + причина | pending → rejected; запись не публикуется и не учитывается |
| Опубликованные | Скрыть / восстановить / удалить + причина | published → hidden / hidden → published / разрешённый статус → deleted; пересчёт только автоматического рейтинга |
| Настройки публикации | Изменить чекбокс модерации + причина + Сохранить | Изменение только политики будущих отправок; уже ожидающие проверки НЕ одобряются автоматически |
| Клиентская форма | Звёзды, необязательный текст, «Анонимно» | Клиент определяется серверной сессией, консультация принадлежит ему, завершена и ещё не оценена; переданный author_id игнорируется |
| Клиентская форма, модерация ВКЛ | Отправить на проверку | pending; подтверждение «Отзыв/оценка отправлен(а) на проверку», публичный рейтинг не меняется |
| Клиентская форма, модерация ВЫКЛ | Опубликовать | published; текст: «Ваш отзыв опубликован»; без текста: «Ваша оценка учтена»; отсутствует автоматическая отметка ручной проверки |
| Публичная анкета | Просмотреть анонимный отзыв | «Анонимный клиент», без profile_id, истинного имени и служебного инициатора; модератор видит истинного автора |
| Публичная анкета | Просмотреть рейтинг | Все published-оценки учитываются, даже без текста; список содержит только published-записи с непустым текстом |
| Супер-администратор → Рейтинг | Задать 4.8 / 125 + причина | Эффективный ручной показатель 4.8 / 125; не создаёт 123 отсутствующих отзывов, число текстов остаётся фактическим |
| Супер-администратор → Рейтинг | Вернуть автоматический + причина | Рейтинг из фактических published-оценок, без скрытых, pending, rejected, deleted |

Приоритет правила публикации общий для клиентской и административной формы. По умолчанию модерация включена. Отзыв от супер-администратора тоже поступает на проверку, если включена модерация. Выключение предварительной модерации НЕ означает «верифицирован».

## Источник и проверка

В обычной очереди модератор видит одинаковый формат записей, без маркера «Добавлен администратором». Источник не подменяется: `source=admin`, настоящий `created_by`, профиль автора и основание сохраняются в закрытом аудите. Публичная проекция не содержит source/created_by/основание. Нельзя выдумывать оплаченные консультации или ставить знак «после завершённой консультации» административной записи без реальной связи.

Публичная анонимность не делает отправку неавторизованной. Сервер должен сохранять связь с профилем, но вырезать имя/profile_id из ответа публичного API при `anonymous=true`. Модератор сохраняет доступ к действительному автору для проверки. Без текста допустима только оценка 1–5; текст без оценки недопустим.

## Серверный контракт

Рекомендуемые операции, не утверждение о существующих backend-маршрутах:

- Клиент: создать оценку консультации с `stars`, `text?`, `anonymous`, idempotency key. Derive author, eligibility и consultation_id на сервере.
- Супер-администратор: создать запись с `author_profile_id`, `expert_id`, `stars`, `text?`, `anonymous`, обязательным основанием и idempotency key. `source`, `created_by`, policy и status вычисляет сервер.
- Модератор: решение для review_id с ожидаемой версией записи и обязательной причиной. Неверный переход/устаревшая версия: 409, пустая причина: 422, чужие права: 403.
- Супер-администратор: изменить moderation_required с причиной; аудит before/after; применять к новым отправкам внутри той же транзакции создания.
- Публичный API: effective_rating, votes_count, text_reviews_count; только опубликованные тексты и безопасный display_author.
- Ручной override: независим от реального числа записей, обязательный аудит; zero votes → отсутствие рейтинга. Не генерировать фиктивные голоса/тексты для «согласования» счётчиков.

Production: атомарная транзакция записи + аудит + агрегат; уникальность consultation_id для клиентской оценки, idempotency key и payload fingerprint; optimistic lock для решений; CSRF, XSS escaping, server RBAC и запрет подмены автора/источника/статуса. deleted в макете — tombstone, не физическое удаление; реальная политика retention/апелляции согласуется отдельно. Rejected/hidden/deleted продолжают занимать одноразовую клиентскую консультацию: редактура/повторная подача в этот scope не входят.

## Приёмка backend, ещё не выполнена

- Реальные 403/409/422 и проверка ролей при прямых HTTP-запросах, включая самоподмену author/source/status.
- Pending не виден на сайте и в расчёте; одобрение меняет оба; переключение политики не выпускает старую очередь.
- Анонимный ответ не раскрывает profile_id/имя ни в HTML, ни в JSON, ни в публичных атрибутах; закрытый аудит доступен только назначенной роли.
- Реальный однократный допуск к своей оплаченной/завершённой консультации и конкурентные повторные запросы.
- Независимая верификация, сохранность аудита, отмена/ошибка записи без ложного успеха; RU/EN и mobile.

Нативные UI-проверки этой поставки доказывают только работу макета. Они не заменяют эти backend-гейты и не означают готовность клиентского запуска.
