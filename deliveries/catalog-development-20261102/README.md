# С чего начать

Две самостоятельные задачи для Игоря. Открыть index.html: в каждой задаче есть готовый HTML-макет и полное ТЗ для человека.

- filter/TZ.html или TZ.docx — фильтр: «Горизонтальный фильтр» / «Вертикальный фильтр».
- results/TZ.html или TZ.docx — выдача анкет: «Знакомства» / «Эзотерика», карточки и все существующие входы в бесплатный чат.
- Для задачи выдачи: demo/catalog-filter.html — гость; demo/catalog-filter-auth.html — авторизованный клиент. Лист «Роли» в results/acceptance.xlsx содержит отдельные проверки.
- admin.html — полный HTML-макет подраздела «Каталог экспертов» со всеми локальными стилями и ресурсами, без служебных панелей и авторских пометок.
- integration/admin/catalog-settings.html и catalog-settings.css — готовая разметка блока формы и изолированные стили; не нужно заново придумывать поля или внешний вид.
- CODEX.html в папке каждой задачи — читаемая производная инструкция агенту; CODEX.md — текстовая копия.
- acceptance.xlsx — 14 понятных проверок каждой задачи и отдельный лист технических кодов. Проверки внедрения ещё не выполнялись.
- integration/ — раздельные блоки для адаптации в рабочем приложении; demo/ — искусственные данные и локальные действия.

HTML ТЗ автономны, с изображениями внутри. Word/PDF — та же редакция. Для понимания каждой задачи не нужны история чата и соседнее ТЗ. Прежние материалы в legacy-reference — только история, не альтернативное задание.

Рабочие настройки сайта не менялись. Макет не реализует серверный поиск, авторизацию, доставку сообщений или платный старт. Фильтр и шаблон выдачи включаются независимо; работающие текущие варианты сохраняются. Пределы проверки и независимой вычитки — REVIEW.md.

Общие проверки доступа объединены в пять групп на листе «Доступ»; их выполняют одним прогоном для двух задач. `integration/qa/` содержит параметры и генератор входных случаев, но не готовый тест продукта. Проверки внедрения остаются NOT_RUN.
