# Подключение

Фильтр и карточки подключаются независимо. Namespace примеров app/assets адаптируется к приложению. В depends каждого AssetBundle добавить существующий bundle темы, чтобы локальный CSS шёл после штатного. Не заменять CSS темы и не регистрировать одновременно прежний смешанный CatalogFilterAsset из истории.

filter/views/_filter.php регистрирует только CatalogFilterAsset. cards/views/_expertCard.php рендерит одну карточку; ExpertCardsAsset регистрируется один раз на страницу отдельно. Сетка карточек находится внутри .cl-catalog-results, имеет классы cl-expert-grid и cl-expert-item. Это не дочерний элемент .cl-catalog-filter.

shared/_versionSelection.php показывает четыре ветви подключения. Имена шаблонов и адаптеры в этом примере заменяются действующими маршрутами. Общая проверка доступности экспертов и открытие бесплатного диалога выполняются сервером до представления независимо от версии.

Сохранить серверные v1-шаблоны, их параметры и работающие ссылки. Демо и legacy-reference не заменяют v1 приложения. Не переносить данные, модальные диалоги авторизации и отправку сообщений из demo.

Рейтинг и избранное берутся из существующих компонентов. trusted HTML в параметрах partial допустим только как результат серверного view, не пользовательское поле. Передавать безопасные внутренние URL профиля и бесплатного чата. При отсутствии условий не подставлять цены или trial из макета.

Настройки: существующая защита формы, серверное право сохранения, allowlist двух значений, отдельное обновление изменённого поля/контроль версии, журнал изменений, readback. Изменение DOM/select не является серверным разрешением. Названия таблиц/permission/API не предписаны.

## Шаблон выдачи

cards/views/_results.php — отдельная сетка/лента и четыре состояния без подключения фильтра. Передаются подготовленные публичные параметры карточек текущей страницы, состояние и штатный pager. Заголовок, счётчик и применённые условия принадлежат общему контейнеру страницы; не дублировать их. После смены условий сервер заново вычисляет состав и страницы. Пагинация использует действующий компонент приложения, с мобильной подписью и стрелками из макета. Это пример view, а не готовый серверный поиск. Все URL проверяет приложение, а HTML-компоненты приходят только из доверенных серверных views.
