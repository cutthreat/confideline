# Подключение

Фильтр и карточки подключаются независимо. Namespace примеров app/assets адаптируется к приложению. В depends каждого AssetBundle добавить существующий bundle темы, чтобы локальный CSS шёл после штатного. Не заменять CSS темы и не регистрировать одновременно прежний смешанный CatalogFilterAsset из истории.

filter/views/_filter.php регистрирует только CatalogFilterAsset. cards/views/_expertCard.php рендерит одну карточку; ExpertCardsAsset регистрируется один раз на страницу отдельно. Сетка карточек находится внутри .cl-catalog-results, имеет классы cl-expert-grid и cl-expert-item. Это не дочерний элемент .cl-catalog-filter.

shared/_versionSelection.php показывает четыре ветви подключения. Имена шаблонов и адаптеры в этом примере заменяются действующими маршрутами. Действующие выборка, права и чат принадлежат приложению и не меняются при выборе оформления.

Сохранить серверные v1-шаблоны, их параметры и работающие ссылки. Демо и legacy-reference не заменяют v1 приложения. Не переносить данные, модальные диалоги авторизации и отправку сообщений из demo.

Рейтинг, отношение к анкете и чат берутся из существующих компонентов. Trusted HTML допустим только как результат серверного view, не пользовательское поле. Не подставлять цены или trial из макета.

Настройки: существующая защита формы, серверное право сохранения, allowlist двух значений, отдельное обновление изменённого поля/контроль версии, журнал изменений, readback. Изменение DOM/select не является серверным разрешением. Названия таблиц/permission/API не предписаны.

## Шаблон выдачи

cards/views/_results.php — отдельная сетка/лента и четыре состояния без подключения фильтра. Передаются подготовленные публичные параметры карточек текущей страницы, состояние и штатный pager. Заголовок, счётчик и применённые условия принадлежат общему контейнеру страницы; не дублировать их. После смены условий сервер заново вычисляет состав и страницы. Пагинация использует действующий компонент приложения, с мобильной подписью и стрелками из макета. Это пример view, а не готовый серверный поиск. Все URL проверяет приложение, а HTML-компоненты приходят только из доверенных серверных views.

## Доступ и поля профиля

Применять существующие серверные проверки siteHideDirectoryFromGuests, siteHideUsersFromGuests и siteHideProfileFieldsFromGuests и права конкретного поля, тарифа и чата. Сверить реализацию с целевым сервером; не расширять область действия старой настройки только из-за названия. Шаблон получает уже разрешённые сервером значения и существующие готовые компоненты $relationshipControl, $ratingControl, $chatControl и $profileFieldsControl для дополнительных разрешённых полей. Последний параметр, как и остальные компоненты, — только доверенный HTML существующего серверного view, не пользовательский ввод. Не определять права, статус, цену, симпатию, избранное или тариф в шаблоне; если URL профиля не передан, не создавать пустую ссылку. Демо использует синтетические данные и не является контролем доступа.

Новая отдельная настройка «Показывать гостям только экспертов онлайн» по умолчанию выключена. Лишь при явном включении сервер ограничивает гостевой каталог подтверждёнными доступными экспертами online до подсчёта и страниц; авторизованные посетители и прямой профиль регулируются своими действующими правилами. Настройка не меняется при выборе шаблонов и не подменяет существующий пользовательский фильтр «Пользователи онлайн». Использовать подтверждённый источник экспертности и доступности, а не дату последнего визита; пока эти источники не установлены, включение и серверная приёмка остаются не выполнены.
