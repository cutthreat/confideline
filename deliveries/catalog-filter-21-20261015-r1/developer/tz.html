1. Что Внедрить

Подключить готовый фильтр к реальным данным текущего сайта: одна логика в гостевом и авторизованном каталогах. Меняются только фильтр и его связь с выдачей. Шапку, навигацию, футер, оформление карточек и соседние функции сохранить. Не добавлять критерии поиска или редизайн.

Новый поиск вводится отдельным вариантом с сохранением прежнего. Новая вёрстка сайта — следующий этап: туда переносится та же модель выбора и контракт поиска, не нынешний CSS. Она намеренно не включена в комплект.

Макеты работают на одинаковых искусственных профилях. Данные аккаунта auth-макета обезличены; название файла не подтверждает серверную роль. Соседние действия демонстрационной оболочки отключены. Не заменять ею настоящую страницу и её обработчики.

Найти реальные entrypoint/model/query обеих страниц и адаптировать подключение, сохраняя общие правила ниже. Не распространять фильтр автоматически на чат, избранное, назначения, SEO и другие списки экспертов.

2. Опции И Данные

Ровно 11 опций: 5 направлений и 6 тем. Подписи и порядок — как в макетах. Taro не переименовывать в рамках технического сопоставления.

По прежнему осмотру админки Areas соответствует MultiSelect-полю 17, alias value; Specialization — полю 18, alias specialistic. Семь ID ниже — кандидаты из UI, не доказанный backend mapping. Подтвердить реальные модели, хранение, связи профиля и условие запроса. Четыре открытые связи не означают доказанного отсутствия во всей системе.

Для профиля и фильтра использовать единые справочники. Не создавать независимую копию значений и не назначать реальные связи по fixtures.

Specialization защищён и связан с другими фильтрами, включая страны/города. Не обходить защиту, не переименовывать alias/ID и не удалять используемые значения. По четырём открытым пунктам найти точную существующую связь. Если нужно дополнение, до изменения описать минимальный способ, зависимости, сохранность профилей/URL и откат. Не скрывать опции и не заменять их близкими понятиями ради подключения.

Новых обязательных продуктовых решений сейчас нет. Только если смысл нельзя установить по принятым источникам, вернуть конкретные варианты и последствия, не пересогласовывая все 11 опций.

3. Правила Поиска И Поведение

published AND allowed_for_catalog
AND (areas empty OR profile has any selected area)
AND (topics empty OR profile has any selected topic)
  • Внутри группы — OR, между непустыми группами — AND. Пустая группа не ограничивает выдачу.
  • Пустое необязательное поле не исключает допущенный профиль из общего каталога, но не совпадает с выбранным значением этого поля. Выключенный Required сам по себе не является правилом допуска.
  • Существующие серверные правила публикации, блокировок и доступа действуют и для items, и для total. Приватные поля и внутренние причины клиенту не передаются.
  • Busy/offline не исключаются только из-за занятости. Показывать правдивый статус, не обещать немедленный ответ и не подменять выбранного эксперта другим.
  • Допуск, фильтрация и удаление повторов одного профиля выполняются до total, сортировки и пагинации. Разные анкеты одного человека автоматически не объединять. Существующую сортировку сохранить, порядок сделать устойчивым.
  • Не фильтровать уже загруженную страницу вместо серверной выборки. Язык, GEO, цена, рейтинг и стаж не становятся новыми критериями только из-за присутствия в карточке.

Изменение checkbox меняет только выбор формы. «Поиск» применяет его с переходом на страницу 1. Счётчик группы относится к форме, «Найдено» — к применённому запросу. Дополнительную строку о неприменённых изменениях не показывать; автоотправки нет.

«Сбросить» сразу очищает обе группы и применяет пустой фильтр на странице 1. Пагинация использует применённый набор и не теряет неотправленный выбор формы. Перезагрузка, прямой GET и Back/Forward восстанавливают применённое состояние из URL: значения, страницу, карточки и total без расхождений.

Загрузка, отсутствие совпадений и ошибка — разные состояния. Ошибка сохраняет выбор и допускает повтор, не превращается в успешный total=0. После изменения выбора действие в сообщении ошибки становится новым «Поиск», иначе повторяет прежний запрос. Устаревший ответ не заменяет новый. Во время загрузки повтор того же запроса блокируется, изменённый выбор можно применить.

После запуска поиска/повтора из кнопки фокус переходит к результату/ошибке. Завершение запроса не перехватывает фокус, если пользователь уже перешёл к другому элементу. После сброса доступен фокус на первом параметре. Клавиатура и aria-состояния сохраняются.

4. Подключение Исходников

Исходники в current-site/. Два HTML показывают компонент в существующих оболочках, это не замена полных Yii-шаблонов.

Файл Назначение
filter-model.js Выбор, уникальность ID, URL, пагинация; без DOM/CSS
filter-data.js HTTP-адаптер, проверка ответа, защита от гонок
filter.js Форма, адаптер, вывод каталога и RU/EN; связать с настоящими карточками и маршрутами сайта
filter.css Текущий внешний вид внутри .cl-catalog; подключать после CSS сайта
filter-fixtures.js Искусственные данные макетов; в production не подключать
filter-model.test.cjs, filter-data.test.cjs Тесты модели/адаптера; не браузерные скрипты
Остальные ресурсы Оболочка и демонстрация; не копировать поверх действующих ресурсов сайта без необходимости

Порядок браузерных скриптов: model → data → controller; в демонстрации fixtures подключены между model и data. При интеграции вместо fixtures явно задаётся серверный endpoint. Скрипт подключить один раз вне заменяемого PJAX-содержимого. Не оставлять прежний submit/PJAX-контроллер владельцем той же формы. Повторная инициализация того же корня защищена; замену всего корня выполнять через lifecycle приложения, без размножения обработчиков.

Без data-catalog-endpoint корень .cl-catalog использует fixtures. В реальной странице задать same-origin GET endpoint; его отсутствие в production не должно незаметно включать демонстрацию. Скрипт не угадывает production URL.

Пример имеющегося адаптера, не утверждение о текущем API Yii:

GET <endpoint>?areas=taro,numerology&topics=love&page=2&lang=ru

taro, love и прочие ключи макета — стабильные ключи интерфейса, не числовые ID справочника из таблицы. Нужен проверенный mapping. URL читает повторные параметры, запись макета — через запятую. Реальные маршруты, локализацию и совместимость сайта сохранить или явно адаптировать.

{
  "items": [{
    "id": "profile-id",
    "name": "Display name",
    "photo": "/path/to/portrait.jpg",
    "areas": ["taro"],
    "topics": ["love"],
    "status": "online"
  }],
  "total": 1,
  "page": 1,
  "pageSize": 4
}

Это минимальный формат адаптера. Существующий API можно подключить преобразованием ответа, без изменения правил поиска. Для настоящих карточек сохранить разрешённые действия и необходимые публичные поля сайта. Текст выводить экранированным, без приватных данных.

Размер страницы макета — 4. При другом размере согласованно адаптировать сервер, контроллер и проверки. Сервер ограничивает страницу последней доступной; при нуле результатов — page=1, items=[], total=0. Некорректные/недоступные значения не превращаются в случайную выдачу и не раскрывают закрытые справочники. Предпочтителен нейтральный 400; иной существующий контракт явно описать и проверить.

5. Совместимость И Включение

Legacy уже поддерживает extraFields[17][], extraFields[18][], опыт, консультации, языки и другие параметры. Их смысл, старые ссылки и предпочтения не удалять и не интерпретировать молча как новый фильтр.

Новый поиск — отдельная стратегия на существующих моделях. Старый активен до разрешённого включения. catalog_filter_variant, legacy, maktaro_v1 — ранее предложенные обозначения, не доказанные реальные настройки/API. Найти фактическую конфигурацию; не создавать второй источник режима. Неизвестное значение безопасно возвращает legacy и записывает серверную ошибку.

Переключение требует серверного permission существующей модели прав; скрытой кнопки или названия роли недостаточно. Аудит содержит актёра, прежнее/новое значение, время и причину. Должно быть понятно, какой вариант активен и как вернуть прежний. Откат режима отделяется от отката данных: связи профилей и зависимые фильтры сохраняются. Новый RBAC этой задачей не вводится.

Комплект позволяет подготовить реализацию, но не является отдельным разрешением на production-переключение, миграции или снятие действующих пауз live-QA. Изменения справочника и план отката описать до исполнения в разрешённом контуре.

6. Визуал И Адаптация

HTML/CSS — визуальный эталон текущего фильтра. Стили сайта вне компонента не менять. Смысловые пиктограммы, нативные checkbox и клик по всей опции сохраняются; пустых видимых квадратов нет. Выбранность — рамка, заливка и галочка справа, не только цвет. Слот галочки 16 × 16 px постоянен, символ 13 px; подпись не сдвигается.

Все размеры — CSS px. Шрифт существующий Source Sans Pro, межбуквенный интервал 0. Подписи не обрезать, не разрывать внутри слова и не уменьшать пропорционально viewport. Последний пункт не растягивать на оставшиеся колонки.

  • Hover/pressed только при (hover:hover) and (pointer:fine), без изменения размеров. Selected сохраняется при hover, disabled не выглядит доступным. На touch цвет нажатия не залипает.

  • Загрузка в выдаче: минимум 160 по высоте, отступ 24, текст 15/22; форма не меняет размеры. Пустота/ошибка имеют действия 44 px и переносы по словам.
  • Гостевая оболочка сохраняет исходное следование системной теме, авторизованная — светлую тему. Шапку в рамках фильтра не перерабатывать.

7. Порядок Работы И Результат От Игоря

  1. На конкретной сборке проверить реальные места подключения и все 11 соответствий. По четырём открытым связям указать источник либо минимальное безопасное дополнение с последствиями. UI-кандидаты не объявлять подтверждённой БД.
  2. Подключить компонент в обеих страницах к существующим моделям и серверной выборке. Сохранить legacy, права, URL и откат; справочники/миграции менять только в разрешённом объёме.
  3. На разрешённой тестовой сборке пройти критерии ниже. Действующие паузы live-QA и ограничения других задач не снимаются этой передачей.
  4. Вернуть один ответ: commit и тестовую ссылку, итоговую карту 11 связей, краткое описание подключения/совместимости/отката и результаты F01–F10. Отдельные паспорта, пустые шаблоны и повторный аудит не нужны. Непроверенное и конкретные блокеры обозначить явно. Без секретов и персональных выгрузок.

8. Приёмка

Одна идентифицированная сборка и фиксированные синтетические профили. Для сценария: вход, роль, ожидаемые/фактические ID профилей, total, страница и доказательство. Визуальное совпадение и тесты модели не заменяют серверную проверку.

ID Проверка Ожидаемый результат
F01 Legacy, прежние ссылки Старые параметры, предпочтения и результаты не сломаны
F02 Оба каталога, все 11 опций Нужная стратегия и точный mapping; guest/auth различаются только по реальному правилу доступа
F03 Несколько значений группы OR; нет повтора профиля из-за join; total верный
F04 Направление + тема AND; результат соответствует пересечению
F05 Пустые группы, Reset, страницы Значения, URL, query, ID, total и page согласованы; reload/Back/Forward page=2, поиск со второй страницы, крайние и пустые страницы работают
F06 Пустота, загрузка, ошибка, повтор, гонка Пустота не маскирует ошибку; выбор сохранён; повторяет нужный запрос; старый ответ не заменяет новый
F07 Busy/offline, пустое поле, недопуск Правдивые статусы; правила пустого поля соблюдены; недопущенных нет в items и total
F08 Неверный/недоступный ID, прямой API Нет обхода доступа, приватных данных, раскрытия закрытых значений и ложного успешного результата
F09 Переключение и откат Серверный permission, аудит, fail-safe; связи и зависимые фильтры сохраняются
F10 Две оболочки, адаптация, доступность 320/360/375/480/768/992/1280 px и границы 367/368, 575/576, 767/768, 991/992; ровная сетка, подписи/фокус/галочки помещаются, hit area ≥44; клавиатура/touch/hover/disabled/reduced-motion без сдвигов

Для каждой опции нужен профиль с точной связью либо честный пустой результат при отсутствии таких профилей, не фиктивное совпадение. Нужны случаи двух значений группы, пересечения групп, нескольких совпадающих связей, пустого поля, busy/offline и недопуска.

Локальные тесты из current-site/: node --test filter-model.test.cjs filter-data.test.cjs. В макетах backend, БД, права и фактическое переключение не приняты. Готовность материалов к внедрению не означает завершение #21.
