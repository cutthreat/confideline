# #49. Критерии приёмки

Редакция 15.10.2026. Это критерии результата Игоря, а не отчёт о выполненных тестах.

## A. Технический ответ, который можно принять сейчас

| ID | Критерий | Проверяемый результат |
|---|---|---|
| A49-01 | Одна идентифицируемая сборка | Точный commit, фактическое окружение/deploy, миграции и применённая конфигурация прав; различия явно указаны |
| A49-02 | Проверяемая карта | Каждое отличающееся правило связывает действие, permission, пользователя/профиль, ownership/assignment predicate, guard и источник доказательства |
| A49-03 | Несколько профилей одного человека | Описана существующая привязка и effective сложение/приоритет прав; профиль не принят за отдельного сотрудника или автоматическое расширение доступа |
| A49-04 | Разделены доказательства | Для каждой строки один из пяти статусов ТЗ; наличие кода/UI не названо runtime PASS |
| A49-05 | Принятые решения сохранены | Финансовые роли, отдельное чтение журнала, owner-bound личные финансы, отсутствие клиента в admin-shell и идентичность агент=эксперт не переоткрыты |
| A49-06 | Конкретные остатки | Дефекты и настройки связаны с принятым правилом; продуктовые исключения содержат текущее поведение, отсутствующее правило и последствия |
| A49-07 | Адресный план | Разрешённые/запрещённые случаи для затронутых ID, вложений, realtime и отзыва уже открытого канала; существующие списки/поиск/экспорт учтены без выдуманных функций |
| A49-08 | Объём и конфиденциальность | Нет нового RBAC, повторного аудита, секретов/реальных клиентских данных, самовольной настройки production/финансов/ролей или снятия пауз |

Принятие A49-01–08 означает только достаточный технический вход. Пустой шаблон, непроверенная формулировка «всё работает» или список кнопок вместо guard-карты не принимаются. Если доказательства недоступны, строка и остаток остаются открытыми; PASS не ставится автоматически.

## B. Приёмка реализации, только после отдельного допуска

| ID | Критерий | Условие приёмки |
|---|---|---|
| B49-01 | Привязка к версии | Все результаты относятся к одной разрешённой сборке/конфигурации; роли и синтетические объекты идентифицированы |
| B49-02 | Положительный и отрицательный путь | Для каждого затронутого действующего правила проверен допуск и отказ, включая прямой запрос мимо UI |
| B49-03 | Межобъектные/межканальные границы | Чужие ID, связанные вложения и realtime не раскрывают запрещённые данные; доступ клиента к admin-shell исключён |
| B49-04 | Отзыв | Уже открытый канал, старая вкладка/ссылка и последующие запросы после отзыва проверены по действующему контракту |
| B49-05 | Минимальная регрессия | Проверены исправленный путь и затронутые соседние роли/каналы; весь старый аудит без причины не повторяется |
| B49-06 | Честный итог | FAIL воспроизводимы и связаны с исправлением; NOT_RUN/WAITING_DECISION не стали PASS; секреты и реальные финансовые действия исключены |

Старые результаты можно использовать только с их датой и доказанной применимостью к сборке. Старые R07/финансовые предположения не заменяют принятое правило PSP refund. До его уточнения спорный ожидаемый результат не является обязательным тестом.
