# Запись на консультацию: календарь и график агента

**ТЗ для обсуждения:** [Google Документ](https://docs.google.com/document/d/1TtU7FU3KrjD9I8Dxin3iAiN0N5nwxp89aE7XdiK1zFI/edit). Редакция от 13 ноября 2026 года.

Агент задаёт один рабочий график для всех закреплённых экспертных анкет. Заявка через любую из них удерживает пересекающееся время для всех остальных анкет агента. Изменение графика не отменяет уже принятые заявки или встречи; конфликт показывается ответственным.

Макеты работают с общими демонстрационными данными браузера. Запись у Алисы удерживает время у Веры; отмена освобождает его. Промежуток 30 минут — пример планового окна, а не ограничение длительности платной консультации. Состав кнопок у занятого эксперта в этом примере показан для проверки механики и не утверждает изменение стандартных настроек из задачи 3.

Для разработчика: `ТЗ.md`, `Проверки.md`, `Примеры уведомлений.md`, исходники экранов в `client`, `admin`, `settings-mockup`. Для автономного запуска из корня комплекта достаточно одного HTTP-сервера; все экраны должны иметь один origin. Макет не подтверждает работу серверной конкурентной защиты, ролей, расчётов и доставки уведомлений.

При текущей консультации обычное снятие назначения и передача откладываются до её завершения; для срочного отзыва доступа предусмотрено отдельное действие уполномоченного администратора с фиксацией причины. При конфликте приоритет — сохранить выбранную анкету, время и цену; если встреча затронута, клиенту предлагают ждать без списаний, перенести встречу с его согласия или отменить её с возвратом неиспользованного аванса. При отсутствии ответа и несостоявшейся встрече по вине площадки сотрудник проверяет оказание услуги и состояние оплаты, после чего неиспользованный аванс сразу возвращается без штрафа.

Перед реализацией проверить действующий код, финансовые операции и полномочия и сверить интеграцию с задачами 1 и 3. Макет не подтверждает, что эти действия уже реализованы на сервере.
