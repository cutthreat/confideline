# Настройки записи и действий на анкетах

Это дополнение к ТЗ задач 1–3. Интерфейс настроек показан в [макете каталога](settings-mockup/expert-buttons.html) и [макете настроек чата](settings-mockup/paid-chat.html). Значения в примерах ниже нужны для проверки и начального обсуждения; сроки, проценты и порядок выплат не должны быть жёстко зашиты в код.

## Кнопка для каждого состояния

В настройках каталога администратор отдельно выбирает текст и действие для состояния «Онлайн», «Занят», «Не в сети». В карточке показывается одна основная кнопка для текущего состояния. При необходимости её можно скрыть. Действие и подпись хранятся отдельно: изменение одного не меняет другое. После изменения действия форма напоминает проверить, что текст описывает выбранное действие; несоответствие вводит клиента в заблуждение. Русскую подпись редактируют в форме; переводы остальных языков используют общий словарь сайта с отдельными записями для каждого состояния и без изменения других надписей.

| Состояние | Начальный текст | Начальное действие |
|---|---|---|
| Онлайн | Написать в чат | Открыть обычный чат. |
| Занят | Уведомить, когда освободится | Открыть окно ожидания доступности. В этом окне можно перейти к записи на другое время. |
| Не в сети | Забронировать время | Открыть календарь записи. |

Для каждого состояния администратор может вместо начального действия выбрать чат, уведомление, запись или переход по заданной ссылке. Например, для занятого эксперта — запись, для офлайн-эксперта — уведомление. Одна и та же операция может быть выбрана для нескольких состояний. Для ссылки сохранять только корректный внутренний путь либо HTTP/HTTPS; проверять адрес и права на сервере. Если нужное действие недоступно, клиенту объясняют причину, не создавая ложного подтверждения.

Уведомление для офлайн-анкеты означает, что она снова появилась онлайн и доступна; для занятой — что освободилась. Если к нажатию эксперт уже доступен, об этом сообщают без создания ненужной подписки. Переход к записи из окна уведомления не оформляет и не отменяет подписку. Если администратор выбрал чат для занятой или офлайн-анкеты, обычная переписка открывается по существующим правам; второй платный сеанс занятого агента сервер не запускает. Переключение состояния обновляет кнопку, но не отменяет уже открытую заявку, подписку или подтверждённую встречу.

## Рабочее время и запись

В карточке партнёра с ролью агента — один календарь рабочих дней, часов, перерывов и исключений. Он используется всеми назначенными ему экспертными анкетами. В карточке экспертной анкеты — список её записей, без отдельного графика. Если агент не назначен, новые окна по этой схеме не формируются. Изменение графика не переносит и не отменяет существующую встречу без согласия клиента.

Администратор задаёт общие параметры в настройках чата:

| Параметр | Что меняет |
|---|---|
| Плановое окно, шаг начал и горизонт в днях | Какие свободные интервалы предлагаются. Длительность платного чата самим окном не ограничивается. |
| Срок ответа агента в рабочих часах и минимальный запас до встречи | Когда истекает заявка и какие срочные окна можно предложить. |
| Напоминание агенту и сигнал ответственному | Когда напоминать по рабочему времени и когда сообщать ответственному о задержке. |
| Срок эскалации конфликта записи | Через сколько минут после обнаружения нерешённого конфликта напомнить ответственному. Если встреча уже наступила или должна начаться раньше, предупредить до её начала; клиенту предложить доступные варианты без списания за ожидание. |
| Срок ожидания доступности | Как долго действует подписка на уведомление для выбранной анкеты. |
| Срок ответа на перенос и режим переноса | Перенос по согласию, через сотрудника или отсутствие предложения; срок не может выходить за ближайшее применимое начало и ранее показанный срок заявки. |
| Два напоминания клиенту и предупреждение агенту | За сколько времени до встречи отправлять напоминание и предупреждать об очередной записи. |

## Оплата, отмена и выплаты

| Параметр | Что меняет |
|---|---|
| Порядок оплаты, число минут аванса, срок оплаты | После начала консультации либо после подтверждения заявки. При втором варианте аванс и срок показывают клиенту до оплаты. |
| Срок полного возврата и правило поздней отмены | До указанного порога — полный возврат; позднее — настроенная доля удержания, полный возврат либо рассмотрение сотрудником. Доля задаётся от 0 до 100% аванса. |
| Льготное время после поздней оплаты | Дополнительный срок полного возврата до начала встречи, если запись оплачена позднее порога полного возврата. |
| Порог возможной неявки и срок её рассмотрения | Через сколько передать случай сотруднику и через сколько вернуть удерживаемый аванс при отсутствии решения. Отсутствие клиента не подтверждается автоматически только закрытием вкладки. |
| Срок напоминания о сверке оплаты | Когда уведомить администратора, если результат списания неизвестен. До выяснения не повторять списание или возврат. |
| Ставка вознаграждения | Использовать существующие общую и индивидуальную ставки в финансовых настройках; не создавать второй независимый источник. Фактическую точку и приоритет сверить с действующим кодом. |
| Период и минимальная сумма выплаты, порядок проведения | По запросу, еженедельно с выбором дня или ежемесячно с выбором числа; сумма в валюте действующего механизма выплат. Использовать существующие настройки, а отсутствующие добавить после сверки. Выплата проходит по действующим полномочиям и выбранному порядку; макет не проводит деньги. Начальные значения периода и порога требуют решения владельца. |

Вознаграждение полагается только за проведённую и оплаченную платную часть консультации. За бесплатную переписку, ожидание, пробные минуты и несостоявшуюся встречу начисления нет. Отмену по вине агента разбирают индивидуально, без автоматического штрафа или выплаты за несостоявшийся разговор. Если площадка или агент не обеспечили услугу, неиспользованный аванс возвращают клиенту; спорный результат сначала сверяют.

## Когда применяются изменения

Новые значения применяют к новым заявкам после сохранения. При создании каждой заявки фиксируют действующие условия: выбранную анкету и агента, цену, плановое окно, сроки ответа и оплаты, размер аванса, применимые правила отмены и переноса. Изменение настроек не ухудшает и не пересчитывает уже показанные и принятые условия действующей записи. Согласованный перенос меняет время по правилам этой записи, а не создаёт новую плату и не запускает льготный срок заново. Напоминания и права обрабатываются по соответствующим зафиксированным правилам.

Настройки доступны только уполномоченному администратору, с серверной проверкой прав и проверкой значений: положительные сроки и интервалы, доля 0–100%, совместимые размеры окна и шага, корректная дата выплаты и ссылка. Изменения и автор фиксируются в истории. Ошибка сохранения не меняет действующих настроек. Сайт проверяет ресурс агента, состояние записи и права при действии, а не только при показе кнопки.

Пример проверки: сохранить для занятого состояния «Забронировать время», для офлайн — «Уведомить, когда появится». У занятой анкеты откроется её календарь, у офлайн — ожидание её появления онлайн; на каждой карточке одна кнопка. Затем задать другой срок оплаты и процент поздней отмены: новая заявка покажет новые условия, а существующая сохранит прежние. Это демонстрация интерфейса; реальные платежи, права и конкурентность проверяются после разработки.
