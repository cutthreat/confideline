# Отзывы и рейтинг: пакет для Игоря

Актуальная поставка от 09.10.2026 по прежнему адресу r7:
https://cutthreat.github.io/confideline/deliveries/reviews-rating-20261009-r7/developer/index.html

## С чего начать

1. Открыть `developer/index.html`: ссылки на админку и 15 составных клиентских макетов.
2. Прочитать `developer/SPEC.html`. Это единственное ТЗ: права, настройки, режимы модерации, расчёт рейтинга, серверные операции, исправление отклонённого отзыва и приёмка.
3. Сопоставить разметку и файлы по карте ниже с действующими Yii2 views, AssetBundle, RBAC и сервисами. Не заменять серверные страницы полным демо HTML.
4. Реализовать серверные операции по ТЗ; убрать демо-хранилище, фикстуры и управление ролью через URL. После интеграции пройти разделы проверки в ТЗ.

## Просмотр

Макеты можно открыть прямо из `developer/index.html`. Для согласованной работы общих настроек и данных между страницами рекомендуется один локальный HTTP-origin, а не `file://`:

```powershell
python -m http.server 8793 --bind 127.0.0.1
```

Команду выполнять в корне распакованного пакета, затем открыть `http://127.0.0.1:8793/developer/index.html`. При занятом порте выбрать другой свободный. Node/npm, сборка и установка зависимостей не нужны. Остановка локального сервера: Ctrl+C.

Демо-данные сохраняются в localStorage данного origin. `role` и `lang=ru|en` в URL демонстрируют интерфейс, но не авторизацию. Составные клиентские состояния открываются из `profile-states.html`; число макетов не увеличено.

## Карта файлов

| Файл в `developer/` | Назначение и перенос |
| --- | --- |
| `reviews.html` | Разметка очереди и решений модератора. Без ручного рейтинга и создания отзывов. Перенести нужные фрагменты в Yii views. |
| `write-review.html` | Выбор эксперта, ручная база рейтинга и создание отзыва/оценки супер-администратором. Независимые операции сохранения. |
| `settings.html` | Общие настройки; выбор `premoderation`, `postmoderation`, `none`. |
| `profile.html` | Клиентская анкета, рейтинг, список, форма и статусы своего отзыва. Полная оболочка служит образцом. |
| `profile-states.html`, `reviews-profile-states.js` | Каталог 15 состояний и клиентский демо-контроллер с фикстурами. Поведение сверять, целиком в production не переносить. |
| `reviews-admin-panel.css`, `reviews-polish.css` | Локальные стили админки и клиентской поверхности. Подключать после штатных ресурсов соответствующей поверхности. |
| `reviews-admin-panel.js` | Клиентские взаимодействия очереди: фильтры, решения, пересмотр и журнал модерации. Адаптировать транспорт. |
| `reviews-create-review.js`, `reviews-rating-editor.js`, `reviews-settings.js` | Контроллеры создания, базы рейтинга и настроек. Адаптировать к серверным ответам и действующей инициализации/PJAX. |
| `reviews-admin-shell.js` | Общая демо-оболочка, меню, тексты RU/EN, связка с демо-хранилищем. Не заменять общую оболочку сайта этим файлом. |
| `reviews-rating-model.js` | Демонстрационная модель валидации и расчёта. Сервер реализует те же правила; клиентский расчёт не является источником истины. |
| `reviews-admin-workflow.js` | Демо-сервис, фикстуры, localStorage и переходы статусов. Не использовать как production API, RBAC или аудит. |
| `reviews-polish.js` | Дополнительные взаимодействия клиентского макета. Переносить только нужные страничные обработчики. |
| `reviews-site-assets/` | Локальные базовые CSS, изображения и иконочные шрифты для просмотра. При внедрении использовать штатные ресурсы сайта, не дублировать Bootstrap/AdminLTE. |
| `SPEC.html`, `THIRD-PARTY-NOTICES.md` | Единственное ТЗ и сохранённые уведомления сторонних ресурсов. |

Встроенные CSS/JS в HTML также являются исходниками и включены в пакет. Сгенерированных отдельных production bundles или скрытого этапа сборки нет. `PACKAGE-CONTENTS.csv` перечисляет все файлы поставки с размером и SHA-256, кроме самого реестра. ZIP не вкладывается сам в себя; ссылка его скачивания в локальном индексе ведёт на опубликованный r7.

## Границы внедрения

- Это полный комплект текущих макетов, не готовый PHP-модуль: DB-миграций, контроллеров, AssetBundle и рабочего API в поставке нет. Их реализует программист в существующем проекте.
- Сервер отвечает за допуск по своей оплаченной завершённой консультации, уникальность голоса, роли, CSRF, валидацию, конкурентные изменения, идемпотентность, атомарный аудит, публичные проекции и инвалидирование кеша. Полные правила находятся только в ТЗ.
- Модератор работает в `reviews.html`; ручное управление и создание находятся только в `write-review.html`; общая политика только в `settings.html`. Новые записи используют один из трёх режимов модерации. Исправление отклонённого текста имеет отдельную обязательную повторную проверку.
- Рейтинг с ручной базой публично отображается как общий рейтинг по согласованному решению. Источник, фактический инициатор и основания остаются в закрытом аудите.
- Все локальные зависимости включены. Штатные стили дополнительно запрашивают Source Sans Pro через Google Fonts и Inter через rsms.me; при отсутствии сети используются CSS fallback-шрифты. Эти необязательные внешние загрузки не являются API сайта.
- Закрытый backend, реальные клиентские данные, секреты, локальные QA-логи, инструменты агента, старые поставки и приложенные для примера архивы в ZIP не входят. Боевой сайт не изменялся.

Последние функциональные изменения проверены до упаковки; в проходе упаковки проверяются состав, совпадение исходников, ссылки и публикация. Это не подтверждение внедрения или E2E-приёмки боевого backend.
