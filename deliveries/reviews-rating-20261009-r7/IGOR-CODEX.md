# #62: технический вход для Codex Игоря

Редакция 19.10.2026. Начните с [ответов Q1–Q7](ANSWERS-FOR-IGOR.md), затем [единственного ТЗ](developer/SPEC.html), особенно §2–5, §9–10. Сохраняйте действующие Yii2 сервисы, RBAC, AssetBundle и дизайн; не переносите demo localStorage/query-роли в production.

## Дополнение макетов

- `developer/reviews.html?role=moderator&history=RV-203&lang=ru`: безопасная история, отдельная от закрытого аудита. `moderationHistory` в demo — образец белого списка полей, не готовая серверная авторизация.
- `developer/profile.html?case=multiple-consultations&lang=ru`: два доступных новых сеанса, собственные rejected/published записи, trial-only и ожидающий расчёт; выбор и раздельные черновики.
- `reviews-admin-workflow.js`: обобщение уникальности и владения на отдельный сеанс; исходный голос/исправление/пересмотр остаются одной записью. `reviewEligibility` демонстрирует смысл проверки, реальные поля/charge types сопоставляете вы.
- `reviews-polish.js`: отдельный ключ идемпотентности и черновик на консультацию; после отмены исправления не отправлять новую оценку как старую revision.

## Обязательная проверка вашей реализации

1. По прямому URL/API отказ клиенту/агенту/роли без права; безопасная история доступного объекта без source, административного создателя/основания, внутренней причины и raw before/after. Superadmin получает полный аудит только через свой разрешённый путь.
2. Одно сохранение/один голос на consultation_id; повтор, параллельные запросы и retry с тем же ключом не удваивают эффект. Тот же ключ с другим сеансом/payload даёт конфликт.
3. Два своих сеанса независимы; чужой клиент/другой эксперт/бесплатный trial/неуспешный расчёт не допускаются. Успешный расчёт в минус допускается. Не требовать положительный общий баланс.
4. Исправление rejected сохраняет id, консультацию, звёзды, автора/анонимность и возвращает pending. Пересмотр не создаёт новый голос. Stale version и сбой транзакции не меняют запись/аудит и не теряют ввод.
5. Черновики разных консультаций не смешиваются; отмена, ошибка и обновление другой вкладкой не делают скрытую перепривязку. При успехе очищается только отправленный черновик.
6. Один итог/политика показа в профиле и перечисленных действующих карточках; кеши инвалидируются. Голоса и текстовые отзывы — разные счётчики.
7. Tab/Escape, начальный фокус и прокрутка истории, возврат в исходную строку, RU/EN, мобильный экран без обрезанной формы. Private own-status доступен при выключенном публичном показе/новом приёме.

## Результат

Верните commit/окружение, карту action → permission → scope → handler, account/session/charge/settlement mapping, используемые URL/views/кеши, политику окончательного удаления и ссылку на регламент пересмотра либо их явное отсутствие. Для критериев выше укажите PASS/FAIL/BLOCKED/NOT_RUN с коротким доказательством. Отдельно перечислите оставшиеся назначения/настройки и owner-решения; не делайте их молча.

Тесты и браузерная проверка поставки подтверждают только синтетическую статическую логику. Это не backend/RBAC/DB/CSRF/production PASS. Количество таблиц и имена маршрутов выбирает разработчик; финансовые расчёты и текущая политика удаления не перепроектируются.
