# Управление полями анкет клиентов и экспертов

В режиме «клиент — эксперт» настройки общего поля можно задавать отдельно. В примере видимость включена для клиента и выключена для эксперта.

## 1\. Результат

На странице «Настройки → Поля профиля» администратор управляет полями клиентской и экспертной анкет. У общего поля настройки клиента и эксперта отображаются отдельными строками и редактируются независимо. При внедрении на текущем сайте применяется режим «клиент — эксперт». Выбранный режим действует для всего сайта: для админки, форм и поиска. Переключение режима после запуска в эту задачу не входит; оба режима проверяются на тестовых данных. Над таблицей расположены вкладки «Клиент — эксперт» и «Все видят всех». Активна вкладка выбранного режима, другая недоступна. В режиме «все видят всех» таблица с теми же строками клиента и эксперта сначала открывается для просмотра; настройки можно изменить после подтверждённой разблокировки. Значения в самих анкетах остаются индивидуальными. Выключение поля скрывает его в выбранном месте, но не удаляет ответы. Пять профессиональных полей доступны экспертам. При переносе сохраняется фактическая доступность каждого из них в клиентской форме; остальные изначально назначаются только экспертам. Администратор может включить их и для клиентов. Служебные данные партнёров и сотрудников, права, выплаты и роли остаются в своих разделах: в каталог полей анкет их не переносим.

Действующая страница: [https\://confideline.com/ru/admin/profile-field/index](https://confideline.com/ru/admin/profile-field/index)

Сейчас в списке нет отдельных строк настроек клиента и эксперта; встроенные вопросы «Пол», «Статус», «Я ищу» и «Возрастом» нельзя полноценно включать и выключать через этот каталог.

## 2\. Как устроен список

1\. Сохранить действующие категорию, ID, заголовок, класс поля, псевдоним и действия. В обоих режимах для общего поля показать данные поля один раз, а настройки — двумя подписанными строками: «Клиент» и «Эксперт». Для применимого только к одному типу поля показывать только его строку.

Сохранить имеющееся изменение порядка полей перетаскиванием. Числовой порядок в форме и перетаскивание должны использовать действующий механизм сортировки, не создавая независимых порядков. В предпросмотре учитывать этот порядок с сохранением действующих групп категорий и закреплённых элементов анкеты. Временная сортировка списка по заголовку или настройке системный порядок не переписывает.

2\. Четыре существующих столбца настроек остаются отдельными: «Видимость», «Видимо только премиум-пользователям», «Поиск», «Поиск (премиум)». В обоих режимах галочка в строке меняет настройку только соответствующего типа анкеты. Для неподдерживаемой настройки не показывать действующий переключатель. Рядом с названием типа строки использовать лёгкое визуальное отличие, как в макете.

3\. Список ищет по названию, фильтрует по категории, происхождению и типу анкеты. «Только различия» показывает поля одного типа и общие поля, у которых отличается хотя бы один применимый флажок; одинаково настроенные общие поля скрывает. После успешного сохранения совпавших настроек поле исчезает из результата и показывается пояснение. Если страница списка опустела, показать предыдущую непустую страницу. Сброс возвращает полный список. При выборе одного типа сортировка настроек относится к нему. При просмотре обоих типов сортировка по настройкам недоступна в обоих режимах.

Для общих полей режим «Только различия» сравнивает только четыре флажка, видимых в таблице. Настройки «В форме» и обязательности в сравнение не входят.

В действующем «Обзоре» фильтр «Я ищу» ищет пол человека по Profile\[sex\], а «Возраст от/до» — его возраст по дате рождения Profile\[dob\]. Это не предпочтения анкеты «Я ищу» (Profile\[looking\_for\_sex\_array\]) и «Возрастом» (две границы желаемого возраста). Для двух последних в текущем «Обзоре» отдельного подтверждённого фильтра нет: их настройка показа не должна создавать второй одноимённый критерий или менять смысл существующих.

Над таблицей находятся два флажка: «Клиент» и «Эксперт». В обоих режимах можно выбрать один тип или оба; если отмечены оба, показываются все подходящие анкеты. По умолчанию отмечены оба флажка; снять последний нельзя. Выбор меняет только состав списка. «Только различия» доступно при просмотре обоих типов; при выборе одного типа фильтр различий сбрасывается.

4\. Пример для режима «клиент — эксперт»: «Цель знакомства», ID 7\. Для клиента «Видимость» включена, для эксперта выключена. При «Только различия» видны обе строки. Если сделать настройки одинаковыми, это общее поле исчезнет из результата. Этот пример демонстрационный и не задаёт реальные настройки сайта.

5\. В режиме «клиент — эксперт» изменение любого из четырёх флажков таблицы сохраняется сразу. Настройки «В форме» и обязательности сохраняются кнопкой «Сохранить» в окне поля; данные пользовательского поля — на существующей странице поля.

В режиме «все видят всех» настройки клиента и эксперта сначала доступны только для просмотра. Поиск, фильтры, сортировка и просмотр настроек поля работают. Чтобы изменить настройки, администратор нажимает «Изменить настройки» и подтверждает предупреждение: изменения после сохранения затронут выбранные типы анкет. После отмены предупреждения таблица остаётся заблокированной. При подтверждении разблокировки открыть актуальные сохранённые настройки вместе с соответствующей им версией, чтобы не перезаписать изменения другого администратора.

После подтверждения администратор меняет нужные настройки; создание, редактирование и удаление полей также входят в этот набор изменений. В набор входят доступные свойства поля, назначение, варианты ответов, переводы и порядок; сами категории по-прежнему управляются в своём разделе. До общего сохранения изменения не применяются на сайте. В форме поля кнопка «Добавить к изменениям» возвращает к таблице и добавляет изменения в список для сохранения. В таблице новое поле отмечено «Новое», его ID появляется после общего сохранения. Поле можно вновь открыть и исправить до общего сохранения; если удалить его из набора, оно не создаётся. Существующее поле, подготовленное к удалению, остаётся в таблице с отметкой «Будет удалено» и кнопкой «Восстановить». Если отменить весь набор, новые поля не создаются, удаляемые остаются, а прежние данные и настройки не меняются.

Кнопка «Сохранить изменения» открывает подтверждение со списком всех подготовленных действий: новых и удаляемых полей и изменённых значений до и после, включая назначение и порядок. Для нового поля показать выбранные типы анкет и начальные настройки каждого из них; прежних значений у нового поля нет. Неизменённые свойства не выводятся. «Вернуться к редактированию» сохраняет несохранённые изменения на экране. После подтверждения изменения сохраняются вместе и применяются к соответствующим типам анкет; таблица снова открыта только для просмотра. Если ничего не изменено, кнопка сохранения недоступна. «Отменить» предлагает отказаться от несохранённых изменений. При выходе или обновлении страницы предупреждать о несохранённых изменениях. После обновления или возвращения в той же открытой вкладке добавленный набор восстанавливается, пока доступна сессия; при закрытии вкладки или завершении сессии он не применяется. При возврате из формы к таблице без добавления незавершённые правки формы не входят в набор; уже добавленные изменения других полей сохраняются. Перед уходом или обновлением такой формы предупредить о потере введённых правок. После окончания сессии неподтверждённые изменения не применяются.

После успешного сохранения показать результат. При отказе сообщить об ошибке: в режиме «клиент — эксперт» вернуть последнее подтверждённое значение переключателя, в режиме «все видят всех» оставить набор доступным для исправления. Если результат неизвестен или изменения применились не полностью, действовать по правилам раздела 6\. После подтверждённого сохранения и перезагрузки показывать сохранённое состояние.

6\. Сохранить действующую последовательность и назначение команд создания, редактирования и удаления. В режиме «все видят всех» до открытия редактирования создание, изменение и удаление недоступны. «Новое поле» и карандаш пользовательского поля открывают действующие страницы создания и редактирования, а не новое модальное окно. Встроенное поле нельзя удалить. При удалении существующего дополнительного поля предупредить: «При удалении поля будут удалены и ответы пользователей. Чтобы скрыть поле и сохранить ответы, выключите показ, поиск и заполнение в настройках». В режиме «клиент — эксперт» поле и ответы удаляются после подтверждения. В режиме «все видят всех» подтверждение сначала добавляет удаление в набор изменений; поле и ответы удаляются только после общего сохранения, а список изменений перед сохранением повторяет, что ответы будут удалены. До общего сохранения удаление можно отменить. Новое поле, ещё не сохранённое и находящееся только в черновике, удаляется из набора без предупреждения о существующих ответах. Команды в столбце «Действия» выровнены по постоянным позициям.

7\. Сохранить выбор размера страницы и переходы по страницам. Размер страницы считается по полям: общее поле с двумя строками не разрывается между страницами. При выборе типа анкеты показывается только строка выбранного типа. Длинный список прокручивается страницей, без отдельной вертикальной прокрутки внутри таблицы. Десктопная компоновка — по макету. Мобильная адаптация в эту редакцию задачи не входит.

## 3\. Что означают настройки

«Видимость» управляет показом значения в анкете. «Видимо только премиум-пользователям» ограничивает показ премиум-аудиторией. «Поиск» управляет наличием критерия в фильтре страницы «Обзор» и поиском по нему. «Поиск (премиум)» ограничивает этот критерий премиум-аудиторией. Существующую настройку «Показывать только экспертов» сохранить и связать с выбранным режимом: при режиме «клиент — эксперт» ограничение включено, при режиме «все видят всех» выключено; противоположное положение настройки в админке заблокировано. Применять её в тех разделах, на которые она уже влияет, не расширяя её действие на остальные. В режиме «все видят всех» фильтр не предлагает выбор «только эксперты»: показываются все анкеты, соответствующие выбранным условиям и общим правилам выдачи сайта. В каждой паре ограничение премиум имеет приоритет; статус аудитории определяется у смотрящего или ищущего, тип анкеты — у записи, которую показывают или ищут. Не выводить недоступные значения через HTML, API или поисковый ответ.

Правило для каждой пары флажков: оба выключены — значение или фильтр недоступны всем; включён только общий — доступны обычным и премиум-пользователям; включён только премиум — доступны только премиум-пользователям; включены оба — также доступны только премиум-пользователям. Показ значения в анкете и участие поля в поиске настраиваются отдельными флажками. Пара флажков поиска задаёт его базовую доступность; окончательное право искать дополнительно зависит от ограничений доступа к значению, в том числе Premium. Если поле скрыто в анкете, а поиск для аудитории разрешён, оно участвует в подборе анкет. Например, клиент может найти анкеты по направлению «Таро», даже если поле Areas скрыто в профиле. Если критерий доступен хотя бы для одного типа анкет, его можно показать в общем фильтре. Когда пользователь его выбрал, в результат включаются только анкеты тех типов, для которых этот критерий разрешён и условие выполнено. Скрытое значение не выводится в карточке, анкете и ответе API. Например, если оба флажка показа выключены, а общий поиск включён без ограничения Premium, искать могут все, но значение не показывается. Если включён флажок «Видимо только премиум-пользователям», обычный пользователь не может искать по этому значению; премиум-пользователь может, если поиск разрешён ему соответствующими флажками. Ограничение доступа имеет приоритет: если значение доступно только Premium или закрыто действующими правилами, обычный пользователь не может применить критерий или получить совпадения по нему, даже когда общий флажок поиска включён. Это относится и к прямому запросу. Использовать существующие поисковые элементы для поддерживаемых классов полей.

Применимость флажков: у дополнительных полей сохраняются четыре существующие настройки. Поиск и его переключатели доступны для классов, поддерживаемых действующим поиском; неподдерживаемый поиск не должен выглядеть работающим. Поддерживаемые классы и действующие правила поиска проверить до внедрения. У встроенных полей доступна «Видимость»; «Поиск» доступен для пола, даты рождения, страны и города. Для остальных встроенных полей и премиум-флажков встроенных полей переключатель не показывается. Настройки доступности поля в форме и обязательности открываются по названию «Клиент» или «Эксперт» в строке, как в макете. В режиме «все видят всех» они доступны для изменения после открытия редактирования. Карандаш дополнительного поля открывает его действующую форму. В ней редактируются описание и назначение поля. Настройки показа, поиска, заполнения и обязательности для каждого типа редактируются в строке этого типа.

Назначение определяет, к каким анкетам относится поле. Для назначенного типа отдельно задаются доступность поля в форме и обязательность; показ значения в анкете и поиск управляются соответствующими флажками. В обоих режимах эти правила настраиваются отдельно для каждого назначенного типа анкеты. Пока поле выключено в форме, его обязательность не применяется. Значение настройки «Обязательно» сохраняется и возвращается при повторном включении поля в форме; ответы не стираются. Настройка «В форме» относится к редактированию анкеты и не изменяет действующую регистрацию: поля, которые сейчас запрашиваются при регистрации, по-прежнему запрашиваются там. Показ в анкете и наличие в поиске не следует смешивать с показом в редакторе. Если отключение встроенного поля лишает пользователя единственного доступного способа указать значение, необходимое действующей системной функции, отключение не сохранять и показать администратору, для какой функции поле требуется. В режиме «все видят всех» при этом не применять никакую часть общего набора изменений. Если настройка неприменима к встроенному полю, объяснить это в интерфейсе и не предоставлять ложный переключатель.

## 4\. Какие поля входят в каталог

В режиме «клиент — эксперт» клиенту и эксперту доступны существующие непрофессиональные поля согласно их действующим настройкам. Пять профессиональных полей доступны экспертам. При первоначальном переносе профессиональное поле остаётся доступным клиентам, если оно фактически доступно им в действующей форме. Если поле не доступно клиентам, первоначально назначить его только экспертам; наличие старого ответа само по себе не включает поле. В режиме «все видят всех» назначение и настройки поля также показываются по типам анкеты и могут быть изменены после разблокировки. Администратор может включить профессиональные поля и для клиента. При первом включении существующего профессионального поля для клиента в любом из двух режимов настройки клиентской строки копируются из экспертной. После этого настройки клиентской и экспертной строк можно изменять независимо. Если поле для клиента выключили, а затем включили повторно, восстановить последние сохранённые настройки клиента. Для остальных дополнительных полей при первом назначении новому типу копировать настройки уже назначенного типа, а при повторном включении восстанавливать последние сохранённые настройки этого типа. Новые пользовательские поля создаются через существующую страницу админки: в режиме «клиент — эксперт» администратор указывает назначение двумя флажками «Клиент» и «Эксперт». При создании поля по умолчанию отмечены оба типа; администратор может изменить выбор, но должен оставить хотя бы один. Если отмечены оба флажка, поле относится к обоим типам. В режиме «все видят всех» назначение выбирается теми же флажками; два отмеченных типа означают обе анкеты. У существующего пользовательского поля назначение меняется на его действующей странице редактирования; после сохранения в списке появляется или исчезает соответствующая строка настроек. Назначение и настройки поля можно изменить без переноса ответов между анкетами.

На странице создания пользовательского поля показаны начальные настройки для отмеченных типов анкет; администратор может изменить их до сохранения: «В форме» и «Видимость» включены, «Обязательно в форме», «Видимо только премиум-пользователям», «Поиск» и «Поиск (премиум)» выключены. Администратор может изменить их до сохранения. Если отмечены оба типа, они получают одинаковые начальные настройки. Дальнейшее редактирование зависит от выбранного режима сайта. Обязательность проверяется при сохранении той действующей формы или этапа, где поле включено и доступно этому пользователю; существующие правила черновиков сохраняются.

Для удобства встроенные поля в каталоге сгруппированы под подписями «Основные сведения» и «Знакомства», как в макете. Это группы отображения встроенных полей: восемь действующих категорий дополнительных полей, их состав и настройки не переименовываются и не переносятся.

Из действующих дополнительных полей сохранить ID, класс, псевдоним, варианты, переводы, категории, порядок и ответы. Профессиональные поля: 17 Areas / value — направления; 18 Specialization / specialistic — специализация; 19 Number of Consultations / ncons — заявленное число консультаций; 20 My Experience / experience — заявленный опыт; 21 My Languages / language — языки. Это значения анкеты, а не вычисленные показатели проведённых платных чатов.

Остальные дополнительные поля из действующего списка: №7 «Цель знакомства» / Trigger; №8 Marital Status / Marital\_status; №11 Children / children; №12 Bad Habits / bad\_hobby; №6 Favorite Drinks / favoriteDrink; №2 Рост / height; №1 Вес / weight; №9 Education / education; №10 Профессия / profession; №15 Zodiac Sign / Zodiac; №14 Pets / Pets; №5 My Hobbies / tags\_hobby; №13 Religion / religions; №3 Facebook / facebookUrl; №4 Twitter / twitterUrl; №16 My Telegram / TG. Их данные берутся из существующих пользовательских полей с этими ID и псевдонимами; рабочие контакты сотрудников к ним не относятся.

Источники остальных встроенных полей: имя — Profile\[name\], фото — действующая фотогалерея профиля, описание — Profile\[description\], дата рождения — Profile\[dob\], страна — Profile\[country\], город — Profile\[city\]. Точные связи и чтения сверить с действующей веткой, не создавать копии значений.

Подключить встроенные поля к управлению без создания вторых копий их значений:

• «Пол» — Profile\[sex\].

• «Статус» на фронте — встроенный Profile\[status\]; в таблице понятная подпись «Статус отношений». Это не статус аккаунта и не отдельное пользовательское поле Marital Status №8.

• «Я ищу» — Profile\[looking\_for\_sex\_array\], не смешивать с полем «Цель знакомства» №7.

• «Возрастом» — Profile\[looking\_for\_from\_age\] и Profile\[looking\_for\_to\_age\], обе границы управляются вместе.

В режиме «клиент — эксперт» запись с устаревшей версией отклоняется без перезаписи более новой. В режиме «все видят всех», если после начала редактирования общие настройки сохранил другой администратор, весь устаревший набор отклоняется, даже когда изменено другое поле: никакая его часть не применяется. Повторное сохранение старого набора недоступно. Экран сообщает о конфликте и оставляет несохранённые изменения видимыми. После отказа от них показать последнее сохранённое состояние и предложить внести изменения заново. Более новые настройки другого администратора не перезаписывать. Если запись уже состоялась, но обновление индекса или кэша завершилось ошибкой, не показывать старое значение как достоверное: сообщить о неполном применении, перечитать подтверждённое состояние и не раскрывать скрытые данные до обновления. Повторять безопасное обновление индекса или кэша, а не исходное изменение настройки.

При внедрении отдельно проверить действующее перетаскивание при фильтрах, сортировке и пагинации и сохранить подтверждённую семантику. Если в рабочей версии поведение для случая не установлено, зафиксировать вопрос до внедрения, не придумывая перестановку скрытых полей.

Встроенные имя, фото, описание, дата рождения, страна и город остаются связаны с существующими источниками и ограничениями. Управление показом не отключает техническую идентификацию и не открывает закрытую информацию. Категории остаются действующими категориями; управление категориями не заменяется новой кнопкой на странице.

Кнопка «Предпросмотр» открывает демонстрацию с выбранными типом анкеты и аудиторией: обычный пользователь или премиум. Можно увидеть три контекста: анкету, форму её редактирования и фильтр «Обзора». В предпросмотре используются сохранённые настройки и изменения, уже добавленные к общему набору. При обновлении предпросмотра в той же вкладке добавленные к общему набору изменения остаются видны. Незавершённые правки формы, не добавленные в набор, в предпросмотр не входят; при этом неподтверждённые изменения не применяются на сайте, а подписи и элементы следует показывать в структуре реального сайта, как в согласованном макете. Возврат к списку сохраняет текущие фильтры и позицию. Демонстрационные значения не сохраняются как данные пользователя и не публикуются.

## 6\. Сервер, данные и права

Настройки должны реально применяться сервером к нужному типу анкеты при выдаче формы, сохранении, просмотре, API и поиске. При выключении данные не удаляются. В обоих режимах изменение настройки одного типа не меняет настройки другого типа. Повторное включение возвращает сохранённые ответы тем, кто вправе их видеть. Обходным запросом нельзя изменить поле, которое не разрешено этому пользователю в текущей форме или неприменимо к типу анкеты. Сокрытие значения от постороннего зрителя само по себе не запрещает владельцу заполнить его в разрешённой форме; обязательность проверяется только для разрешённого активного поля и соответствующего этапа. Если конфигурация изменилась во время редактирования анкеты, не сохранять устаревшую форму частично и не затирать имеющиеся ответы. Сообщить пользователю, что форму нужно обновить.

Доступ к настройкам и закрытым сведениям определяется существующими ролями и серверными правами; один флажок не выдаёт новое право. Изменения конфигурации сохранять атомарно и применить к соответствующему кэшу и поисковому индексу. При переносе сохранить ответы и фактическую доступность полей, пересчитав флаги согласно их новому смыслу. Предусмотреть проверку до и после переноса и безопасный откат.

Перенос настроек: до переноса для каждого существующего поля и применимого типа анкеты определить фактические видимость для обычной и премиум-аудитории, доступность в форме, обязательность и поиск. Сохранить фактическую видимость и доступность формы, а не копировать старые флажки механически. Например, если раньше общая видимость выключена, Premium включён и поле фактически скрыто от всех, после переноса оба новых флажка показа должны быть выключены. Исходные настройки и все ответы сохранить для проверки и отката. Исключение: если значение фактически доступно для просмотра только Premium, обычный пользователь после внедрения не может искать по нему, даже когда раньше общий поиск был разрешён. Для поля, скрытого от всех без ограничения Premium, разрешённый поиск сохраняется. Для профессиональных полей №17–21 сохранить фактическую доступность в клиентской форме; поле, ранее недоступное клиентам, первоначально назначить только экспертам. Назначение само по себе не включает видимость. Проверить существующие зависимости встроенных полей и не отключать обязательные системные функции. Если исходное поведение или право невозможно установить, не угадывать и не вводить изменение в эксплуатацию до уточнения.


Для существующих дополнительных полей отдельно перенести доступность в форме и обязательность: для каждого применимого типа сохранить фактическое поведение действующей формы и существующее правило проверки обязательности. Новые значения «выключено по умолчанию» к уже существующим полям не применять. Если исходные настройки клиента и эксперта различаются, сохранить их раздельно для соответствующих строк. Если поведение или обязательность на действующей версии установить не удаётся, зафиксировать неопределённость и не вводить миграцию в эксплуатацию до уточнения.

Во время сохранения повторное нажатие недоступно. В режиме «все видят всех» все подтверждённые изменения применяются как единый набор. Успех показывается после подтверждения записи и применения изменений к выдаче, кэшу и поиску. Если ответ потерян и результат неизвестен, не повторять запись автоматически: сообщить об этом, получить фактическое состояние с сервера и показать его; при недоступности чтения оставить состояние неопределённым и предложить повторить проверку.



## 7\. Проверка результата

1\. В режиме «клиент — эксперт» проверить активную вкладку и недоступность другой вкладки. На общем поле изменить отдельно каждый из четырёх флажков у клиента и эксперта: меняется только выбранная строка, настройка сохраняется после перезагрузки, фильтр различий работает.

В режиме «все видят всех» проверить активную вкладку, недоступность другой вкладки, отдельные строки клиента и эксперта и исходную блокировку изменения. Поиск и просмотр настроек доступны. Отменить первое предупреждение: блокировка остаётся. Подтвердить разблокировку, изменить несколько настроек клиента и эксперта и убедиться, что до общего сохранения они не применяются на сайте, а изменение одной строки не меняет другую. Открыть подтверждение сохранения и сверить список изменений с указанием типа анкеты и прежних и новых значений, вернуться к редактированию, затем подтвердить сохранение. После перезагрузки настройки сохранены для соответствующих типов анкет, таблица снова заблокирована. Проверить отказ от изменений, предупреждение при выходе и ошибку сохранения без потери черновика. Проверить поиск всех подходящих анкет без выбора «только эксперты».

2\. Проверить поле только эксперта, общее поле с одинаковыми настройками и общее поле с отличием; затем сбросить фильтр и проверить полный список и сортировку.

3\. В режиме «клиент — эксперт» для «Пол», «Статус», «Я ищу» и «Возрастом» проверить выключение и включение каждого типа, форму и просмотр; для применимого поиска — фильтр и серверный результат. У возраста скрываются обе границы, ранее заполненные ответы возвращаются. №8 и №7 сохраняют отдельные значения.

4\. Проверить два случая. Скрытое от всех поле без ограничения Premium при разрешённом поиске находит подходящую анкету, но значение отсутствует в карточке, анкете и API. Если значение доступно для просмотра только Premium, обычный пользователь не получает совпадение по нему, даже когда общий поиск был разрешён до переноса; проверить прямой запрос и старый кэш. Premium-пользователь находит анкету, если поиск ему разрешён. Если критерий разрешён для другого типа анкеты, его можно показывать в общем фильтре, но выдача не раскрывает закрытые совпадения.

5\. Через существующую форму создать и изменить тестовое пользовательское поле, назначить его клиентской анкете, экспертной или обеим и проверить появление на фронте согласно настройкам. В каждом режиме впервые включить существующее профессиональное поле для клиента и проверить, что все его начальные настройки совпадают с настройками эксперта, включая доступность в форме, обязательность и применимые флажки просмотра и поиска. Затем изменить настройки клиента и эксперта отдельно, убедиться, что другая строка не меняется, и проверить сохранение после перезагрузки. Отключить поле для клиента, изменить настройки эксперта и снова включить поле клиенту: должны восстановиться последние настройки клиента. На тестовом дополнительном поле с ответами проверить предупреждение, отмену и подтверждение удаления поля вместе с ответами. В общем режиме проверить, что до общего сохранения поле и ответы остаются, удаление можно отменить, а итоговое подтверждение предупреждает об ответах. Новое поле, находящееся только в черновике, убирается из набора без предупреждения об имеющихся ответах. У встроенного поля команда удаления отсутствует.

6\. Открыть предпросмотр трёх контекстов для обоих типов анкет. Для просмотра анкеты и фильтра «Обзора» проверить обычную и премиум-аудиторию; в форме редактирования проверить настройки владельца. Изменить настройку, проверить результат и вернуться в таблицу.

7\. На копии действующих данных проверить перенос и откат: до и после сравнить фактическую видимость для обычных и Premium-пользователей, доступность формы и обязательность для обоих типов, идентификаторы, варианты и ответы. Проверить случай «общая видимость выключена, Premium включён»: ранее скрытое от всех поле остаётся скрытым. Проверить сохранение клиентской доступности профессионального поля, если оно было доступно, и исходное назначение только эксперту, если клиентам оно не было доступно. Отдельно проверить согласованное ограничение поиска по значениям только для Premium. Проверить права администратором и пользователем без доступа, ошибку сохранения и повторную загрузку.

8\. Проверить одновременную работу двух администраторов: устаревшее изменение не перезаписывает новое; в общем режиме весь устаревший набор отклоняется. Отдельно открыть список первому администратору, сохранить изменение вторым и только затем открыть первому редактирование: он должен увидеть актуальные настройки второго. Проверить потерянный ответ и сбой применения настроек к поиску без повторной записи.

9\. Проверить первое назначение и повторное включение дополнительного поля, выключение и повторное включение поля в форме с сохранением обязательности, а также восстановление общего черновика после обновления страницы. В общем режиме открыть предпросмотр с изменением из черновика, обновить его и убедиться, что изменение остаётся видно.

10\. В общей выдаче проверить критерий, доступный только одному типу анкет, скрытое поле и Premium. В устаревшей форме анкеты проверить, что ответы не перезаписываются частично. Проверить действующую регистрацию и редактирование: выключение поля в редакторе не меняет регистрацию и не требует скрытое поле при сохранении этой формы; системная функция продолжает использовать сохранённое значение. Если поле необходимо действующей функции и другого доступного способа его заполнить нет, отключение отклоняется с понятным объяснением, а общий набор изменений не применяется частично. При режиме «клиент — эксперт» существующая настройка показа только экспертов включена и заблокирована; при режиме «все видят всех» выключена и заблокирована. Проверить все разделы, где эта настройка уже применялась.

## 8\. Визуальные ограничения и граница готовности

Взять действующие компоненты и CSS сайта. Шапку, логотип, боковое меню, глобальные стили и соседние разделы не менять. Новые правила помещать в отдельный файл и ограничивать контейнером функционала, не затирая существующие CSS. Макет показывает ожидаемую страницу; снимок действующей страницы — исходное состояние. После разработки нужны ссылка на реализацию, результаты проверки и указание, что осталось непроверенным.
